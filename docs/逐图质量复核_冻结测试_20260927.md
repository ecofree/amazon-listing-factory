## 三、问题具体发生在哪个环节

### P01：白床 scene 改机位、缩短护栏、扩大入口

**已确认的证据：**

1. 实际附件 1 是 `inputs/B0DSRTM3HX/scene_0.jpg`，附件 2 是另一机位的主图证据。
2. 提示词明确写了保留 `viewpoint`，并写明第一张决定机位、辅助图不允许合并机位。
3. 同一提示词又要求强调 `independent accessibility`、`open entry`。附件 1 主要展示完整长护栏，入口在远侧，不适合靠当前视角突出入口。
4. 输出变成与辅助主图近似的观察方向，并把近侧短护栏进一步缩短。对照辅助主图也不是准确照搬产品。

**结论：这是实际生图执行违约，同时存在“本图目标与编辑底图可见关系不协调”的输入问题。** 不能归结成程序没发保真提示，也不能把“有辅助图”直接当成唯一原因。辅助视角干扰、强调入口造成结构优化冲动都是有证据支持的候选原因，但本轮没有单变量对照，尚不能分开定因。

**处理落点：** 在既有视觉规划／图源绑定中，让图的表达目标服从选定底图可见关系；生图输入中，辅助图只承担确有必要的事实补充。不能让“更突出入口”变成新造入口。不要对所有类目、所有功能图盲目删除辅助附件。

**最小验证：** 针对此失败样本保留当前基准，只做两个各自单变量的对照：一组仅移除跨机位辅助图；另一组保留附件但仅把目标改为当前机位能表现的场景目标。来源、模型及其余文字固定。若只一张偶然成功，仍不能声称唯一根因已经确定。

### P02：原木床 main 增加连接条及螺钉

这张实际只有一张输入参考，提示词已经要求保持 `joins`、`part count` 和结构。输出依然在护栏底部补画出新的连接形式。

**因此，多参考图不是全部主体重绘的根因；“只留一张原图”也不是充分解决方案。** 本例是模型对局部机械连接的重新解释，通用保真合同未稳定落到具体连接处。不是源图确有的硬件，也不能以整体床形相似判为通过。

**处理落点：** 使用现有生图合同／已有局部修复能力，针对原图可见的该连接关系进行约束与对照，不再堆一整段全类目“不能改变”。若此处反复失败，再决定是否值得使用既有局部修复；不能未经实测就宣称一句提示词必然锁住连接。

### P03：黑柜厨房目标被浴室共享风格覆盖

实际 `tasks/B0BYCY68SG/scene.prompt.txt` 同时包含：

- 本图目标：`alternative kitchen or dining space`。
- 共享环境：`bathroom and living interiors`、`grooming accessories`。
- 可替换道具也以 toiletries 等浴室用品为主；目标 state 写 tiled wall，而后面的具体墙面组件又写 painted drywall。

`core/image_prompt_compiler.py` 的 `compile_task_prompt` 输出本图目标，`_family_art_direction` 又输出完整共享环境，两者都被保留。这里共享风格包含了“空间类型与用途”，已经不只是色彩、光照和材质。

**这是可确认的指令冲突，属于规划数据到提示词投影之间的职责重叠。** 不应简单判成模型随机。模型最后选浴室只是冲突的表现。

**最小处理：** 在现有规划字段和编译函数中明确：本图目标决定空间用途，共享方向只负责一致的设计语言，不重复决定房间类型；删除冲突投影，不新增一轮审查或第二套场景规划器。由于本次用了旧规划，还需要用现有流程验证新的 Gemini 规划是否仍产生这种冲突，不能据此认定新版规划已失败或已修好。

棕色柜的目标明确要求浴室，因此相同的输出场景在它身上不是错误。质量判断必须对应当前任务目标，不能只比“是否像源图”。

### P04：仿真树主体大形正确，表面细节仍不能宣称不变

四张都维持销售件数、每棵三个球冠和黑盆；没有出现此前讨论的地钉支脚错误。这次实际产品是盆栽三球冠树，不能据此推断“带地钉仿真树”的关系已经修复。

叶片轮廓／密度观感和树皮纹理有重新描绘。不同分辨率、缩放、光照也会影响观感，**本次不把每片叶子的像素差异直接判成商品错误，也不把这些差异统统归为正常**。植物类目的产品本身就是枝叶与表面，不能像床品那样任意重新设计。

**最小处理：** 保留现有主体保真原则，按同尺度局部对比判定叶形类型、球冠相对比例、分枝连接与饰面有无实质变化；不要求追踪每一片叶子的坐标，也不为此引入新分割服务。本轮结论到“大形可用、细节待定”为止。

## 四、修改后确实有价值的部分

1. **产品与非销售物品的边界更清楚。** 床品、房间、柜内用品可以变化，大多数柜体样本并未随环境一起整体重构。
2. **柜体主要关系比较稳定。** 两个高柜的四张图均保留上部右滑门、下部左开右闭、开放格和低脚；没有看到旧例中的大幅门覆盖改动。
3. **销售数量保持。** 单树与双树没有互串；环境中的其它植物没有被错误计入销售件数。
4. **没有新增广告文案或尺寸标注。** 但只测摄影类图片，不能外推到 func／size 的文案压缩、引线归属或尺寸端点已经通过。

这些是样本中观察到的改善，**本轮没有同输入、同模型的旧版／新版成对实验，不能给出可信的改善百分比，也不能将全部差异只归因于提示词修改。**

## 五、还有哪些设计和验证问题

### 1. 成套表达仍可能重复，摆件替换程度不一致

白床 main 与 scene 最后变成相近的视角和房间表达，原先两种观察方向的价值丢失；应先解决 P01，再评估成套重复。两张柜体 main 大量沿用源道具，这不自动构成主体错误，但旧报告“摆件均更新”的表述过度。白底 main 的核心任务本就不一定是换全部摆件，不宜机械要求重新设计。

### 2. 这次是旧任务重编译后的摄影图抽测，不是完整生产冻结验证

`compile_freeze.py` 深拷贝 20260922 现成 ImageTask，只更新当前类目规则、编辑合同、版本与指纹，再编译。旧 `image_direction` 和 `family_art_direction` 被继续使用。新事实判断、分类、Gemini 成套规划及规划审查没有重新执行。

`generate_freeze.py` 直接调用 `generate_with_provider_retries` 并复制返回文件，未经过完整生产执行器。真实调用只选 `main` / `scene` 共 16 张。70 个任务编译成功不等于 70 张图片通过，更不等于正式调度、局部修复、func／size 全链已经验证。

3 个 blocked 行由旧任务状态直接带入；不能称为当前实现重新识别并正确拦截了 3 个问题。四类样本中壁挂柜是实心门柜，并不是之前有问题的镜柜，镜面保真也未覆盖。

本轮保存的任务／提示词／附件／输出哈希可证明本地材料一致；目录没有据此自动获得代码快照、服务端忠实执行或像素保真的证明。此次复核不继续付费生图。

本次实际复核了 303 项本地材料哈希或请求映射检查，全部相符。提示词按实际发送脚本的 `read_text().encode()` 口径核对，Windows 文件换行差异不误报为提示词被改动。

### 3. 旧人工报告漏判，脚本将所有输出统一写成“通过”

`finalize_freeze.py` 对每一张生成图固定写入“主要结构通过（人工研发复核）”，其断言只检查文件与哈希。它不是一个视觉判断器，也没有本次逐图反例的分级记录。旧记录把白床错误视角／缺栏归为遮挡，把原木床局部连接变化漏掉，把厨房变浴室当成普通更新，并把 Brown 写成 Black。

这是上次复核与报告的不足，本次明确修正。生成成功、文件哈希通过与画质通过必须分别陈述，无需为此增加生产流程。

### 4. 初次试跑和重发的统计边界

最终 16 张均有 finalized 回执；初次试跑额外保存 1 张白床主图。按回执文件 ID 去重，整个目录有 19 个不同请求回执：17 个成功输出、1 个初次结果未知请求、1 个替代请求的已知失败。存在同一未知回执在两处保存而状态不同的副本。

替代请求 HTTP 400 不能证明原请求的远端结果或计费已查明。原请求被本地 superseded 是重发处置，不是远端确认。此问题属于测试记录的准确性，不能混进最终 16 张的画质成功率。

## 六、建议的最小处理顺序

1. 先修正本次结果口径，以本报告和逐图复核页替代旧的“全部通过”。
2. 优先消除 P03 已确认的“本图用途与共享环境”冲突，修改现有规划／编译投影，不新增步骤。
3. P01 用明确单变量对照区分底图目标不协调与辅助机位干扰，避免一次修改多个因素；P02 单独验证局部连接保真，不能用 P01 的单参考图方案包治全部重绘。
4. 摄影抽测稳定后，若要声称完整冻结验证，仍须在现有正常入口运行规划到生成，并覆盖 func／size 与旧问题的实际产品。复用现有流程与用户设定模型路由，不增加审查轮次或外部分割依赖。
