1. 具体接入位置

  1. 现有 Gemini 子体规划返回 region_intent：实际编辑底图上的目标实例、可见构件、局部范围与正负点，或可核查的不适用原因。未见过的底图不得编造坐标。
  2. 现有 brief 内调用本地 SAM worker 建立候选。整批 brief 共用一次权重加载，使用原 host_gpu_auto 槽；没有安装新的主 Python 环境，没有增加外部服务。
  3. 原 planning review 同时查看实际底图、候选接触表、当前保护区和局部差异；严格解析器保存实例/构件选择与 signed repairs。
  4. 局部合并采用 (原区域 ∪ 产品补选) − 明确非产品。拒绝删除已确认构件、误入另一实例或丢掉本来已覆盖的锚点。原来就漏选的部分不能冒充本次删除回归，仍由下一次原审查判断。
  5. 改变蒙版就改变审查内容 key，旧 supported 不审批新蒙版。通过后，将唯一不可变 artifact 投影到第一 edit_base 的 protected_mask，再形成原 ImageTask 指纹。
  6. 原 executor/transport 接收同尺寸 RGBA：alpha255 请求保留、alpha0 请求编辑。重试、切换模型、保存响应恢复不调用 SAM；生成开始前退出 worker。

未增加生产阶段、逐图手工审批、第二套事实/规划/QA/候选控制器。size/func 仍为源图编辑合同；本轮尚未完成其实际成图角色验收。targeted_edit 的新候选底图不能复用原图坐标蒙版，自动候选蒙版按原批准方案后置。

4. 回归过程中修正的接入问题

  • 第一版审查主 JSON 示例遗漏区域元数据，模型只返回原 findings：删除旧示例，改成当前完整格式，没有增加审查调用上限。
  • 裁剪外负点本来已被空间支持排除，错误拒绝导致无意义修复：保留原坐标事实，交互只传裁剪内负点，没有把点移到其他位置。
  • 局部更新把初始漏选误算成新增损害：只用原区域已覆盖的锚点检查回归，同时保留已确认构件面区域的删除保护，不要求一次局部修正证明整图完美。
  • 多子体分别加载会占用同一 GPU 并耗尽原 deadline：改为原 brief 批次共用一个 worker，RPC 在原资源槽内串行，Gemini 原规划仍可并发。
  • 重复角色的相同区域修正复用同一不可变结果；修正最多一轮，不循环堆负点、不整块替换旧构件、不全图填孔或膨胀。

较早的失败回归完整保留在 fixed11 与 fixed11_v2；最终 fixed11_v3 用时 129.59 秒，未提高原 180 秒 child deadline。最终 worker 物理前向与原审查请求计数见下方，不把候选数量当调用数。
