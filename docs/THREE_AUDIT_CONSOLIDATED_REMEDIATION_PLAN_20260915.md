# 三轮审计合并整改方案（2026-09-15）

## 1. 方案定位

本文件是整改设计，不是已实施报告。本轮仅核对报告与当前源码并新增本方案，没有修改生产代码、配置或测试，没有启动视觉规划、生图、QA 或冻结测试。

合并三组证据，并以当前可达代码为准：

1. [整改只读复核](/D:/Amazon_pics/amazon_listing_factory/docs/PRECISE_REMEDIATION_RECHECK_20260915.md)，结合[后续实施与二次核查](/D:/Amazon_pics/amazon_listing_factory/docs/PRECISE_REMEDIATION_CLOSURE_20260915.md)，区分已修复点与新暴露问题。
2. [冻结测试截断与合同根因审计](/D:/Amazon_pics/amazon_listing_factory/docs/FREEZE_CONTRACT_ROOT_CAUSE_AUDIT_20260915.md)。
3. [视觉规划与设计过度约束审计](/D:/Amazon_pics/amazon_listing_factory/docs/VISUAL_DESIGN_OVERCONSTRAINT_AUDIT_20260915.md)。下文 V01-V20、Q01-Q03 对应该报告编号。

目标不是让所有模型输出都通过，而是：**正确商品证据可以被自由设计成高质量图片；无关道具、旧构图、旧拍摄状态不再阻塞；真实产品错误仍然能被识别；暂时失败可以有界恢复，成功结果不重复付费。**

P0-P4 是开发整改顺序，不是新增生产 stage。现有 observation、事实/角色合同、child 规划、prompt、generation、QA、模板链路保持一套。

## 2. 先校正三轮报告之间的结论

| 项目 | 当前判断 | 本次处理 |
|---|---|---|
| 无标题却带 title 位置导致 review 指纹不同 | 同一投影已进入 review 与编译 | 保留，不恢复审查后变更语义或旧键兼容 |
| HTTP 200 明确 error 被误当可恢复图片 | 已有统一拒绝分类 | 保留；不得为提速删除响应收据和防重复付费保护 |
| component_style 冲突完全不能修 | 已允许定位到该 shared_prose 字段 | 保留；继续解决其它确有责任的组件字段无法修的问题 |
| 没有任何观察反馈入口 | 已有 brief 内一次有界反馈 | 不再新增反馈机制；缩小触发到真正的商品证据错误 |
| 测量标签导致裁框扩张未解释 | 当前已有 provenance 和必要标注上下文 | 保留；继续区分商品被裁与无关道具被裁 |
| 纠正失败后普通恢复不再处理 | 代码确有此行为，过去作为防重放目标实现 | 修正 consumed 与 resolved 混用，不推翻有限预算 |
| 道具库存、原拍摄状态、词表误杀 | 当前仍可达，部分有真实失败和离线反例 | 必须成组替换，而非追加放行语句 |
| MAX_TOKENS 等被统称合同错误 | 当前调用规模与结果归因仍不合理 | 修正客户端分类、规模和记录 |

这不是回滚到旧版本，也不是把三轮报告所有建议叠加。此前“漏一件源道具就必须观察纠正”的目标本身需要撤销，即使该反馈代码曾通过测试。

## 3. 不可改变的落地原则

- 不新增 stage、controller、QA 流程、候选流程、第二套 prompt 或 feature flag。
- 程序管理商品事实、引用、依赖、预算与状态；Gemini 决定目标场景、配色、视觉叙事；图像模型完成参考编辑和设计表现。
- func/size 继续是参考图编辑，不变成无证据新造产品，也不引入本地 Pillow 排版或抠图/擦除阶段。
- 保留现有主图政策：床架 lifestyle；浴室柜、药品柜、仿真树按现有白底策略。白底不等于一律禁止合理的内部使用道具。
- 同一 child 使用一个目标设计体系；不同 child 即使商品同色也可不同。不恢复固定色板路线或 family 级锁色。
- 保留英制换算、尺寸测量对象和端点、功能事实与限定词、商品变体及出售数量。
- 保留无品牌普通书本/道具文字的允许边界；继续尽量无人，包括镜面倒影。不得把审美升级为自动硬 QA。
- 不变更 safeplus、China、quantity=200、库存可售、履约、GTIN 等既定模板及商业默认值。
- 不调整本轮范围外的 provider 启停、模型分工、生成分辨率、放大策略或并发控制器。
- 不迁移、清理或重新消费历史 jobs。本次变更过的语义只适用于新版本产物，旧产物不能静默转成新合同输入。

不能承诺外部模型永不失败。“不造成新阻塞”在本方案中指：不增加非商品门槛，不扩大一个失败的影响范围，不让失败恢复永久失效，不把等待伪装成通过。

## 4. 唯一语义模型

### 4.1 商品证据与目标设计分离，但不建立第二套事实系统

继续使用现有观察产物和 FinalSourceIntent 作为商品证据。它回答：卖什么、哪些部件和状态有证据、哪些尺寸属于哪个部位、哪里存在真实不确定性。

现有 child visual plan 回答：把这件商品放在什么场景、使用什么床品和道具、怎么配色、怎么布局、每张图证明什么。

**源图记录的是“原来拍到了什么”，目标规划决定“这次要展示什么”。两者不必有相同道具、位置、背景、色彩或拍摄状态。**

| 对象/属性 | 不变量 | 可以设计的内容 |
|---|---|---|
| 出售商品 | 身份、结构、真实材质/颜色、零件及出售数量 | 画面位置、占比、光线；有证据支持的视角与使用状态 |
| 不随商品出售的床垫、床品、枕头 | 不误导商品尺寸或包含范围，不遮掉当前必要证明 | 有无、数量、款式、颜色、材质、摆放 |
| 房间、墙、地板、家具、装饰 | 合理使用场景，不冒充商品组成 | 全部重新设计，无须源道具逐一配对 |
| func 图 | 真实功能、具体机构、数量和限定条件 | 叙事、版式、是否使用小窗、字体、图标、底衬 |
| size 图 | 数值、单位、测量对象与物理端点对应 | 文字位置、尺寸线排布、背景、图形样式 |

移除床品后露出的结构若有同 child 证据，可以采用对应证据；没有证据就不能虚构。是否允许不是由“这张源图有没有床品”决定。生活图可以铺床，排骨架证明图不能把要证明的排骨架全部盖住。

### 4.2 把 scene_objects 改为目标组件选择，不再绑定旧道具库存

在现有 image_direction 内替换 scene_objects 的结构和语义，删除旧 `source_id/object_id -> palette/null` 以及 `new:group.component` 分支，不保留双格式读取。

建议的单一表达：

```json
{
  "scene_objects": [
    "room.wall",
    "room.floor",
    "bedding.duvet_cover",
    "bedding.primary_pillowcase",
    "decor.reading_books"
  ]
}
```

这些 ID 只引用同 child 现有 palette_direction 中由 Gemini 定义的目标组件。该字段负责本角色选择哪些组件；palette_direction 负责每个组件的颜色、材料和图案；creative_brief 负责布置和构图，不再重写色值。

这不是增加一套道具实体控制器：不要求为每个旧枕头、书本、瓶子生成身份，也不重复维护第二份组件颜色。未选组件不要求出现在该图。商品及包含配件不能通过该字段删除或改色。

### 4.3 以必要事实覆盖替代旧视图覆盖

在既有 evidence_usage 和 role contract 中改语义：目标图片需要覆盖的是必要商品特征和尺寸关系，不是每个源 panel/inset 的存在。

- source/view ID 继续用于附件定位和来源追踪，但不能单凭 ID 不同判定物理特征不同。
- 同 child 联合观察负责真实部件身份；不另建同义词/别名 controller。
- display 是目标里实际采用的商品视图；verification 可以只证明结构，不再强制在目标图里复制其相机取景。
- 本图必须证明的独有卖点、测量对象和端点仍须有清晰展示，不得用“自由设计”悄悄删掉。
- 保持用户要求的全部输出槽位。源图数量和任务数量不因删掉旧视图义务而被缩减成四张代表图。

## 5. P0：纠正观察、参考与事实边界

### 修改内容

1. 观察只详述出售商品、包含配件、相关部件、真实功能/测量证据；普通场景道具无需穷举或引用商品规格证明归属。
2. 仅在某个对象可能是出售组件、或会影响必要商品证据时记录其歧义。unknown 不意味着放行真实产品，也不能因为一只无关花瓶不明确就封锁整图。
3. 删除“任意 occludes 就不可移除”的判断；检查被遮挡目标是否为商品、其它视图是否提供所需证据。
4. 删除 `_PRODUCT_PART_STATE_MUTATION_RE` 的事实决定用途、仿真树名词屏蔽分支、把共享 prose 中所有英制数字都当产品尺寸的规则。英文否定句、装饰镜和商品柜门由真实对象范围判断，不再扩充类目豁免词表。
5. 取消“源图全部道具完整”与商品观察完成的绑定。可用的商品证据保留；具体事实未解决时，只保留其真实未决状态及影响任务。
6. 沿用现有裁图函数和 provenance，保留商品、必要标签和端点。移除源道具不通过破坏事实裁图实现；保留的旧图形只做证据，不拥有风格权威。
7. 在现有角色选择中解除 source_00 是唯一 main 证据的要求。可以正常选择同 child 的其它可靠完整商品视图，但不得把未验证 source 或错误变体伪装成可用输入。缺少必要产品证据仍明确未决，不新增单图规划兜底。
8. 取消全 bed_frame 类目被标成儿童/Montessori 的事实。用户明确指定儿童床仍按儿童场景设计；否则结合具体 child 事实由 Gemini 判断适用场景。

### 修改位置与删除项

[visual_semantics.py](/D:/Amazon_pics/amazon_listing_factory/core/visual_semantics.py)、[final_source_intents.py](/D:/Amazon_pics/amazon_listing_factory/core/final_source_intents.py)、[image_reference_context.py](/D:/Amazon_pics/amazon_listing_factory/core/image_reference_context.py)、[visual_design_kit_compiler.py](/D:/Amazon_pics/amazon_listing_factory/core/visual_design_kit_compiler.py)、[visual_context.py](/D:/Amazon_pics/amazon_listing_factory/core/visual_context.py)及相关类目配置。

同步物理删除旧库存 mandatory 校验、旧词表和例外、来源视角绝对保护语义；不得在外面新增一层“允许变更”去绕开原判断。

### 完成条件

源马桶/花瓶/裁图外椅子可以直接不被采用；道具遮道具不触发产品保护；商品门、轮子、排骨架、接头和真实数量错误仍能定位。该条件属于整改测试，不是给生产增加审核阶段。

## 6. P1：一次性统一规划、复核和最终 prompt

### 6.1 Gemini 真正负责目标设计

现有一次 child 规划需形成完整目标设计：适用受众、空间关系、光照与材质表现、床品/道具组合、颜色主次面积、每角色的买家问题和信息层级。不增加双候选或第二次审美规划。

设计质量方向放在已有字段内替换旧内容：

- 场景：可信的美国家居尺度、动线和使用关系；明亮但不洗白商品；有自然材质层次，不用深灰背景掩盖材质。
- 配色：Gemini 按具体商品设计多种可能性后在当前 child 决定一套执行组合；不由程序规定白床只能蓝灰、原木只能陶土。目标组件在全角色统一，光照变化允许，主色身份不能漂移。
- func：具体机构和使用收益驱动设计，文字服务产品，不默认“大标题加固定圆形小窗”；可以采用不同视觉叙事，不用程序随机套版。
- 图形：保留用户要求的文字/徽标/引导线协调；local 底衬仅在实际布局有需要时选择，不把所有文字包装成胶囊。
- 同 child 有共通设计语言，但不是所有角色使用同一构图。统一来自组件、字体、图形和光照逻辑，不来自复制源图。

数值配色工具仍在现有调用中提供亮度、色差、对比度参考，不自动选色或评分拒绝。不能把“工具已调用”当成审美合格证。

### 6.2 参考输入与复核任务收敛

- 原图/裁图负责商品结构证据，获批设计参考负责其授权范围内的视觉风格；不互相越权。
- 不新增生成产品抠图、局部擦除、第二参考清洗阶段。必要裁图含旧装饰时，目标设计明确替代它们，不要求复制。
- 没有合适的获批设计参考就走当前自主规划能力，记录 autonomous；不是恢复固定模板或偷偷读取 draft 素材。本轮参考数为 0，后续不得称其为获批素材方案对照。
- 复核只附带所需的商品原图/裁图和声明，重复附件按来源绑定去重；原图与裁图不因为内容相似就误删，测量坐标必须仍可定位。
- 删除每 source 必须存在的 staging_inventory operation；不再为每个无争议视图重复设置一个必须远端 supported 的门槛。
- 观察对源商品证据负责；现有复核对实际采用的证据覆盖、产品声明和明确目标冲突负责。无待验证操作时保存明确无须模型复核的记录，不伪造 supported，也不为取得“成功”额外请求。
- 对同一目标组件的两个明确相反赋值进行局部修正；不因源床品蓝色、目标鼠尾草绿而判矛盾。不从泛称 bathroom fixture 推断“必须是源图那只马桶”。

### 6.3 修复器能改真正错误的责任字段

保留已经完成的 text_placement 投影一致性和指纹保护。修改现有一次局部 repair：

- 修复输入是精确错误字段及其必要依赖，不是整份旧设计加一段新禁止词。
- 对实际错误的 palette 组件定义、graphic 描述、environment prose 等允许修正，不再只允许 palette_additions 而禁止改错值。
- 未关联色值、字体、商品事实和其它 child 不允许顺带改变；审美“不够喜欢”不自动触发该修复。
- 在现有 family_art_direction 原位替换错误值，不产生新旧两份权威。当前 schema 删除 additions-only 专用分支，使用同一受影响字段修复方式。
- 修复完成后统一编译；受影响的 review/prompt 按实际依赖重新绑定。只改某图布局不能使其它 child 重画；确实改了全 child 色彩则不能假装旧成品仍匹配新设计。

### 6.4 最终 prompt 的单一职责结构

| 区段 | 唯一内容 | 不再携带 |
|---|---|---|
| 任务与类目政策 | role、输出任务、现有 main policy | 重复市场宣言、历史修复说明 |
| 商品事实与附件绑定 | 商品身份、必要结构、事实引用 | 源花瓶/床品/椅子必须保留的状态和关系 |
| 本图目标设计 | 构图、使用场景、选定目标组件 | 再定义共享色值、强制复制源视角 |
| 使用到的 child 样式 | 对象色彩/材质、字体、图形语义 | 全 child 未使用组件、第二套背景规则 |
| 本图事实文案与测量 | 允许的显示文字、数值、测量对象/端点 | 已在其它区段重复的 captions 和尺寸 |

这是编译器输出顺序，不是新增五个流程节点。不设“超过 N 字符禁止生产”的新门槛。长度用来定位内容重复，验收看语义是否完整、唯一、可执行。

program-owned product boundary 不再无视目标 brief 注入源照片保留规则。技术画布不自动继承源房间；保留物理安装关系与保留墙面颜色分开。已删除源道具的 contained_in/occludes 不再作为目标指令发给图像模型。

产品性能、数量、限定条件仍需事实支撑；导航型标题不强迫伪装成一个产品性能声明。最终可渲染文字只有现有 display_copy/measurement 两个明确职责，不恢复创作 prose 中夹带文案。

### 完成条件

逐份展示修改前后实际编译 prompt，标出删掉、保留、迁移到唯一权威的语义。不能仅报字符下降。旧的 source-visible bedding、固定 perspective、全 staging inventory 等语义在 observation、planner、review、compiler、QA 中同时退出。

## 7. P2：恢复、截断和耗时修正

### 7.1 失败处理表

以下分类使用现有请求、状态及恢复入口，不新建调度状态机。

| 情况 | 当轮处理 | 再次恢复 |
|---|---|---|
| 源观察或必要复核有效成功 | 持久化并按输入指纹复用 | 不重复请求 |
| MAX_TOKENS | 记录 output_limit，不进入商品矛盾分类；剩余既有预算内纠正输出容量/无关内容 | 有限重试，不原样重发同一个超容量请求 |
| 规划超时、临时不可用、暂时无法判定 | 仅相关任务未决，保留具体原因和尝试记录 | 在已有有限预算内重试；预算耗尽明确可恢复/需新授权，不伪造成功 |
| 已证实源商品事实错误 | 仅对应 source/事实进入现有观察纠正 | 不对其它 child 或无关源图全量重观察 |
| 目标设计字段自相矛盾 | 留在既有局部 repair | 不回 classify |
| 源图无关道具漏记或被裁掉 | 不构成商品错误 | 不发起观察纠正，不消费恢复预算 |
| 生图明确尚未生成的拒绝 | 沿用现有 provider 分类及可用路由 | 不把错误包当图片解码 |
| 已收到图片/下载指针，本地处理失败 | 恢复下载、解码或落盘 | 不再次付费生图 |
| 生图已提交、结果未知 | 保留收据和未知状态，按现有恢复能力查询/恢复 | 不盲目再提交，不声称肯定没生成 |

不能用一个通用 inconclusive 永久冻结一切，也不能把所有 inconclusive 变成自动通过。真实商品不确定性与请求没完成必须分开。

### 7.2 修复 consumed/resolved 混用

在现有观察缓存与 attempt 记录内，已消耗请求不等于成功证据：

- 删除 `status == success OR applied` 作为 retained 的条件；只复用已验证成功的事实行。
- 保留消费记录及原始失败，记录现有预算使用量，不能因新 trace UUID 或改文案而重置预算。
- 同次运行/自动续跑不因反复看到 failed 而无限重放；用户显式 resume 由现有恢复语义决定一次有界的新尝试，不要求先改源图、删缓存或伪造人工 reobserve。
- 已明确 unsupported 的产品声明需要修规划，不因重试重新赌 supported；暂时 review 不可用不作为永久负面事实缓存。
- 不增加新的日常审批节点；付费测试批准是当前协作要求，生产继续沿用已有预算政策。

### 7.3 输出容量与观测记录

在现有 vision client 和观察/复核调用内：

1. 先读取 finish reason，再将错误归为输出耗尽、传输失败、结构格式错误、已完成但真实语义冲突。
2. 根据当前 source/view/必要事实规模设置有界 output budget，不再所有复杂观察都隐式落到 8192；上限以已验证 provider 能力和现有预算为界，不凭猜测设置极大值。
3. MAX_TOKENS 后若尚有既有尝试预算，不原样重试；不补括号、不拼接不完整 JSON、不伪造默认字段，也不新增单图规划降级路径。
4. 已保留 source 的上下文只传后续必要的商品身份/证据，删除整份道具列表和重复 prose；保持一次 child 联合规划，不拆成彼此独立的角色设计。
5. 每个 attempt 唯一保存请求与响应索引，保留 finish reason、实际预算、可用 usage、解析位置和缺失范围。usage 不可用就记录 unavailable，不把推测写成“思考 token 耗尽”。
6. 不覆盖旧 attempts 索引导致历次失败只剩最后一轮；不把一个超时展开成几十个伪事实错误。

不规定 9 张图一定要多少 token，也不以更长 timeout 代替删掉无关职责。无法在真实能力上限内完成时明确报容量问题，不创造无证据兜底。

源 title/bullets/specs 多处重复出现的同一事实，在现有事实目录中共用完整文本，原 evidence ID 和来源仍保留。不同测量对象、数量、静态/动态条件、否定与性能限定词不能因为文字相似而合并。原始响应继续留存为证据，但不反复全文塞回模型请求。

### 7.4 状态、吞吐与 scope

- kit 已保存、部分 ready、全部 ready、等待复核分别统计。`ready_children` 不能按“存在 kit”统计。
- 记录 classify、规划、必要复核、repair、排队、生成、本地处理、QA、模板的用时及物理请求数；排队时间不能归成 provider 生成耗时。
- 保留当前硬件/provider 感知并发，减少不必要模型请求和附件重复，不新增跨任务队列。单个角色未决不阻止已有可执行任务在现有队列中工作。
- 冻结 scope 使用明确 child ID 和完整 source 清单，不再以 `--limit 2` 暗示选中了预期两个变体。需要显式选择参数时，只扩展既有 ensure_run_scope/请求入口，属于数据选择参数，不是行为 feature flag；不手工改冻结 scope 绕过校验。

## 8. P3：现有 QA、测试和旧行为清理

### 8.1 QA 只保护真实商品及发布要求

沿用现有 gates，修改比较对象：

- 必要部件、结构、变体、数量、功能声明和尺寸关系必须正确。
- 不再按原 crop 范围或原床品有无判断商品是否被改；结合当前 child 的实际商品证据比较。
- 一个正确 inset 不能掩盖主体结构错误；技术图的重复特写也不能误算多卖一个商品。
- 新房间、新花瓶、新床品、删除源摆件不是商品 defect。普通无品牌道具文字不自动判品牌。
- 模型不可用不冒充 QA pass；仅记录真实未决范围。不新增审美评分、色差阈值、房间风格白名单。

目标配色、字体/徽标协调、光照和美感仍需实图检查，不能拿数值工具或 QA pass 替代。

### 8.2 替换测试，不扩张错误合同

保留当前 100 case / 60 秒预算；在现有测试内合并或替换，不用巨大 fixture 把新增校验藏在一个 case 里。单元测试 mock 只证明数据行为，不再以 `Fixture pixels checked` 暗示真实看过图片。

| 必须允许的正例 | 必须识别的反例 |
|---|---|
| 删除装饰花、换新镜子、去掉裁图外椅子 | 删除出售商品的门、镜面组件或抽屉 |
| 保护产品的否定句正确理解 | 明确要求伪造产品结构 |
| 源裸床变真实使用场景，改变非出售枕头数量 | 杜撰床板、接头，遮掉当前 func 必要证明 |
| 采用同 child 另一可靠视图/功能状态 | 使用错误变体或没有证据的内部结构 |
| 合并冗余小窗但保留独有事实 | 丢失必要机构、数量、承重限定词 |
| 装饰画尺寸描述、合法英制换算 | 商品测量对象错位、端点不符、单位错换 |
| 源色与目标色不同 | 同一目标组件在多个字段自相矛盾 |
| 临时失败有界恢复，成功结果复用 | 永久 retained 失败，或重复付费生成 |
| 审查和最终编译同一份规划 | 指纹失效仍使用旧审查 |
| 无关道具遗漏不回 classify | 真正商品证据错误被悄悄跳过 |

定向运行相关模块；生产套件仅在代码整改末尾运行一次。不运行历史全量 discovery，不添加 SP-API 测试。

### 8.3 物理删除清单

必须连同调用、prompt 文字、schema handler、cache reader 和相关测试一起清理：

1. 产品名词 regex 判定及仿真树例外。
2. 旧源道具身份到 palette/null 的 scene_objects 格式，以及 new:别名分支。
3. 每图强制 staging_inventory 和整 source 道具完整性门槛。
4. 全角色源 perspective/state/extent/occlusion 一刀切保护。
5. bare views remain bare、不能增加非出售床品等旧规则。
6. graphic_canvas 隐式 retain source context。
7. 仅凭旧 feature ID 相同/不同决定事实覆盖的路径。
8. additions-only 修复权限及阻止修正已知错误设计值的旧分支。
9. 失败纠正被 retained、复核只因 key 存在就不再处理的判断。
10. 全类目儿童房硬编码事实、截断半句话的上下文拼接。
11. succeeded/ready 字段将持久化误称可生产的统计。

旧版本产物保留只读，不编写兼容迁移让旧合同继续参与新生产。更新受影响 schema/policy/fingerprint；不得借此使无关模块、其它 child 或未改变职责全部失效。

## 9. P4：经批准后冻结完整实测

本方案不授权立即付费测试。P0-P3 完成后先提交本地检查结果，得到用户批准才执行。

### 测试设计

- 使用床架和浴室柜两个现有 ASIN family，各 1-2 个明确 child。床架优先白色 B0FHD4MS3K 与原木 B0FFMWB9XV；浴室柜具体 child 以已有证据、用户批准和冻结 scope 为准，不能把实际 B0CCJ56SMH 说成另一个 ASIN。
- 生成选中 child 的全部角色/全部图片，直至模板。事前列出每个 child 源图数、角色清单、预计首次生成请求数和允许重试上限。
- 记录工作区源码和配置指纹、child/source SHA、模型及输入附件，不能只记录 HEAD，因为当前有大量未提交修改。
- 这是明确选定变体范围的真实 canary，不等于已经验证完整 family 批量生产。沿用现有测试 scope，不为两变体测试放松正式 production 模式的 full-family 完整性要求。
- 本次失败基线没有完整生成图，不能把它当成完整图像 A/B 对照。保留其阻塞日志作为流程基线；只在用户授权范围内读取同 child 可比旧成品作视觉参考，不重跑已知阻塞旧代码来消耗预算。
- 若确需严格前后两组实图，须单独说明原基线是否可运行及两组成本，再获得批准；不能暗中翻倍生图。
- 先完成一个 child 的整套，人工检查结构、设计自由和颜色一致性，再继续剩余批准样本。人工检查属于本次测试安排，不加入日常生产 stage。
- 检查无系统性回归后，剩余已批准样本沿用当前硬件/provider 感知并发，不要求逐 child 新增批准，也不把测试首套顺序执行推广为生产串行规则。

### 图像与流程验收

1. main/scene/func/size 的商品主体一致；主体与局部图不出现两套床架结构。
2. 同 child 床品、目标墙面/地板及图形系统协调；白底 main 与生活图背景不同属于正确策略，不算漂移。
3. Gemini 能重新设计场景、使用状态和 func 信息组织，而不是保留旧道具与旧 panel 后换颜色。
4. func 卖点具体、事实准确；size 数值、测量对象、单位和端点正确，文字可读。
5. 明亮通透、材质可信、道具比例/动线合理，尽量无人；普通无品牌书本文字允许。
6. 失败只补必要任务，成功图片/已收响应不重复生成；普通 resume 不陷入永久失败缓存，也不无限重试。
7. 每个 child 提供源图/成品对照和完整拼接图，逐张列问题，不只看缩略图或四张代表图。
8. 模板生成的范围、图片数量、QA 状态如实记录，不把 draft/inconclusive 宣称已完成发布验收。

### 成本与停止边界

沿用现有预算机制，不新增生产熔断 controller。测试启动前明确上限；同一确定性错误重复、发现真实主体结构回归、代码指纹变化或预算耗尽时，停止该受影响测试范围并保留现场，不自动重开新 job。其它已批准且无关的任务能否继续按事先约定范围执行。

性能用真实阶段时长、等待、请求数、复用率和峰值内存对照，不编造“必定十分钟完成”或以单次接口速度证明吞吐改善。

## 11. 发布纪律与最终交付

- P0-P3 在同一隔离整改范围内完成逐步检查，不让“新版 planner 配旧版 QA”的半套语义进入付费生产；不维护长期新旧双行为。
- 先记录当前脏工作区基线，保留已完成的正确修复。不回滚不相关改动，不自动提交或推送。
- 每项替换前列可达链路和旧代码清单；替换后搜索旧规则、旧 schema handler、旧缓存读取及锁死旧行为的测试。
- 对失败影响范围按实际依赖计算：源图改动、目标组件改动、单图布局改动不是同一种全量失效理由。不能为了避免失效而复用内容不符的候选，也不能为了“干净”把所有已成功图片重画。
- 必须区分两种情况：本次 schema/语义版本切换时，旧 kit 不作为新合同输入，既有任务不被自动升级或重跑；同一新版本运行中的局部失败恢复，才按稳定输入指纹复用成功结果。不承诺跨语义版本无条件沿用全部旧图，也不借版本更新自动重画历史任务。
- 交付分开写：代码完成、离线行为验证、远端流程验证、实图质量验证、模板完成度。任何一层没有证据就明确未验收。

最终顺序：**P0 商品证据与设计边界 → P1 规划/复核/执行统一替换 → P2 有界恢复与响应容量 → P3 当前 QA 和测试闭环 → P4 用户批准后的完整 child 冻结实测。**

重点不是删除更多提示词，而是让商品事实只保护商品，让 Gemini 的目标设计真正成为环境、床品、布局和配色的唯一权威，同时保留准确的产品证据和可恢复的生产状态。
