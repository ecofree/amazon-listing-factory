SAM 3.1 最小接入执行方案

推荐：接入现有 brief 内部的“实际编辑底图保护区准备”，复用现有规划审查、修复循环、ImageTask、原生 mask 传输和结果检查。

第一版使用已经实测的本地 SAM 3.1 INT8 环境，处理可见不透明产品构件及明确售卖实例。先完成当前调用链的受控接入验证，再根据实图结果决定启用范围。当前证据支持实施接入代码，不支持立即把 SAM 设成所有商品、所有角色的强制前置门槛。

业务阶段保持原样：不增加 segmentation stage，不要求逐图手工涂蒙版，不引入新服务或另一套控制器。SAM 只输出区域；商品事实、视觉设计和生成结果各沿用现有权威。

2. 接入的具体位置和责任

现有商品事实与观察 → 现有成套规划选定实际编辑底图 → 在 brief 内准备 SAM 候选 → 同一次规划审查核对实体、构件和区域 → 原修复循环内完成有限局部修正 → 原 brief 编译 → ImageTask／Prompt 指纹冻结 → 原 generate → 原结果检查

插入点：core/visual_design_kit.py::_finish_image_briefs() 的 compile_reviewed()，有效 draft 的底图已经选定之后、design_binding_request() 构建之前准备候选。当前 core/image_tasks.py 中 resolve_edit_references() 的调用与 _task_fingerprint() 之间只投影最终已审查的保护区，不在那里重新运行 SAM。

已有环节责任SAM 不承担的内容
商品事实／联合观察提供确认的售卖成员、附件、可见部件与 source/object 身份。不由分割分数决定单件/两件套，不用树盆或床品的一般常识覆盖商品证据。
成套规划／原规划审查决定目标画面与编辑范围，绑定实例位置，审核漏构件、误选和修正区域。不把 mask 作为设计模板；不通过新的单图规划器替代现有成套规划。
新增唯一区域模块＋本地推理工作进程执行分割、尺度映射、区域增删和文件输出；程序执行已经确定的约束。不决定事实、审美、ready、QA、候选批准或发布。
现有生成与结果检查发送实际原生 mask，检查最终结构、颜色、纹理和材质。不因 mask 合格就自动认定实图合格；不在失败时静默撤掉 mask。

4. 区域实现：固定一种方法，替换已失败的试验规则

  1. 固定真正提交的第一张底图。通过原 resolve_edit_references() 取得 product_sources[0] 的像素、SHA、尺寸；角色 source_id 只是证据锚点。输入、审查预览与 mask 使用同一图像解码和方向，工作进程不能单独旋转或裁切整图。最近 11 张源图均没有 EXIF 旋转标记；带 EXIF 的通用能力不据此宣称已经通过。
  2. 语义分割建立候选。使用简短产品或部件名称，保留独立 mask、候选框和分数。低分整件与高分局部都可进入归属比较，不能先按分数截掉需要的整件。
  3. 同一次原规划审查返回选择。把候选接触表、目标/部件清单及其身份送入原请求。选择结果必须绑定底图、父实例和目标构件；补漏位置可由已知构件的 SAM 查询框自动建立，不只搜索旧 mask 边缘。
  4. 局部处理只更新区域。全图统一坐标记录局部框、缩放与逆映射。产品补选与非产品删除分别计算；未被局部选中的像素不自动变成删除区。点提示仅在已绑定的同一实例/局部使用，沿用实际已测试的低分辨率状态语义。
  5. 用差异提交，避免整体替换。设已有保护区为 M，已核实归属的补选为 A，明确非产品的可删除支持为 D，已确认产品支持为 K。更新为 M_new = (M ∪ A) \ D，必须检查 D ∩ K、对其他构件的影响和范围越界。出现身份或木面删除矛盾时不提交该修正，并在原修复预算内处理原因。
  6. 保守约束不能冒充真值。K 来自既有观察/审查确认的产品支持，不能把多候选交集或“高分 mask”直接命名为真值。它能防止已经确认区域退步，无法自动证明尚未识别的构件完整。对疑似木面删除，在原审查中同时展示底图和删除区；既不能全部删掉，也不能把所有删除都判有害。
  7. 最终区域沿原审查合同确认。初始漏选与修正误删分开记录。明显构件遗漏、木面内部破洞、售卖实体误归属不能由点检查通过掩盖；粗略边缘不单独制造新的硬阻塞。

不迁入生产的旧试验规则：全图负点累计重算；只取 candidate 0 或预测 IoU 最大者；所有候选并集；按整矩形覆盖；按旧组件 mask 全量替换；未经核实的床品 mask 直接相减；全局填孔/膨胀/最大连通域；把 90% 包含率或本次 10% 裁切扩边写成通用品质阈值。这些目前是隔离研究脚本，不是待兼容的生产后端。

5. 同类多实例与跨品类的统一合同

不做床架、柜体、树的三套控制器。一次区域请求只包含：实际底图身份；事实引用；要保护的父实例及可见部件；位置锚点；允许编辑的对象；特殊表面策略。模型临时 candidate_id 不能当 ASIN 或持久 object_id。

  • 双树：事实确认两件时绑定左右两个父实例；同一树的整件和叶球候选属于一个实例，不额外计数。单件场景的另一棵树不能因“看起来是同类”自动保护。
  • 高柜：柜门归到主柜；背景洗手盆柜即使同类别也不合入。抽屉、柜门、把手和铰链属于组件关系。
  • 抽屉床：拉出的随售抽屉仍是同一组装体的一部分；抽屉中的衣物、书和摆件按售卖事实另行处理。
  • 身份冲突：空间重叠与模型分数只能辅助排序。没有唯一关联时，保留歧义交回原 brief 修复，不能靠并集猜测。

6. 最小数据与缓存设计

规划输入到区域输出保持单向：在原规划响应的 brief 内补充 region_intent（保护对象/部件、可见位置锚点、可编辑对象与特殊表面），供区域模块消费；编译后的 brief 仅保留最终 product_region 引用。当前观察已有 object_id 和部件事实，没有完整构件坐标，不能假定这些坐标已经存在。位置锚点在原有规划调用中形成，不另做逐部件观察请求；其作用是匹配候选，不是像素真值。

只增加一个 brief 区域引用。brief.product_region 引用当前底图的不可变区域 artifact。区域 artifact 保存实际底图 SHA/尺寸、事实与实例绑定、处理/模型版本、坐标映射、候选与修正轨迹、最终 mask 路径/SHA和实际调用耗时。不再建立独立 ready/status 控制器：最终状态由原 brief compiler 与其 design_review 决定。

原审查合同新增明确操作 product_region；存在区域删除时才检查相应变更。选择与修正放在审查行的结构化字段中，不挤进自由文本reason：

region_selection: {input_key, targets: [{object_id, candidate_ids, component_ids}]}
region_repairs: [{parent_id, part, operation, query, crop, positive_points, negative_points}]
operation: add_product | remove_nonproduct
crop: {left, top, right, bottom}，归一化到实际底图
points: {x, y}，归一化到实际底图

parser 核对请求key、候选范围、父对象、坐标与操作类型；不得丢掉不认识的区域finding后仍判supported。同步替换当前“supported edit不要求mask”的泛化文句：没有区域请求的编辑仍不附加mask要求；已带区域合同的请求须核对实际区域。相互覆盖的旧提示删除，不不断追加新禁令。

  • 区域内容 key 覆盖 child、实际底图像素、事实/售卖范围、保护意图、几何映射、SAM 代码/权重身份和处理版本。相同 Job 内相同底图与相同保护意图跨 role 复用；不同变体不因图片相同就盲目共用。
  • 审查请求覆盖该次候选/当前 mask 的内容 key；审查结果引用 key。内容 key 不包含 ready 或 review_key，避免自引用。区域改动后请求 key 改变，旧 supported 结果不能继续用。
  • 初始自动匹配的mask在同一次原审查中展示。选择改变、合并或局部修正产生不同mask时，沿原修复循环的下一次审查检查新的合并图；不能拿旧候选的supported替代新mask的审查。未改动且已有当前审查的区域不单独再开复审。首轮预算仍沿原review上限，不按每一根木条另起请求。

  • 黑白检查图和 API RGBA 图可由同一保留区域导出。内部 1=保护；API alpha 255=保护、0=可编辑。叠色接触图只供审查，不能作为普通第二参考代替原生 mask 参数。

7. 本地运行与效率

采用已经运行成功的 Comfy SAM 3.1 INT8 静态图路径，并固定实际代码、依赖、权重 SHA。旧方案中的 HF Space、多目标视频 wrapper、任意二值 mask 回灌和官方原权重重新下载，不作为本次接入依赖。不得把低分辨率 decoder 状态与外部二值 mask 回灌混为一谈。

  • 主项目继续用 D:\anaconda\python.exe。独立工作进程使用已安装的 SAM 环境；主环境不再装一套 Torch/Comfy。路径通过现有本机配置提供，不写死用户目录、实验日期，不移动当前 venv，不把模型或环境提交 Git。
  • 生产 worker 不 import/exec 隔离实验脚本，不读取历史候选 mask。现有环境与权重可作为已授权运行依赖引用；图像、mask和任务输入必须来自当前 Job。清理依赖目录须先检查配置引用。
  • 沿用现有 provider_concurrency_slot('host_gpu_auto')，一次本地 GPU 推理进程；按本次 brief 批次复用权重和同图特征。权重哈希在启动/固定身份时核对一次，不每张图读取 1.2 GB。
  • 导出 CPU mask 后及时释放 GPU；brief 批次结束关闭工作进程，异常、deadline 和取消时也关闭。generate 不驻留 SAM，避免挤占已有图像请求的主机内存。测量冷启动和进程树峰值 RSS，不能把 1,754 MiB Torch 显存当 CPU 内存预算。
  • 一个底图一次候选准备、一批必要局部请求、最多一轮区域修正，沿原 brief deadline 和修复预算。局部前向必须逐项计数；不另开独立 Gemini 区域轮询。若测试发现真实必要请求超出原预算，先校正责任环节与重复请求，不能删掉构件要求来凑次数。
  • 不提高 core/image_resources.py 的现有内存门槛，不通过永久常驻进程消耗生图容量。新增资源预约确有需要时扩展同一资源权威，不建立第二份队列/账本。

targeted_edit 用当前候选做底图不能复用原图坐标mask。当前代码移除原mask是防止坐标误用的必要行为，不能删掉这条保护。第一版声明SAM自动生产者用于brief形成的普通编辑任务，不宣称targeted_edit已获得同等mask保护；现有候选编辑合同继续负责保真。需要候选mask时另用同一模块在原修订入口、不可变请求形成前准备，并核对授权编辑区，不能自动保护恰好要修的错误部件。
无候选、worker失败、归属不明或审查未决任务沿现有brief／review原因处理，无依赖的child/role继续。新蒙版任务不伪造ready、不复制原图交付、不无限修正，也不静默改走无蒙版路线。

将 targeted_edit 自动蒙版明确后置可以保持第一版改动范围；若用户要求首轮覆盖所有自动候选修复，这一项必须加入同一接入提交并补实图验证，不能隐瞒为已支持。
