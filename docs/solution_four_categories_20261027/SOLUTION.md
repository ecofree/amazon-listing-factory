# 四品类问题复核与最小闭环方案

日期：2026-10-27。状态：**设计方案，尚未实施**。

本轮只读复核生产代码/指定证据，在本目录运行隔离合成反例。生产代码、原作业、原回执、额度、已有图片均未修改；付费调用 0。没有执行历史作业恢复、正式 QA、发布或真实生成。

## 1. 结论先行

最佳方案不是「继续加规则，然后全量 resume」，也不是把 blocked 改成 ready：

> **保留唯一执行链，先修证据与接口边界；把四类语义放回各自声明；一次冻结代码后，对已有产物做有范围、有证据、有批准的恢复；最后有限验证与交付。**

原因：当前主要问题叠加了三件不同的事——**产品语义错误、已付资产与当前合同脱节、工程链未真正贯通**。单改提示词或增加重试不能一起解决。

- 947 个已建角色中，908 个有候选，另有 7 个保存了原生结果；32 个仍是原生图请求未知。**843 blocked 不等于 843 张待生成。**
- 就该 947 角色基线而言，没有证据支持立即增加新生图 POST。先处理已有结果与原请求；另一个尚未建立有效初始规划的子体不能被悄悄排除在完整家族目标之外。
- 现有严格来源/候选校验应保留。恢复入口需要改，但不能退回「同源 SHA 就沿用旧批准」。
- 四类共用执行框架是正确的；两个柜类共用 storage/CABINET 类型也不是错误。要隔离的是输入身份、事实语义和类目规则，不是复制四套程序。

## 2. 保留与删除边界

### 必须保留

- 唯一观察、事实、原规划器、提示词编译、候选、QA、人审、发布权威。
- 原接受内容与原始响应、请求身份、来源 SHA、实际输入、候选版本、收费/未知约束；不重写旧 accepted/content_id 来匹配新代码。
- 已修的 `candidate_prompt_current()` 共用判定、完整响应结算、未知防重发、真实事实撤销、原图编辑及原生/后处理分层。
- 当前 947 角色库存与完整家族目标；执行子集不是缩小交付分母。
- 已确认的 safeplus / US / 树类 GTIN 豁免等按原范围复用，不重复索取，也不外推到另外三类。

### 必须随替换物理删除

- 类别决定无轴尺寸顺序、树高取最大值，以及上游无轴即当 LWH 的路径。
- 把所有类别的真实 Size 标签套入床架命名规格过滤器的调用链。
- 分类输入递归拼入 related/review/其他商品的路径。
- 用自由文本 kind 作为布景授权主键，以及整体撤回同类道具权限的替代逻辑。
- 被迁移的 core 类目词表/分支；不能 core 与 manifest 各留一份。
- 全量重编译/重写未选角色的修复路径；新投影替换误导性的单轴“待生成”统计。
- `Final_pics/.../role_job.png` 导出、异内容静默覆盖，以及失败后偷偷换名导出的路径。
- 手工补字段才可通过的交付测试假对象；以真实生产者→消费者契约测试取代。

不恢复旧 `style_profile`、独立 qa_rules / template_mapping、副本权威、多重视觉裁判、审美打分、自动重生或硬 mask 保真承诺。

## 3. 三项核心设计

### 3.1 分开“产物存在”与“当前可用”

在现有候选/生产状态权威增加**只读派生投影**，不写第二套账本：

|维度|唯一证据来源|不能推导的结论|
|---|---|---|
|产物存在|原生回执、CandidateManifest、实际文件和 SHA|有图不等于合同有效/QA 通过|
|当前绑定|当前事实、有效角色合同、实际请求/附件、候选绑定证明|blocked 不等于没生成|
|质量资格|当前候选对应的唯一 QA 与既有人审|旧 inconclusive 不能变 pass|
|发布/交付|当前 release、远程 GET 字节/有效期、导出清单|文件在 Fianl_pics 不等于已正式批准|

已有 `current_candidate()` 可能恢复 staging、补 sidecar、结算回执，**不能把它当成原作业的只读盘点函数**。盘点应在同一候选权威内使用无副作用检查；真正本地提交另走明确操作。

修 N01 时，由候选权威返回经过核验的来源信息/不可变 manifest 引用，交付模块消费该契约。当前任务身份与原请求身份必须区分，避免等价复用时把旧 task_fingerprint 覆盖回当前任务。交付 JSON 使用显式、可序列化的工件引用与 SHA；不靠 `default=str` 掩盖字段类型/路径边界问题。

### 3.2 修真实输入语义，不用下游兜底

1. **主商品身份**：分类读取同一主 ASIN 的直接类目、标题与结构化商品证据。推荐、评论、A+ 中其他商品不能同等投票。直接证据冲突/只有宽泛 storage 信息时明确待确认；保留后置家族检查。不要扩成无止境关键词分类器。
2. **变体标签与物理尺寸**：原始 `Size=6 FT` 是选择标签，不能因为带单位被删除；Queen 是床垫命名规格，不是床架外形尺寸。两者均保留来源，按对应类目与真实工作簿字段核验。物理尺寸、包装尺寸、推荐厚度不能反向覆盖标签。
3. **尺寸事实**：保留来源字段名、测量对象、轴、值、单位及限定条件。有明确 `L×W×H` / `D×W×H` 字段或值内标识才映射；无轴元组保留原文并标明缺证据。单位换算不能创造轴。原数据若已丢掉字段顺序，回查原证据，不能按类目重猜。
4. **布景权限**：同一个原观察权威提供稳定物体类型和实例归属。授权针对具体 source/object 及明确的新非售道具插入范围；售卖主体/随售附件/未知归属不得因名称变化被授权。存在随售毛巾也不应禁止所有另一个明确非售毛巾实例。
5. **条件事实**：缺失、不适用、明确 false 三者不同。库存/价格/合规声明按 SKU、卖家、市场及有效期绑定；178 项模板条件不能变成让运营机械填写 178 个布尔值。

### 3.3 硬约束、建议、依赖各归其位

- 建议：`planning_guidance` 影响未完成/未来规划；原请求已经冻结的实际上下文继续可追溯，旧接受不因此失效。
- 硬约束：使用现有 policy/合同权威，明确 category/role/适用事实，进入实际请求及当前性判定。未被读取的 manifest 文字不算落地。
- 依赖：哈希实际发送/编译的输入投影及不可省略的身份、售卖归属、来源、纠正、品牌等关键条件。**不能仍把全 facts 发给模型，却只从缓存键删除几个字段。**
- 局部变化只有在确证未影响角色事实、实例、文案、测量、区域与实际编辑输入时，才可局部失效；不能承诺 package_quantity 改动一定与主图无关。
- 稳定证据 ID 防止纯措辞漂移扩大失效，但不得猜 old ID→new ID，也不得忽略观察 state/product_features 的真实变化。缺乏可证对应时，由原观察/规划权威在明确范围内确认，不新增裁判。

## 4. 工作包、代码落点与验收

所有代码先在隔离样例上完成、冻结，再对历史数据做一次有差异批准的应用。不要每修一项就对四原作业重算一遍。

### W0｜准入预算与冻结清单（第一步）

- 落点：`scripts/run_production_tests.py`、现行测试/fixture、现有审计记录。
- 合并重叠行为测试，把新增精确观察复用场景纳入已有对应测试；保留正反例。不得提高 100/60 上限、过滤现行用例、用 skip 隐藏超限。
- 记录代码、关键配置、原作业输入/派生产物与请求索引的前置 SHA；不为盘点调用有写副作用的恢复读取器。
- 验收：默认集合 ≤100；实现过程中仅目标测试，最终冻结后默认套件一次 ≤60 秒。报告测试精确命令、数量、耗时及未验证范围。

### W1｜资产投影与候选→交付契约

- 落点：`core/candidate_state.py`、`core/production.py:image_pipeline_boundaries()`、`core/delivery_package.py:_bound_evidence()`、控制台对应展示。
- 按 3.1 分列状态；有候选/原生结果但合同阻塞时，下一步是核证绑定或本地收口，不是新增 initial POST。
- 修来源 DTO 和路径序列化；使用原生回执 owner 的核证能力，不让交付另写一套候选有效性算法。
- 删除：误导性单轴统计、手工扩充候选投影的测试捷径。
- 最小验收：真实候选生产者→读取器→交付证据→JSON 序列化闭环；等价复用保留原请求身份；缺/错原生证据拒绝；读取盘点不写原文件。纯接口测试不证明图片质量。

### W2｜身份、变体、尺寸、实例权限的源头修复

- 落点：`core/category_guard.py`、`products/generic_extractors.py`、`core/product_family.py`、`core/template_field_values.py`、`core/template_engine.py`、`core/required_role_policy.py`、`core/visual_semantics.py`，以及实际消费的四类声明。
- 实施 3.2；抽取与模板使用一致的有依据轴向语义，不保留两个相互矛盾的解析回退。
- 最小验收：床架加入 related 药柜不高置信改类；6 FT / Queen 经真实 listing-row/field-plan 链保留；同一无轴元组不因分隔符改变被猜成不同高度；包装尺寸不冒充主体尺寸；随售/非售同类型不同实例分别授权。
- 影响保护：先输出事实变化及受影响角色清单。被撤销的无依据默认值不能为恢复数量重新填回。

### W3｜四类规则归位与规则身份

- 落点：四个 `products/*/manifest.yaml`、`core/plugin.py`、`core/config_merge.py`、`core/required_role_policy.py`、`core/planning_contract.py`、`core/planning_identity.py`，及现有关键词/模板消费点。
- 迁移具有业务语义的类目词表、模板提示、恢复差异；共享类型相同的字段/执行逻辑不重复实现。无轴猜测是错误逻辑，应删除，**不是搬进 manifest**。
- 把真正硬规则绑定到类目/角色；建议保持非追溯。不得建立通用表达式规则引擎或四套插件控制器。
- 最小验收：改变树类某角色硬约束只影响相应依赖；建议变化不撤销旧接受；浴室柜与药柜搜索/字段边界不同但合法共用 CABINET 模板类型；core 中被迁移的分支不再可达。

### W4｜有界规划与受控历史结果回接

- 落点：`core/visual_design_kit.py` 的 `build_visual_design_kits()` / `_recovered_ready_role()`、`core/planning_identity.py`、`core/planning_provenance.py`、`core/image_tasks.py`、`core/image_task_inputs.py`、`core/image_response.py`、`core/image_generation_executor.py`、现有 production/factory 入口。
- 执行选择独立于完整 RunScope：明确 child/role、阶段、期望输入/合同/候选修订。未选角色不重规划、不补 SAM、不消耗额度；完整库存不删。共享设计变化确实影响更多角色时，报告影响并停下，不自动扩大授权。
- 不再要求当前 brief 先为 ready，才允许查找原成功证据。先按原 job/child/role 查候选、原生结果、封存接受和原请求，再验证是否能形成当前合法绑定。
- 仅纯本地可核证的同一执行内容/附件及合法当前合同允许确定性回接。原接受记录保持原样，采用决定单独引用其证据和当前修订；不改旧 accepted/content_id、不按相似文案或文件名认领。
- 需要语义判断时，由原观察/规划权威处理精确缺口；新调用必须另获有界预算。历史格式/证据不完整则停在待补证，不能加永久旧版兼容读取器。
- 缺少原生/后处理来源时，不能补写“当时已执行”的处理记录。若原生结果完整，可另获授权做新的本地成品派生，保留旧版本并记录本次真实处理；不能虚构已发现超分伪影，借用仅允许伪影修复的入口。
- 编译/合并选择内的角色变更；保留未选的封存内容及原归属。未选角色的当前性仍由同一校验投影决定，不强行保 ready。
- **文字规格尺寸例外**：用户已作的具体授权要核验并承接，但不能伪造成图上 measurement_id。若接纳此模式，扩展现有 measurement authority 为显式来源分型：图上测量，或同子体商品陈述（原始证据引用、对象、轴、值、单位、限定条件）。原规划器选择，编译器按来源输出，唯一 QA 对应检查；不是失败后自动 fallback。没有图上端点证据不得画成已校准测量。
- 最小验收：pending 但原证据齐全的旧产物可进入核证；真实事实/来源/纠正冲突仍拒绝；选择一个角色不动兄弟封存记录/额度；已 received 只本地处理、网络调用计数为零；证据不足不生成假合同。

### W5｜唯一发布与交付出口

- 落点：`core/publish.py:_export_final_pics()`、现有模板交付调用点、`core/delivery_package.py`。
- 图片：`Fianl_pics/<parent>/<child>/<role>.<ext>`；子体 URL 清单同目录。模板：`Final_templates/<parent>/<template_file>`。
- 父子归属来自核证 family mapping；canonical 图/工作簿仍在原 job，外部目录仅为单向交付投影。模板只用当前合格、已核验的真实 URL。
- 同 SHA 幂等；异内容默认停止。确需替换时要求明确目的、原目标 SHA、新来源 SHA、候选/发布修订及决定 ID；保留可恢复原件，先写临时文件核验再提交。中断恢复不重复上传或生成。
- 已有 1254 原生图/未批准图可作为明确标记的检查材料保存，但不能仅因处在 Fianl_pics 就计作正式合格交付；不得把尚未发布的 URL 编出来。
- 最小验收：准确父子路径、同名异内容拒绝、同 SHA 重入、并发/中断、清单与实际字节相符；job 内模板唯一权威不受外部副本反向影响。

### W6｜原费用约束与业务身份承接（付费恢复前硬门）

- 落点：`configs/production_workspace.json`、`core/batch_ledger.py:reconcile_prior_work()/adopt_prior_order()`、现有请求 owner、业务输入与 TemplateFieldPlan。
- 先明确核证范围：已固定的历史来源、四个原作业、相关独立授权/替换链。针对明确清单设计一次性显式约束导入，不在 dispatcher 中扫描历史目录，不建平行运行账本。
- 固定工作区若启用，必须承接原订单/目录、消费与预留、未知/替换、重试及时间约束；不是建空账本获得新额度。现有 15 项清单不自动代表四原作业已覆盖。
- 按可核证的物理提交身份去重，而不是按候选版本、角色数、导出次数，亦不能假设所有重试都有不同供应商 request_id。无法消歧的记录保持限制，不能记作零费用/未发送。
- 账单金额、请求结果、重发授权三件事分别记。原始响应不存在，不能由“500、0 tokens、$0”生成执行失败证明。
- 最小验收：重复登记不增加额度，原 unknown 不释放，原目录唯一承接，配置/代码漂移暂停；业务证据仅在原有效范围复用。纯本地盘点/归档不应为了运行而初始化付费域。

### W7｜原作业受控恢复（必须另行批准应用）

- 在 W0–W5 冻结后生成 dry-run：每个动作列原路径/旧 SHA、目标内容 SHA、证据引用、影响角色、预计网络/付费数、写入集合及回滚位置。
- 分开批准：本地派生文件/候选收口、工作区/业务登记、模型规划、QA、发布。批准其中一项不代表授权其他项。
- 加原 job 锁并比较前置 SHA；变化即停止刷新提案。幂等决定 ID；原回执/接受证据不改造；新有效派生产物引用原证据。
- 本地事务只改批准的文件，备份仅对应前版本。不因回滚派生文件而回滚已经发生的请求或账本消耗。
- 验收：写入集合与提案一致；既有图片 SHA 不变；角色库存不减；未知及其消耗不变；读取器与候选/任务绑定检查通过。成果只能称“恢复/绑定完成”，不能称 QA、正式交付完成。

### W8｜四类有限真实退出门与扩量

- 先复用已付样例，不为检验新代码重新生同图。每类一个黄金子体覆盖所需角色，加一个对应难例；另做一整个家族的变体、URL、工作簿与交付包闭环。子体样例不冒充完整家族。
- 固定代码/规则/来源/模型/实际请求，分别保留 source、native、final。区分原生结构漂移与后处理伪影；模型参数或一次目视改善不是保证。
- 唯一 QA 只查硬事实与发布要求；不确定走现有人审，不加审美裁判。未获新授权不增加 QA、规划或生图付费调用。
- 原 32 未知（含指定保护的 21 条）继续保留；需要新请求时，必须单独说明确切原请求、恢复失败证据、风险、范围、限额与消耗。不能从本方案推导默认重发授权。
- 扩量条件：当前默认套件通过；本类难例与完整交付证据成立；费用承接成立；有限批次无作用域外请求；发布有效期及持续运行验证有独立记录。停止条件见第 7 节。

## 7. 实施顺序、停止条件与批准边界

### 推荐顺序

1. **W0**：先解决测试预算，不进入功能开发。
2. **W1 → W2/W3 → W4 → W5**：免费离线代码修复及集成；W6 的证据清单设计可并行，但不启用新付费域。
3. 冻结同一代码/规则修订，运行最终默认套件；输出删旧路径、代码行数变化和最小反例结果。
4. **W6/W7**：拿到明确批准后，按提案登记原约束、应用本地恢复。先本地、再必要的原权威有界确认；不先全量重新规划。
5. **W8**：另获预算后做有限正式 QA/人审/发布/完整工作簿验收。需要新生成时另列具体对象和原因；不是恢复动作的隐含权限。
6. 有证据后才扩量。24 小时持续运行、供应商稳定性、平台接收均另有记录，不能由一次离线套件推出。

### 必须停止

- 当前输入/代码/配置与批准快照不一致，或未知请求/消费无法对齐。
- 需要扩大执行范围、改变交付分母、推断旧 ID、伪造事实/测量/批准。
- 已有文件同名异 SHA 未获明确处置；原生或候选证据缺失/冲突。
- 现有大生产文件超过 2,000 行却净增；新生产模块 ≥800 行或新测试模块 ≥600 行且没有批准。
- 默认套件超预算/失败，或替换后旧运行路径仍可达。
- 实图出现结构、数量、颜色、文案、尺寸等硬事实失败；暂停该范围，不自动重生或换评分模型。

### 回滚原则

代码回退只回退本次明确补丁，不动工作树其他未提交修改。恢复文件回退只使用批准提案对应备份，且先确认后续没有新写入。账本/回执采用保留事实的后续决定，**不能为回滚删除请求、撤回消耗或把未知改成未发送**。共享源码变更前暂停/清点活动 worker，避免跨版本派工。

### 本次没有要求重复提供的内容

已确认且未失效的商家/市场/树类豁免不重问；已有独立补图授权先查原证据。只有确实缺少的原响应、准确来源链、未覆盖业务事实，以及新的写入/付费动作才需要补证或授权。没有完整原响应的历史请求可以继续保留未决，不强迫以承担重复收费换取表面完成。
