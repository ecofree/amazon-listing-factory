# 冻结续跑为什么仍阻塞：只读归因 — 2026-10-12

## 结论

“预算耗尽”是最终停机条件，不是完整根因。原报告中的 15 pending 包括历史额度已经耗尽、缺少新蒙版确认、尚未派发的合同修复，以及**请求合同与执行准入不一致**。

最后一种是上一轮实施仍留下的真实缺口，不能归咎于模型随机失败，也不能只靠每次追加 1 次请求解决。

本审计只读取四个指定任务与冻结源代码；没有追加额度、发起模型/SAM/图片请求、重发生图、修改生产代码或原任务。审计期间另一次续跑更新了原任务，因此分别保留了两个时点，不能声称整个审计期间任务文件都没变化。

## 3. 确认的实现缺陷：最后一次调用可以提案，但不允许执行

当前控制链：

- `core/visual_design_kit.py` 约 354–368 行：先扣除本次调用，按剩余容量计算 `can_modify`。
- 只追加一次时，本次请求之后剩余为 0，所以 `can_modify=false`。
- 同处 `writable_fields(..., semantic=True)` 仍开放 `region_intent` 等区域字段。
- `core/planning_contract.py:response_row_schema()` 只用 `can_modify` 限制 `change_region`，**没有同样限制 `patch_plan` 的物理字段**。
- `core/visual_design_kit.py` 约 307–309 行：合法 patch 完整校验后，因为已存在 mask、区域依赖变化且 `can_modify=false`，抛出 `Another physical modification or its confirmation is not authorized`。

因此发生：

```
追加 1 次 → schema 允许提区域修改 → 模型返回合法 patch
         → 执行器禁止修改 → patch 不提交 → 额度再次归零
```

两个当前受影响角色的内存探针均证实：

- 原始回执及当前输入绑定有效；
- 回复 schema 错误 0；修改后的完整合同错误 0；
- `region_field_writable=true`，但 `can_modify=false`；
- `region_operations=0`，不是已经用完本地修改机会；
- 会命中执行拒绝条件，且提议确实未提交。

这不是“源证据未必支持”的模型判断，而是程序给出的能力合同不一致。不能通过忽略预算检查、强迫接受旧蒙版或无蒙版生成来掩盖。

### 两个放大因素

1. 有效但尚不能执行的修改提案没有保留为可继续的待执行工作；下一轮又购买修改决策。
2. 最后 `set_issue(... budget_exhausted ...)` 覆盖前面的具体错误。追加额度恢复时又清空 `protocol_failures`，即便输入未变。紫树同一个失败签名在第四次、第五次后都计为 1，而不是累计为 2。

结果是报告只显示“再加一次”，既隐藏根因，也削弱了跨次授权的无进展防护。

## 4. 对“总共再加 7 次”的修正

原报告的每子体 +1 只能作为试探性授权，不能称为完成预算。按原报告当时的保护目标，蓝药柜 size 和紫树 func 都有修复→新结果确认的依赖；缺陷不改时，紫树只加一次会继续命中同一拒绝分支。最新实际续跑也验证：加了七次以后仍有三项未完成。

从 **14:15:40 的最新状态**看，在保持现有控制方式、每次修复/确认都一次成功且不发生新问题的条件下：

- 蓝药柜 size：1 次新蒙版确认；
- 棕药柜 scene_04：2 次（修改决策/执行，再确认）；
- 紫树 func：2 次（修改决策/执行，再确认）。

这是条件性工作量估算，不是成功保证，也不是本审计授予的调用权限。优先应修复提案保存和能力合同，而不是继续按一次一笔盲目充值；修复后，已保存且绑定有效的提案是否能显式接续，应经过明确的执行权限与回执规则验证，不能自动伪造新的 accept。

## 5. 应改哪里，而不是加新审核层

1. 请求 schema、可写字段和执行器共用同一个能力/预算依赖判定。
2. 对有效但预算不足的区域修改，明确保存“待授权执行及确认”的工作；不把它标成协议错误后丢掉。
3. 区分本次调用额度、合法修改准入、新结果确认的剩余容量；授权前列出依赖链，而非统一每子体 +1。
4. 保留原始阻塞原因；预算不足只作附加状态。仅追加额度不能清空同输入的无进展记录。
5. 继续保持接受独立、候选不可变、真实事实与几何约束、未知付费响应保护。没有新增审查模型或第二控制器的必要。

## 6. 未知图片请求是另一条边界

原报告中的 RemoteDisconnected / SSL EOF 只表示客户端不知道远端是否完成，不证明请求没执行。停止自动重发是正确的付费安全边界；与上述规划死循环无关，也不取决于它是否为 HTTP 524。本审计未对其后续重发/生成结果作验收，不授权任何重发。
