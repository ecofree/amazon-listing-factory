# 远端蒙版归因验证与白床漏保护：最小执行方案

日期：2026-10-15。状态：方案，尚未执行远端实验。本轮没有付费请求、没有修改生产代码或原作业。

## 1. 要回答的三个问题

1. 网关是否把正确的 image/mask 和编辑参数传到实际执行端？
2. 正确传递后，执行端的输出是否随蒙版改变，并在保护区遵循保留要求？
3. 白床烟囱缺失能否通过修复已确认的漏保护改善？

这三个问题分别取证。局部产品重绘既可能伴随蒙版生效，也可能伴随蒙版被丢弃；不能用重绘这一症状直接推断原因。

## 2. 当前已有证据与新核查

- 三组真实请求的离线 multipart 重建均包含独立 mask；源图、发送蒙版和实际提示词哈希匹配；alpha 与原蒙版一致，只有 0/255。当前已排除这些本地准备错误。
- `core/api_registry.py:119` 仅根据配置声明判断支持 mask，不是远端验证；其 “enforce an immutable pixel mask” 注释超过实际能力证据。
- `core/provider_smoke.py:188` 使用 32×32 全透明蒙版，没有保护像素；只能检查调用与图片解码，不能证明主体保护。
- `core/planning_feedback.py:101` 初次建稿可带全部可见源图；后续通常只带当前 `product_sources`，第 152 行的观察证据也按这个集合过滤。同子体其他源图中已有的烟囱事实，不能指望后续无状态调用自动记住。这是确认阶段的证据可达性缺口，不等于证明初次规划从未看见烟囱。
- `core/planning_contract.py` 已有“小支撑/不同材质也要保护”的规则。仅继续追加泛化的保真语句不是本次主要修法。
- 白床全部 10 个原候选都没有完整烟囱，核心区域最高约 4.2% 覆盖；裁剪范围包含烟囱。不存在通过重新挑选一个旧候选即可解决的依据。
- 实际白床 `region.json` 的 `repair_round=1`，本轮机会已用于 `select` 合并整床和板条两个视图。不能再在此版本强行追加 delta 或清零轮次。

既有证据：`THREE_IMAGE_ROOT_CAUSE_AUDIT_20261014.md` 与 `test_runs/three_image_root_audit_20261014/`。本次只定向核查原三项及其当前代码，没有扫描其他历史作业。

## 3. 最小远端验证：先取得边界证据，再发有判别力的请求

### 3.1 第一步：优先追查原请求，新增生图 0 次

向服务方准备以下追查清单；发送给第三方须另有用户授权。本轮仅准备，不代发。

| 原案例 | 本地记录的 remote request ID |
|---|---|
| 白床 / cxk sunburst | `7fe23c95-8da8-4434-bcd5-c55bbcc97a6a` |
| 白玫瑰 / bilinkai-fixed sunburst | `bd6586c9-cd9a-49f7-bfbf-936def6b1f05` |
| 白柜 / cxk 2.5 | `f95cdc9e-f6c3-4ff7-88c5-4b9c43eb11f3` |

要求服务方将这些 ID 关联到实际上游请求，而非仅回答“支持 mask”：

1. 网关入站解码后的源图尺寸、RGBA 像素摘要、mask alpha 像素摘要、0/255 像素数量。
2. 出站到上游的实际 endpoint、后端模型/版本、上游请求 ID、image 顺序、mask 字段和解码后的相同摘要。
3. 尺寸变换、裁切、透明通道转换、提示词改写、模型替换的实际记录。若发生合法统一缩放，提供变换参数与变换后的对齐证据，不能只以 PNG 文件哈希不同判错。
4. 上游对 mask 的接收/解析记录或具备这种可观测性的受控复现；仅网关声称“已发出”不证明上游实际解析。
5. 上游原始生成图与交给客户端的图，及其间的缩放、裁切、拼接、压缩记录。

不得索取或输出密钥、图片 Base64。摘要可以由服务方计算；没有历史日志时改为一次可观测的新实验，不反复追索不存在的日志。

### 3.2 第二步：固定一条路由的互补蒙版对照，2 个请求

先选原白床使用的 cxk / `gpt-image-2.5-sunburst`；先确认该次可获取上述边界记录。此模型名是当前路由别名，不据此声称知道其实际后端身份。

**诊断图：**1024×1024，无文字、无商品事实、无 SAM；白底左右各一个大小相同的灰色方块，内部有粗纹理标记。使用大块内部区域，避免边缘抗锯齿影响判断。原图由本地确定性脚本生成，固定 SHA。

| 请求 | image / prompt / provider / model / 其他参数 | 唯一变化：mask |
|---|---|---|
| A | 完全相同 | 左半不透明保护，右半透明可编辑 |
| B | 完全相同 | 右半不透明保护，左半透明可编辑 |

固定提示意图：将可编辑区域中的灰色方块改成蓝色；保留非透明保护区域的方块、位置、大小、纹理与背景。提示词不出现左/右指令，避免文本代替蒙版指示区域。

- 两次 mask 的 RGB 内容相同，只有 alpha 互补。均由独立 `mask` 字段发送。
- 请求尺寸、质量等固定；串行，不切 provider，不自动重试，不使用未经支持的 seed 参数。
- 同一当前传输函数构造请求，离线先检查字段、图片和 alpha；保存经过脱敏的请求元数据及非图像响应诊断字段。
- 比较原生输出，跳过项目超分和发布；不把 1254 等返回尺寸本身当成模型替换证据。
- 原生尺寸不同时按坐标比例测量，使用内部 ROI 及粗纹理；只允许预先定义的统一缩放比较，不能局部配准把位置或几何变化“校正掉”。
- 分别记录编辑区域是否变蓝、保护区域颜色/纹理是否变化、几何是否移动。阈值在出图前用本地重采样对照标定，仅用于本实验，不新增生产闸门。
- A 只改右、B 只改左，表明这条链存在与 mask 对应的区域控制。仅凭这两张仍不能证明是模型内部处理，网关也可能做区域处理；也不能证明对复杂产品绝对保真。
- 两张都乱改、两张都不改或行为不一致，均不能仅凭图片判定网关丢 mask。拒绝编辑与保护失效也分开记录。

**为什么不用全透明/全不透明各一张：**全透明没有保护对照，全不透明可能退化成无操作；互补蒙版在每次请求中同时包含“应修改”和“应保留”的区域。

### 3.3 必要时：同一真实上游的直接对照，至多再 2 个请求

仅在需要检验网关影响且能够确认并访问同一上游模型/版本、接口、参数和输入时，向上游直接发送 A、B。该访问条件未核实，不能预先承诺可执行。

- 同名模型换到另一个 SubRouter provider，不算直接上游对照。
- 不增加生产服务，不写生产路由切换，不购买新服务；隔离实验使用合法获授权的访问方式。
- 直连成功、网关失败是路径差异证据；还需边界记录定位究竟哪里变了，不能忽略随机输出与后端漂移。
- 若服务方不能提供任何上游可观测证据，又没有同一上游直连，当前黑盒条件下无法唯一识别内部责任。明确给出“该接口无法完成归因”的诊断结果及缺失的确切证据，不消耗更多普通商品请求掩盖这个限制。

### 3.4 结果到修复的对应关系

| 取得的证据 | 能下的结论 | 精准处理 |
|---|---|---|
| 网关入站正确，出站丢 mask、反 alpha、错配 image 或变换未对齐 | 网关处理缺陷 | 修实际转发/预处理；同一对照复核。项目不靠提示词补偿协议丢失 |
| 上游返回正确，客户端收到的原生图已改变 | 网关返回后处理缺陷 | 修返回后处理；先复用原响应验证，避免重复生成 |
| 正确 mask 被实际执行端解析，受控输出仍越界，网关未改图 | 上游执行端未遵循区域要求 | 若能定位到模型输入边界，归为模型执行；否则标明上游服务内部，不伪称神经网络已被单独定位 |
| A/B 区域控制有效，复杂商品仍改变结构 | 基础区域控制有效，产品几何保真未达标 | 区分小部件漏覆盖、边界外扩及受保护区内部重绘；不继续修本地上传或盲目增加 SAM 查询 |
| 只有图片差异，没有边界记录 | 只能给行为证据 | 不给网关或模型定责；补指定边界取证，不原样重试 |

这些结论只覆盖被验证的路由与后端版本。cxk 结论不能自动推广到 bilinkai-fixed 或其他模型。

## 4. 白床精准整改：证据供给 → 实际分区修正 → 单变量实图

### 4.1 修改原确认调用的证据供给，不引入第二规划器

在 `planning_feedback.request_planner_tool_decisions` 的现有输入投影中，保留实际编辑源图作为坐标权威，同时让后续确认能读取同子体已有的产品部件观察及 source/feature/owner 来源。复用已有 `source_manifest`，不建立第二套持久事实、额外模型调用或独立识别流程。

替换当前“确认阶段把所有结构证据一起按编辑图过滤”的投影：编辑附件仍按任务需求选择；已有结构观察作为可追溯参考。不能简单把全目录图片都再次附给模型。

参考事实只用于提醒核查：烟囱必须在当前 source_03 上可见并定位，才能加入该底图保护。其他源图的遮挡面、配件、重复视图、同名 object_id 不能被程序直接合并成此图已确认的部件。模型完成跨视图归属，程序保留原始来源，不自动制造新商品事实或 caption。

将原“两个视图存在即够”的接受理由替换为检查实际可见产品构件的依据。功能文案仍只表达已选卖点；保护范围不能被 caption 列表缩窄。

### 4.2 用现有 region_intent 和 SAM 修正路径补真实缺口

原白床版本已使用一次区域修改，因此不在旧版本继续追加，不改 repair_round，不重置 planning_journal。

1. 在原任务的允许修订字段中开放真实缺陷对应的 `region_intent`，保留正确文案与视图布局。
2. 由原规划器给 `bed_frame_01` 增加烟囱局部 `parts`，裁剪只覆盖实际底图中烟囱及必要的连接处。不是新增售卖实例，也不是另画一个部件图。
3. 真实意图变化使现有 `ProductRegions.prepare` 生成新版本；保留原历史与消耗，不更换 job 绕预算。
4. 保留两张功能视图的保护；新局部查询如果仍不完整，在新版本原有的一次修改机会内，将候选选择与烟囱的交互 `add_product` 一起提交，随后沿原确认入口检查。
5. 正点落可见烟囱实体，负点落相邻墙面/床品；语义准备中的点只用于诊断，只有现有交互 delta 才实际用点提示。禁止把改几个诊断点声称为分割已修复。
6. 对原烟囱核心 ROI、连接处、整床视图、板条视图及邻近背景复核；不要求全图每个边缘像素 100% 精确，不将此 ROI 阈值推广成所有产品的生产拦截规则。

若新版本局部修正也失败，记录精确缺口交回现有人工入口，不自动扩大蒙版包住床品，不循环购买规划额度。

### 4.3 离线验收覆盖实际失效路径

最少合并行为用例：

- 后续确认收到已有烟囱事实及来源；当前底图未显示的参考部件不能变成自动新增部件或文案。
- 旧 `repair_round=1` 不可二次追加；实际意图修订生成新 region 身份，原账本和历史保留，禁止旧 acceptance 冒用新 mask。
- 新版同 owner 局部追加与两视图选择合并、执行中断续接均正确；不串实例、不把诊断点当交互提示。

只在实施代码修改后运行定向用例，冻结后完整生产套件一次，仍 ≤100 例、≤60 秒。本轮方案阶段不运行全套。

### 4.4 最后只生成白床 1 张，有明确比较价值

在远端边界实验完成、修订合同和新蒙版均核查后，用原 source_03、同提示词、同路由、同参数，只换补齐的 mask 生成 1 张。如果需要修改生成提示词，则不能再把该张称为 mask 单变量验证，应另明确实验变量。

上一轮错误输出只作比较证据，不作为编辑底图；不把已经缺失烟囱的候选当正确产品保存。正确同源旧请求可作历史基线，但旧时点模型状态/随机性不可控，改善只能证明本张结果，不能估计稳定成功率。

逐项核对烟囱、屋顶、护栏、入口、床腿、板条、颜色纹理及原来已修好的标签关系。若保护区正确但烟囱仍被删除，归入执行保真问题，不再回头修改候选排序。

## 5. 范围、预算与交付边界

- 当前交付：方案文档 1 份；生产文件新增/删除/修改均 0；付费请求 0；没有操作原作业、旧候选、审批或预算。
- 后续实验：网关 A/B 共 2 张；同一上游直连对照按必要性至多加 2 张；白床验证 1 张。总计上限 5 张，不默认把上限用满。普通三商品重跑不在本方案内。
- 远端实验串行，预估实际调用与检查 10–20 分钟；服务方取证时间不包含在内。白床局部规划/SAM/检查另约 10–20 分钟，取决于现有资源。
- 价格从可核实的现有计费资料确定；未核实价格不编造金额。执行前明确总金额和白床规划调用额度，原三张验证额度已耗尽，本方案不视为新增付费授权。
- 新未知回执封存，不在该实验自动重发；出现转发已证实错误时停止后续归因请求，先修责任点。不会因此新增全项目生产闸门。
- 生产最小改动预期以 `planning_feedback.py` 的证据投影为主，相关行为测试合并更新；`api_registry.py` 只纠正能力注释的过度承诺。不把 smoke 升级成每次生图前的额外付费环节。
- 实验记录放隔离目录，复用现有传输和回执能力；按需要保存脱敏非图像元数据，不另建生产日志控制器，不保留或输出密钥/Base64。
- 不修改 SAM 权重、不提高覆盖率硬门槛、不增加 QA 模型、不切换成抠图合成、不默默换 provider。

**执行顺序：原请求边界取证 → 可观测的互补蒙版对照 → 按证据修网关或定位执行端 → 白床现有规划/分区精准修正与离线验收 → 白床单张实图。白床离线修正可与远端取证并行推进。**
