## 三、新增回归：应优先处理

### N01 · P1：新增图片头校验出现不可处置的恢复死路

**已复现。** 合成 250 字节截断 JPEG，经真实 images.edit → worker → 回执路径，新的 `Image.open()` 抛 `OSError: Truncated File Read`。HTTP 包已保存，但解码尚未返回，`.bin` 没有保存，回执停在 `submitted`。

连续两次 `materialize_response()` 都失败；由于该错误没有归为 `ImageOutputRejected`，不会进入 `output_rejected`。现有 `approve_one_resend` 又因存在 body SHA 拒绝处置，要求先恢复一个本地无法恢复的结果。

**这是本次新增 header 校验触发路径的回归。** 同输入执行整改前 decoder 和 save_response 会返回 250 字节、留下 `.bin` 并记 `received`；不把所有历史解码问题都归为本次引入。

最小修复：在现有校验和回执职责中正确区分永久坏数据、资源不足和可重试下载错误。截断/畸形图像头进入已有拒绝处置状态，保留有限原始证据并允许已有显式授权入口处理；内存不足保留本地恢复语义。**不新增恢复阶段，不把坏图自动当未知请求重发。**

定位：[图片头检查](D:/Amazon_pics/amazon_listing_factory/core/image_provider_transport.py:52)、[恢复异常分类](D:/Amazon_pics/amazon_listing_factory/core/image_response.py:319)、[现有处置拒绝](D:/Amazon_pics/amazon_listing_factory/core/image_response.py:215)。

### N02 · P2：分块读取中断会丢掉已收到的前缀

**已复现。** 当前 bounded reader 累积 chunks；后续 `IncompleteRead` 只携带最后一段 partial。外层保存该 partial，没有拼上已经收到的 chunks。

同一个离线 worker 收到 42 字节，`.partial` 只保留 21 字节；执行整改前同一 edit 函数会保存全部 42 字节。确认影响是付费响应与诊断证据丢失；**没有实证说明这个缺陷本身额外提交了请求或造成新重复计费。**

最小修复：在当前有界 reader 内保留累计已收到数据，异常向原 transport observer 交付完整且仍受上限约束的 partial；不另造读取或恢复控制器。

定位：[有界读取](D:/Amazon_pics/amazon_listing_factory/core/image_provider_transport.py:36)、[中断保存](D:/Amazon_pics/amazon_listing_factory/core/image_provider_transport.py:243)。

## 五、明确仍存在的旧代码缺陷

### S01 · P1：白底产品靠近边缘会被像素分支直接误杀

两张合成图的外部背景全白，四角白、产品完整未裁切，分别展示 1 件及 2 件产品。整改前和当前均自动 fail，独立观察调用次数均为 0。

原因：负像素信号仍直接写 `main_background=fail`，`_evaluate()` 看见 local fail 就跳过观察。该统计不知道边缘非白像素是商品还是环境，不能据此确认外部背景非白。

最小修复：让正、负边缘信号都保留为诊断信息；沿已有独立观察判定产品之外的背景。无需另增模型调用阶段或降低真实白底要求。正式 QA 虽不在当前生图试验范围，此缺陷在后续 QA 可达。

定位：[负信号 fail](D:/Amazon_pics/amazon_listing_factory/core/image_qa.py:230)、[跳过观察](D:/Amazon_pics/amazon_listing_factory/core/image_qa.py:158)。

### S02 · P2：RGB PNG 的 tRNS 透明色遗漏

RGBA、LA、P 透明已有处理，RGB PNG 带透明色键仍未处理。合成的“白底、透明黑矩形”实际上可见内容全白，却通过原生非纯色检查；normalize/超分丢失透明色键，透明区域变实体黑块。

整改前已有同类遗漏；当前 F4 仍未收口。尚未发现真实 provider 返回这种格式的证据。

最小修复：现有可见 RGB 归一化职责统一处理 `image.info['transparency']`，RGB PNG 直通只适用于无透明信息的图；覆盖真实可见像素判断和已有提交入口，不新增格式兼容层。

定位：[可见像素](D:/Amazon_pics/amazon_listing_factory/core/imagegen_artifacts.py:50)、[RGB PNG 直通](D:/Amazon_pics/amazon_listing_factory/core/imagegen_artifacts.py:65)。

## 六、新变更影响及判断边界

1. **“审核策略变化仍可复用旧规划草稿”的承诺不成立。** Kit policy 从 v92 到 v93；`_read_previous()` 先做当前 policy 验证，旧行被丢弃，不能到达 `_local_evidence_repair()`。旧审核 trace 也不具备新 trace_schema。按当前代码，更新后的这类旧规划需要重新 planner，增加 Gemini 调用；这是失效影响，不是本轮确认的错误放行。应明确是否确需 kit 层重规划，不能借新增兼容 reader 或搬旧审批绕过失效规则。
2. 新背景语义分支对“有明确位置、置信度 .99 的 room 反证，但 coverage=partial”返回 inconclusive。没有自动通过实证；如果 coverage 表示完整背景覆盖，局部明确房间已足以否定白底，当前拒绝条件偏强。应澄清该字段语义，再在同一判定里修正，不能把它混称为已经发生的发布误放。
3. 12 个启用生图路由仍通过同一个 SubRouter 网关。换 provider 名称不等于独立网关对照；真实模型身份和服务端 mask 转发仍不能由本机回执直接证明。
4. SAM 主模块、worker 及部分 fixture 仍未进入 Git 跟踪。当前工作区可运行，但若只提交 tracked diff，会遗漏运行依赖；本轮没有执行提交或推送。
