# 冻结测试针对性整改方案

日期：2026-10-10。依据：2026-10-09 四 ASIN、八变体冻结及其独立复审。今天重新核对 100 个冻结文件 SHA，当前代码/配置没有变化。

状态：**方案，尚未实施。** 本文将已证实的程序/合同缺陷与仍需实证的生成执行问题分开；没有新生图、模型调用或生产修改。

## 一、整改目标与责任

本轮 73 个任务、50 张候选、23 个未完成合同。白床生成 0 张，蓝药柜仅 1 张。需要同时处理四条责任链：

1. **源观察与规划**：错误材料锚点、未经证明的机械结构、目标与演示不一致。
2. **审查与 SAM 纠正**：错误点被当木面补选，正确木面漏选却被要求移点。
3. **确认调度与协议**：新合同漏计/漏审、部件名和候选 ID 混淆。
4. **生成执行**：正确单柜合同与蒙版送出后仍输出双柜；两株数量正确但位置/尺度不符。

修改沿现有观察→规划→区域/审查→提示编译→生图职责完成。验收评估**可见结构、材料、连接、目标实例和必要演示**，接受合理的分割边缘近似，不增加像素覆盖率门槛或品类特例。

## 二、确定缺陷：具体改法与验收

### R01 · 先修确认集合、排序和剩余审核槽

**暴露问题**：白床 repair 后第 3/4 次审核都看前五项，后四个新合同未审。蓝柜还有一次审核额度，却因八项修复无法完整确认而提前结束诊断。

修改 `core/visual_design_kit.py` 的现有循环：

- `confirmation_roles()` 纳入所有合法、具备实际输入的待确认 binding。新合同的 `design_review={}` 不能作为排除理由；没有 region 但需要物理画面审查的角色同样计入。
- 以 **binding key + 当前 mask content key** 统计实际审核尝试，不以“这个 role 曾经看过”替代。提交前记录身份，成功、timeout、协议失败都算实际尝试；没有实际请求不计。
- 优先审核当前输入尚未获得审查的角色，再处理已尝试的 retry；保持稳定次序，避免同一前批连续占满五个位置。已 ready 且当前绑定仍有效的角色保持既有复用方式。
- 修订容量不足时，保留原循环里仍可执行的只读诊断/确认槽；typed brief 错误仍等待原 repair，不能通过重审代替修改。尾槽不产生没有后续确认容量的新 mask。
- 修复准入、SAM 纠正准入、实际审核排序使用同一合法待确认集合；当前请求占用的额度须先扣除，再计算后续确认容量。

**删除**：依赖非空 `design_review` 的漏计条件、role 级“看过”排序、修复容量不足就结束全部可审请求的提前退出。

**验收**：固定白床反馈下，第四批先包含此前未审的 `func_02/03/04/size`；固定蓝柜反馈下，最后一个槽可诊断 scene/scene_02，但不制造无法确认的全量修复。review 4、repair 2、每 role SAM 局部纠正最多 1 的现有预算保持不变。

这能消除调度浪费，不能保证九个内容有缺陷的角色在四次审核内全部通过。剩余内容错误须由 R03–R05 降低。

### R02 · 明确候选确认字段，物理替换旧协议

**暴露问题**：四条响应把 `headboard`、`interior_shelving` 等 part 名填入 `component_ids`，而程序实际要求的是候选哈希。一个 part 可对应多个候选，不能猜转换。

在现有 `bind_region_review()` 边界统一使用：

```text
object_id：请求供应的实例 ID
candidate_ids：选择现有候选，仅允许可编辑的区域审查使用
confirmed_candidate_ids：确认当前 support 内的具体部件候选
```

`confirmed_candidate_ids` 必须精确来自本次供应的可确认 candidate 集合，并满足当前 owner、part、像素 support 约束。模型不回显 input/content 哈希，程序继续绑定这些值。

同步替换外部示例、解析、canonical 消费、apply 和当前协议测试；删除旧 `component_ids` 返回格式。空确认数组只表示没有额外确认某个部件，不代表整图自动通过。陌生 ID、part 名、跨实例候选和不可确认候选仍明确拒绝。

**验收**：合法供应候选绑定通过；本轮四个错误返回不再被引导产生；旧字段、跨实例和同名多候选不被兼容接受。必须真实复验模型是否选对候选，不能只用离线合法 JSON 宣称模型问题已消失。

### R03 · 用源点归属驱动修复动作，替换错误归责协议

**暴露问题**：原木床条纹床品点被当成护栏漏保，SAM 新增 59,324 像素保护床品；棕药柜正确圆角柜板点因为漏保被派去修改坐标。

当前提示已经要求看原图中心、区分错点和漏选。继续重复这句话不足以修复，需改变现有同一次审核的证据表达与动作合同。

**诊断页替换**：

- 现有源图/局部/覆盖格显示同一 `child / role / source_id / object_id / part_id / P或N / 坐标`。
- 明确区分“规划声明的 query/owner”与“绿色表示当前几何保护区”。先展示未覆盖的原图中心和邻接实体，再对照 mask；保留结构上下文。
- 同坐标重复点共享裁片，列齐各自 whole/part 身份。优先让实际冲突点进入现有诊断页，保持附件预算；不把未展示/无法辨认的点当作已经确认。
- role 页眉来自本次审核 binding；共享 region 不能烧入第一个 role 后给其他 role 复用。沿现有图片渲染和请求绑定替换页面，不写回产品事实或 mask。

**同一次 finding 的点裁决替换**：模型返回当前源中心归属、是否匹配声明部件及简短可见材料证据；程序在现有解析器中根据不可变点图和现有 coverage 生成原动作。点缺陷不再同时由模型自由填写一个相反的责任字段。

| 原图点中心的判断 | mask 状况 | 对应原动作 |
| --- | --- | --- |
| 床品、清洁布、道具，或属于另一部件 | 命中或未命中 | 修该点所属 intent；不补进保护区 |
| 属于本部件的可见材料 | 未命中 | 修当前 mask；保留正确坐标 |
| 属于本部件的可见材料 | 已命中 | 此点无缺口；继续检查其他必要结构 |
| 负点实际在应保留产品上 | 任意 | 修原负点；不删除产品 |
| 材料/边界仍不清楚 | 任意 | 保留现有待审状态，不自动填充或移点 |

query/crop/实例错误、整块漏选仍用现有关系裁决。程序负责路由与绑定，源材质判断仍由现有视觉审查完成；不能从颜色、SAM hit 或描述文字猜材料。近边界采用已有采样容差，不新增精细分割闸门。

**验收**：原木床床品点、白床缝内床品、蓝柜清洁布均派 intent；棕柜真实圆角木面未保派 mask；银旋钮属于柜体但不属于镜玻璃 part 的判断不能互相替代。初审一次列出同图已发现的问题，避免只修相框、保留其他错点。

### R04 · 真正漏选的结构与必要安装演示，在原 region 中补齐

**暴露问题**：床头板/棕色屋顶/烟囱、板条示意、侧栏等有真实缺口；白玫瑰说明写保地插，实际地插没有被保护。棕药柜安装件被不充分地判成 non-product。

沿现有 targets/parts/query/crop 和原一次 SAM 纠正：

- 规划把目标要求可见的结构和连接明确为当前对象的 parts；不同材料的屋顶、凹槽木板仍属于同一个床架实例。
- 一张图确需展示的安装件/连接细节，按源图里的物理部件表达；“圆形 callout”是版面，不能代替金属件、螺钉或塑料锚的物理 query。
- 区分必要安装支撑、销售配件和是否随售。是否随售未知不自动推出“应删除安装演示”；观察与目标存在矛盾时沿原事实审查处理。
- 在已有局部 batch 内合并当前已确认的必要缺口；只使用有证据的区域和连接，不因某个 miss 扩大到整片床品或背景。

**验收**：床头/屋顶等主要可见结构不再大片遗漏，床品缝仍可编辑；安装演示保留真实对象与安装关系。最终判断结合实际输出：合理边缘漏保而成图保真可接受，整体选中但结构改变仍失败。

本项不换 INT8 权重。现有证据未隔离量化、锚点、query/crop 和分割能力，不能将全部问题归因 INT8。

### R05 · 源事实不猜机制，目标与必要演示保持一致

**暴露问题**：白玫瑰源观察先断言“螺纹旋入底盘”，文案绑定后 GPT 画出具体螺纹；目标承诺装配/整形/擦拭，输出只剩两项。

在现有源观察与 planning review 中替换原说明：

- 记录可见穿盘、转动和接触关系；源图不能证明的具体螺纹位置、孔型、连接机制保持未知，并从肯定事实和文案中删除。
- 使用现有 feature_id 区分可独立绑定的装配、整形、擦拭动作，仍归同一个 tree 实例；无需新增 schema 或功能识别模型。
- 同一次事实审查发现不充分具体化时沿原 `correct_evidence`，再由原 repair 同步修改 goal/state/copy。不能在错误句后追加“不要改结构”。
- 同一次计划审查核对本图承诺的动作是否都有证据和演示。独立事实不必全部变成文案，但目标已经承诺的动作必须兑现；也可以明确缩小目标，不能留下“三动作目标、两动作合同”。

**验收**：证据不足时不批准具体螺纹位置；也不宣称实物完全没有螺纹。目标保留擦拭时，生成图展示真实擦拭关系，布仍是可编辑演示道具。允许重排功能版面，不机械保留原三个圆圈。

### R06 · 同品多实例的选中/排除和位置关系，编译成清晰动作

**暴露问题**：Begonia source_07 有三株，mask 选 front+left，输出两株却改变位置/尺度；未选 back 没有具名进入排除合同。白玫瑰 func 的 side-by-side 与原位置/比例约束存在解释张力。

修改现有 `image_reference_context.py` 和 `image_prompt_compiler.py` 的投影/表达：

- 在整件 main/scene 的现有范围内，从当前源观察的**独立主实例**与已选 targets 得到未选的同品实例 ID，投影具名排除；辅助细节、状态重复图和 included accessory 不计为另一个主实例。
- 保留当前 source crop 作为身份窗口，用自然的编辑动作表达“保留哪件、移除哪件、露出后延续哪些非产品环境”。坐标不是裁切或重建命令。
- 直接动作放在现有图像任务合同前部，保真约束和环境设计随后；替换原冗长重复说明，避免新增多个相反指令。
- 固定坐标 mask 下，版式重设计作用于文字和非产品区域。规划 state 删除“等高并排/把产品居中重排”等与原位置/比例相反的含义，不以代码替 Gemini 设计布局。

**验收**：Begonia 明确选 front+left、排除 back，实际输出保留选中实例的前后/左右与大小关系；两个 source-visible 实例不被拉成复制式等高对象。

当前提示已有“排除其他副本”和 exactly 2。以上是表达精度修复，**尚未证明具名排除本身就能解决位移**，成图必须另验。

### R07 · 尺寸图贴边：修现有版式，不建立新规则引擎

原木床 size 的 36.5 英寸标注贴右边，数字和物理关联未发现明确错误。沿现有视觉规划的 typography/布局要求为标注留足画布内空间，调整文字/引线，保持尺寸值与端点关系；检查 native 即可确认，不靠超分补救。

此项优先级低于事实、结构与实例错误；不增加字体阈值检查器或独立排版阶段。

## 三、双柜：现已排除什么，下一步怎样验证

### 已知边界

两种浴柜 scene_04 的实际提示都要求左柜/单柜，实际上传 mask 也只保护左柜；右柜检查区域保护像素为 0，native 已双柜。已排除本地实例合同丢失、mask 误包右柜、放大新增右柜。

**网关是否按预期消费 mask，以及模型是否遵从，仍未知。** provider 别名都经过 SubRouter；本地 supports_mask 标记和请求 SHA 不能证明服务端应用行为。

### 针对性处理

1. 从本轮已有 request_id、request_fields、上传 mask/source SHA 核查可取得的服务端接收/转发记录。没有上游证据时保持未知；不把本地正确输入再改坏。
2. 同时准备一个**替换式短编辑合同**：先明确删除右侧整柜、在其原位置延续墙面/地面；左柜保持原位置、可见结构和材质；最后给环境风格。继续使用原 source/mask，避免重写床架/柜体通用保护句。
3. 批准实测后，固定 provider、model、source、mask、size、quality，先给 Natural/White 各提交一次短合同，**2 次起步**，与本轮原合同失败参照。这个跨运行比较只能验证新方案能否满足需求，不能独立证明唯一病因。需要严格配对时，再固定其中一个样本同批比较原/短合同，最多追加 2 次，不自动扩展重复次数。
4. 只有结果支持“合同表达是关键变量”才将这种直接动作写入现有编译器。短合同仍失败时，转向服务端能力证据；不能继续循环追加同义句。
5. 短合同仍失败且服务端证据不足时，可把上述最多追加 2 次的额度用于 masked/unmasked 行为对照，替代严格配对；两个结果有差异或相同都不能单独证明网关丢了 mask。它只属于隔离诊断，不构成生产降级路线。

双柜初始两张及最多两张追加对照，合计最多 4 个逻辑任务，计入第五节的首轮总预算；不是再开一份无限测试额度。已有未知结果处置授权继续有效，重发计入物理提交预算。未知回执按现有回执规则处理，不能当作成图失败或用于质量比较；额度被未知请求耗用时保留对照未完成结论。

预计单线程约 5–15 分钟，遇超时可能更长；实际金额以供应商账单为准，现有本地记录不足以给准确金额。实验代码及产物隔离在 test_runs，生产仍由原控制器执行。

**这部分是验证方案，不是已经证明有效的双柜修复。** 生图模型可能不遵从；没有可靠结果时不宣布保真通过。其他有效角色沿原流程继续，不把这个场景扩成全品类新增前置门。

## 四、避免下一轮再被已有程序缺陷堵住

这些由上次代码复审独立复现，本次正常 PNG 没有触发，不混计为 23 项阻塞的原因。最小修补仍应纳入执行：

| 缺陷 | 修改现有职责 | 验收 |
| --- | --- | --- |
| 截断 JPEG 头抛普通 OSError，回执恢复死路 | 已确认坏编码归入已有 `output_rejected`；磁盘/内存/URL恢复问题保持本地恢复语义 | 截断文件可以明确处置，不自动触发付费重发 |
| IncompleteRead 丢累计前缀 | bounded reader 交付累计且仍受上限约束的 partial | 保留完整已收证据；超限证据不交解码器 |
| RGB PNG tRNS 遗漏 | 现有 visible RGB/normalize 统一处理 alpha/透明信息，透明索引 0 也有效 | 可见全白被正确识别，不经超分变黑块 |
| 白底近边缘商品被负像素信号直接误杀 | 正/负边缘信号均为诊断；沿现有观察判断产品之外背景 | 完整白底近边缘商品不在观察前被误杀 |

正式 QA 配置恢复使用现有 scope/provider；只到生图的验收不以 QA 为前置。本次 50 个 inconclusive 是端点不可用，不需要据此重生成 50 张。

## 五、执行顺序、版本影响和验收范围

### 推荐顺序

1. **先 R01/R02 与坏图回执/partial 修补**：消除确定的确认浪费和恢复死路。
2. **同批 R03–R05**：诊断身份、材料归属→动作、真实必要部件、事实/演示一致性。三者是一条责任链，不能仅替换一行提示词。
3. **R06/R07 与可见透明/白底判定修补**：明确目标动作，处理已知布局与判断错误。
4. **固定样例验收**：先本地行为测试，再少量真实审查/SAM与 native 比对；双柜按上面的隔离对照执行。
5. 具体失败关系通过后，再补白床/蓝柜未验证图位；原始冻结记录保持为证据。

### 版本影响

R02 替换审核返回形状，R03 改点裁决，R05 修观察/规划说明，可能使相应旧审核 trace 或规划草稿失效。**不承诺全部旧草稿免调用复用。** 实施时明确受影响的现有版本和来源；保留预算/回执账本，不通过更换 revision 清额度，也不将旧审批升级为当前审批。

本方案不要求迁移、清理或重写四个旧 job。固定样本可作为隔离诊断证据；旧 kit/审批不作为新生产输入。语义未变且当前来源仍有效的结果，按现有合法读取规则使用，不建第二套兼容 reader。

### 最小验证
