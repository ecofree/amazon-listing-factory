# RealESRGAN 残影根因与最小整改方案

日期：2026-10-13。状态：根因对照与替代权重实测完成，**生产修改尚未实施**。本轮固定此前两份紫树原生图、既有局部和当前模型资产，不扩展 ASIN，不请求新的生图。

## 一、清晰结论

**本例的直接原因，是当前 `realesrgan-x4plus` 已训练权重把成品图近白背景中极弱的灰度波动重建为显著竖向纹理。项目把这组偏纹理恢复的权重无差别用于完整成品图放大，使原本肉眼几乎不可见的波动变成了画面缺陷。**

官方原始 FP32 权重也会复现，因此本例不能再归为“只要修 NCNN、指定正确 GPU 或恢复 FP32 就能解决”。当前模型文件与官方发布包逐字节相同，也排除了本机模型下载损坏。半精度存储及不同计算实现会改变严重程度，但不是这个已知缺陷存在的必要条件。

同一输入、同一网络结构、同一 NCNN 执行链改用官方 `realesrnet-x4plus` 后，两份完整原生图的三处残影检查区均为 **0 / 0 / 0**。这一方向保留神经超分，不靠把 Lanczos 扩大成默认放大策略。

不能把这个结论扩大成“所有 GAN 超分都必然有问题”或“RealESRNet 对所有图片绝对保真”。已证明的是这组权重、这些输入与已知残影的关系。

## 二、因果链与排除证据

```text
真实生图响应：白色说明面板中有约 1～5 级的近白像素波动
  → 当前 RRDB/GAN 权重重建出显著竖向纹理
  → 4× NCNN 中间图已经有残影
  → 再缩到 1600px，残影仍然保留
```

缩小操作并非残影的起点。原生图、归一化和 PNG 解码也没有产生可见竖纹。此前单块、切块、设备、线程及精度对照的结果已复核，不重复无效调参。

### 1. 模型资产并未损坏

从官方发布包 `realesrgan-ncnn-vulkan-20211212-windows.zip` 提取的模型与项目资产一致：

- GAN `.bin`：`713ee713b0353afaa27976f0563a64a5043bd70b9bd8936c2e26e25ebcdbcddf`。
- GAN `.param`：`35330ececcea33b6c397a72548e788d5d53becee4734c50b7fada36e89f10a86`。
- RealESRNet `.param` 与 GAN `.param` **相同**，网络图未换；官方权重不同。
- RealESRNet `.bin`：`26bccfcc82d9e8260c0c6b0dffb34ab297982740882d1f33c6d423f70b562c40`。

来源与 SHA 见 `test_runs/realesrgan_rootcause_20261013/official_bundle_provenance.json`。官方原始 GAN checkpoint 及 RealESRNet checkpoint 的下载来源也已保存，不进入生产模型目录。

### 2. 原始 FP32 权重也产生残影

使用官方 23-block RRDBNet 结构、严格匹配的原始 checkpoint，在既有 256px 局部做 CUDA FP32 对照，关闭 TF32。观察的 4× ROI 对应此前第一处白色面板。

| 对照 | ROI 深色像素数（最小 RGB 通道 <180） | 最小 RGB |
|---|---:|---|
| 官方原始 GAN FP32 权重 | 3163 | 155 / 146 / 140 |
| 当前 NCNN 半精度存储权重，FP32 计算 | 3620 | 153 / 144 / 138 |
| 原始 FP32 权重，仅把已知空白 ROI 置为纯白 | 1 | 188 / 183 / 177 |
| 原始 FP32 权重，诊断副本的近白像素置为纯白 | 0 | 255 / 255 / 255 |
| 当前存储权重，诊断副本的近白像素置为纯白 | 0 | 255 / 255 / 255 |
| 官方 RealESRNet 原始 FP32 权重，未修改输入 | 0 | 255 / 255 / 254 |

这组输入消融证明极弱近白纹理是本例的触发因素；替换官方同架构权重证明可以在**不修改输入**的情况下消除这个已知缺陷。

注意：诊断副本的置白只用于定位因果，不作为生产修复。把 RGB≥250 的区域统一漂白可能破坏白柜、床品、浅木材、高光和文字抗锯齿。

权重对照中的 `mismatched_layers=351` 指当前官方 NCNN 半精度文件不等于 PyTorch `.half()` 的逐元素舍入结果，**不表示 351 层下载错误**。原始 FP32 也复现、当前文件又与官方 NCNN 资产相同，因此无需靠这一差异推断损坏或把 FP16 定为唯一根因。

### 3. 训练目标差异支持这一解释

两者使用相同 RRDBNet 结构。官方训练配置中，RealESRGAN 在像素损失之外加入感知损失及对抗损失；RealESRNet 采用像素重建损失。结合本地对照，当前 GAN 权重对近白纹理的响应不适合本项目已经完成排版的成品图。这是由实验和训练配置共同支持的解释，并非仅凭模型名称推断。

官方配置：[RealESRGAN](https://github.com/xinntao/Real-ESRGAN/blob/master/options/train_realesrgan_x4plus.yml)、[RealESRNet](https://github.com/xinntao/Real-ESRGAN/blob/master/options/train_realesrnet_x4plus.yml)。官方模型目录说明把 RealESRNet 简称为 MSE 模型；其训练 YAML 实际使用 L1Loss，方案采用“像素重建型”表述，避免混淆。

## 三、修复方向的完整图片验证

沿当前 `upscale_for_publication_with_backend` 调用链，仅在隔离进程中替换模型名与模型目录。输入字节不变，GPU、tile、线程、超时、互斥锁、4× 输出及最终缩小均沿用当前实现。

| 输入 | 当前 GAN 的三处残影计数 | 官方 RealESRNet 计数 | RealESRNet 进程耗时 |
|---|---|---|---:|

| 局部修订紫树原生图 | 3113 / 634 / 244 | 0 / 0 / 0 | 11.096 秒 |

两次退出码均为 0，backend 真实记录为 `realesrnet-x4plus`。两份完整图及局部对照已目视检查：已知竖纹消失，文字、圆框、操作示意、地钉和树体保留，未见新的同类竖纹。

## 四、最小、精准的实施方案

### 推荐：在现有超分环节替换默认权重

将当前成品放大使用的 `realesrgan-x4plus` 权重，替换为同项目官方 `realesrnet-x4plus`。继续使用现有 NCNN exe 和既有提交链。

这确实是默认模型权重策略的变更：保留 RealESRGAN 工具链，但实际权重名是 RealESRNet，不能继续把 manifest 标为 `realesrgan-x4plus`。本轮只给出方案，没有擅自改变此前“正常默认 RealESRGAN”的生产配置。

具体范围：

1. **`core/image_upscale.py`**：替换固定模型身份及对应资产检查；沿用当前唯一 NCNN 调用路径。GPU 1 / tile 256 / 线程 1:1:1 / timeout 120 / SAM 排他锁和明确报错规则保持。
2. **`core/candidate_state.py`**：允许读取新 backend 的候选，真实写入 `realesrnet-x4plus`。旧 GAN、旧 Lanczos 及历史异常标签只作为既有候选证据读取，不恢复旧执行路径。
3. **生产模型资产**：在上线切换前，将本轮已核对的官方 Net `.bin/.param` 就地部署并核验 SHA，随后移除被替代 GAN 资产的生产位置；旧模型已在隔离官方发布包中留存用于复核。避免首次生产运行才下载模型或安装新运行时。
4. **既有测试夹具**：替换默认模型名称断言，复用现有尺寸、GPU 锁、无静默降级和候选来源用例；保持默认套件≤100例，不新增第二套测试链。

无需新增品类分类、额外 Gemini、SAM 分割、额外生图、自动漂白、结果检测器或新的审批步骤。也不按 func/size 单独打补丁：白底主图和场景中的浅色区域可能有同类输入，应纠正成品放大的默认权重选择。

Lanczos 仍只用于现有的同尺寸处理、正常缩小，以及明确确认超分伪影后的个别候选恢复。普通小图仍由模型进行真正的 4× 超分。

### 既有候选处理

- 不覆盖、重标或自动重跑旧候选；旧审批不转给新 SHA。
- 紫树已经有干净 candidate2，本次无需再提交 candidate3 来证明这项研究。
- 如果将来要将既有失败候选重处理为 Net 输出，应在现有 publication reprocess 权限和来源绑定内支持明确的目标 backend，扩展其现有操作身份与幂等校验；不能直接把当前只绑定 Lanczos 的恢复记录改名。本项仅在明确请求正式候选重处理时实施，当前默认模型修复不依赖它。

## 五、验收与边界

实施后以这两份固定原生响应验证真实默认路径，不允许输入置白或 `artifact_fallback=True`。两图的三处残影区域应均为 0，backend 为 Net，文字和主体目视合格；再运行最小定向用例和一次≤60秒的默认生产套件。

权重更换可能降低 GAN 式锐化和细节重建强度，这正是保真取向的取舍；须在下一次既有冻结测试中检查细字、木纹、叶片和金属边缘，不能把两份紫树结果推断为全部产品验收。此次是两个真实完整输出的已知缺陷验证，不是新的通用画质保证。
