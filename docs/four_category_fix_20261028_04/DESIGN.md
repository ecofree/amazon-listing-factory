# 第四轮：显式文字规格尺寸合同

基线：`63fd0667690c009362f6a9e7c44615a5fec838ebf97a6ebb057eeb029ffcaae1`。
仅代码与隔离测试；不改原作业/回执/图片/额度，不发付费请求。

## 核心边界

- 默认仍是图上测量，不在缺证据/失败后自动 fallback。
- 新路径仅供 size 角色，必须显式授权到 child + 精确 role + 现有来源图 + 已有事实字段。
- 初版仅支持当前 ProductFamily 中可由同 child 原始属性验证的明确正标量长度；标题、Size 标签、无轴元组、包装尺寸、冲突/未确认字段不能自动升级成产品高度。范围、近似值或额外部件条件若当前事实口径不能完整表达，拒绝授权，不删除限定词后印成精确值。
- 对象/轴/标签来自类目声明，数值/单位/限定条件来自现有事实权威及原始属性；授权只选择可用事实，不创造新事实。
- 产品图仍为同 child 原图编辑。文字规格是 text-only，不能伪造图上 measurement_id 或校准端点/箭头。
- 规划器选择 measurement_ids；程序核验来源；原 QA 检查数值/单位/限定条件、不得冒充图上测量；不新增裁判或自动重生。

## 执行设计

1. 把现有 measurement_authority 移至同一个 `measurement_sources` owner，加入来源区分；原实现和旧 import 同步删除，不留转发兼容层。
2. 授权事件记录在现有 job 输入中，带原文件/事实指纹和决定 ID。默认预览，应用需当前提案指纹；撤销仍是显式事件，不碰费用 journal。
3. 授权后的来源元数据投影到现有 product_claims，不向观察对象塞假测量。普通事实不变；未选声明不会影响其它角色的内容身份。
4. 缺失的 size 覆盖锚点只可通过显式授权绑定已有同 child 可用图；不重分类原图，不重编号/删角色，实际编辑底图仍由原规划器选择。
5. 图像与声明用不同 ID namespace。一个 size 合同只选一种来源，不混合来源冒充完整测量。
6. 提示词、execution_profile、候选身份、原 QA 都消费同一个 typed measurement_authority。
7. 当前事实、原属性、授权或字段含义变化时声明失效；旧候选不能依靠旧权限复活。原回执恢复和图片后处理仍各归其原 owner。

## 失败测试 / 验收

- 无图上测量且无授权：size 明确 blocked，不产生伪测量。
- 预览不写入；错误 SHA/事实/child/包装来源/标题猜测拒绝。
- 明确授权后从真实初始规划→任务→提示词形成 text-only size，使用同 child 原图和声明量，不要求一个并不存在的测量附件。
- 提示词不声称来自图上端点，数字只由 measurement_authority 生成。初版对额外限定条件采用拒绝而非丢弃，不声称已经支持所有文字规格表达。
- QA 的 dimension_accuracy 必须引用声明证据；仅引用照片不能给声明尺寸 pass；声明 JSON 字节也在前后核验范围内。
- 撤销/改值后，size 不再当前；其它角色保持，旧图和未知回执不动。
- 同一默认测试集合 ≤100，最终 ≤60 秒。

本轮不会声称 7 张独立尺寸图或 116 个独立候选已经回接；实际旧请求/原始证据是否充分，仍需后续明确的原作业提案。
