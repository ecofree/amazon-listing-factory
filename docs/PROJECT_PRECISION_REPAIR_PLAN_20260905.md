## 一、修复目标

本次修复不是重建工厂，而是使当前生产链路的事实、编辑范围、设计、执行与交付相互一致。

最终应达到：

1. 一个 child 的临时故障不阻断无依赖关系的其他 child，已完成候选不重复付费生成。
2. 标题、五点、描述、item highlights 的硬事实与当前 child 一致，不用泛化关键词证明数值正确。
3. 源图提供产品与功能证据，非售卖道具和房间不继续主导新设计；size/func 不被偷偷转成重新设计商品的任务。
4. 同一 child 的全部图片使用同一套适用的配色及图形令牌；不同 child 可以不同，不建立 family 级固定色板。
5. 现有 provider 和机器资源被合理使用，但不为填满并发而牺牲 child 一致性或引起内存崩溃。
6. 请求到草稿模板的运行可以自然到达草稿出口；正式模板仍遵守现有审核、图片地址和事实条件。
7. 代码完成、本地验证、实图质量、模板完整性分别有证据，不再用一项通过替代其他项。

**不作不现实的保证：**修复可以消除已确认的软件错误和不必要阻断，但不能保证外部模型永不重绘、接口永不故障。区域编辑能力没有实证之前，不能把“零重绘”列为已经实现的能力。

## 二、不可改变的实施原则

| 范围 | 保持不变 |
|---|---|
| 主流程 | 不新增 stage、controller、QA 流程、候选流程、后台守护调度器或 feature flag |
| 运行行为 | 同一职责只保留一个可达实现；替换时删除旧分支、旧字段读取、旧测试，不保留旧新两套 |
| QA | 只处理硬事实及发布条件，不新增审美自动失败门槛；不把所有 OCR 不确定性升级为失败 |
| 主图策略 | 床架继续 lifestyle；浴室柜、药品柜、仿真树继续现有 white_background 策略 |
| 业务默认值 | safeplus、China、quantity=200、库存可售，以及品牌、制造商、履约、GTIN 等按用户此前要求执行 |
| 配色 | 动态规则与参考参数，不恢复固定色板；生产时不联网选色 |
| Provider | lz_token_gpt_image_2 保持停用；物理上游冗余明确延期，不强行接入新 provider |
| 放大 | 不擅自删除或恢复另一套 Real-ESRGAN 行为；基础图不超过既定 1024 边长要求，放大单独执行 |
| 历史任务 | 不扫描、迁移、重放、删除历史 jobs；旧产物仅在获准的对照测试中作为证据 |
| 验证 | 定向测试优先；默认生产套件不超过 100 项、60 秒，不跑历史全量发现套件；付费测试先明确边界 |

“不造成新阻塞”具体指：不增加与当前目标无关的全局前置条件；不牺牲真实事实检查换成功状态；局部错误只影响依赖它的输出；资源等待和重试有界，能明确结束并恢复。

## 三、根因与修复责任

这次应按因果关系处理，而不是按图片表象逐条添加 prompt。

| 根因 | 表现 | 应修改的现有责任位置 |
|---|---|---|
| 参考保护只有读取端，缺少真实输入 | protected 文案存在，仍重绘 | 参考准备、ImageTask、接口传输 |
| 观察证据被碎片化和关键词过滤 | 独有卖点消失，事实合同失败 | 当前观察/分类与证据绑定 |
| 程序与 Gemini 重复拥有设计决定 | 规划被覆盖、生成呈模板化 | 当前 child 规划及编译器 |
| 角色分支丢掉适用的 room 令牌 | func 床品、背景继承源图并漂移 | 当前 prompt 投影 |
| 数值/文本检查语义过宽 | 900 lbs 漏检，泛化声明当道具文字 | 当前 copy 校验与 QA |
| 全局完整性与单任务就绪混淆 | 一个失败拖住整个 family | 当前 currentness 与任务形成 |
| 波次等待和分散资源估计 | provider 闲置、内存峰值叠加 | 当前执行循环及 provider admission |
| 执行完成与交付目标混淆 | 待审时不出草稿，空图模板被当完成 | 当前 controller、模板和摘要 |

依赖顺序：**P0 版本/安全边界/参考权威 → P1 流程隔离与效率 → P2 单一语义和设计修复 → P3 全套实图及模板验收。**

P0 中接口区域编辑尚未验证，不应阻断与其无关的 P1 修复。但不能在参考权威尚未明确时宣布 P2 配色或保真验收通过。

### P0-4 参考保护必须先证明可行，再进入生产

对应：F01，涉及 F06、F13。

修改位置：[final_source_intents.py](/D:/Amazon_pics/amazon_listing_factory/core/final_source_intents.py)、[image_tasks.py](/D:/Amazon_pics/amazon_listing_factory/core/image_tasks.py)、[image_reference_context.py](/D:/Amazon_pics/amazon_listing_factory/core/image_reference_context.py)、[image_generation_executor.py](/D:/Amazon_pics/amazon_listing_factory/core/image_generation_executor.py)、现有 transport/registry。

必须先明确三个不同层级：

| 层级 | 能证明什么 | 不能证明什么 |
|---|---|---|
| 声明支持 mask | 配置中有能力标签 | 接口接收、正确执行 |
| 真实请求发送 mask | 参数、尺寸、哈希和请求一致 | 区域正确、商品不重绘 |
| 源图与成品对照 | 指定样本的结构和区域结果 | 所有商品永远零重绘 |

实施前的技术决策：

- 先验证当前 provider 的区域编辑语义，包括透明区域含义、实际参考尺寸、是否保持参考几何关系。不能按“参数名叫 mask”推定为像素硬锁。
- 当前没有可信生产区域生成者，这是尚未解决的实现前提，不以一句“接入分割”掩盖。需要先判断既有观察结果能否提供足够可靠的产品/图形区域证据。
- 普通矩形框、全图 mask、半透明整图 mask 都不能冒充精准保护区；也不能把背景与床品一并锁住，再声称解决配色继承。
- 区域能力验证是有限工程实验，不新增生产 stage，不安装未验证的分割服务，不追加新的付费模型调用链。

生产落地只允许一个最终选择：

1. **证据成立：**在现有参考准备职责内生成可追踪的区域结果，引用到当前任务。参考变换与区域变换必须一致；显式请求区域编辑时不允许静默丢 mask。仅影响具备该职责要求的任务，不为普通参考编辑突然制造一个缺失字段全局错误。
2. **证据不成立：**不发布“已实现硬保护”的修复；删除无生产者的假接线和能力声明，保留现有诚实的参考编辑能力及人工事实复核。F01 的结构保真缺口保持未关闭，不把它记为成功。其他独立修复照常推进。

这不是保留两个生产模式：它是实施前选择一个可证明的结果；不增加 feature flag 或兼容旧新路径。

size 的保护对象应是商品结构与测量关系，不是把旧字体、旧箭头颜色也永久锁死。商品、背景、床品、尺寸文字/线条须明确不同编辑权限，否则“防重绘”和“统一设计”会互相冲突。

验收：普通新任务完整经过参考准备到真实请求；区域不是测试手填；实际结构、部件数量、支撑关系、尺寸端点正确；无依据的区域保护不进入生产。

## 五、P1：修复现有流程的隔离、出口与效率

### P1-1 currentness 只验证当前权威，不强求无关 child 全部成功

对应：F03。

修改位置：`asset_manager.py`、`image_prompt_compiler.py`、`image_tasks.py`、`image_generation.py`、`release_manifest.py`。

将现有判断拆清职责但不增加第二套校验器：

- 清单层：范围、URL、schema、版本和每条任务记录必须完整且匹配当前输入；失败也必须是一条有原因的记录。
- 任务层：只核实该任务依赖的源图及规划是否有效。
- 交付层：required 图片未齐全时不能成为完整正式交付，但已经就绪的 sibling 可以继续生成并进入草稿。

删除：将任意 retryable 下载直接解释成整个分支过时的判断；保留哈希不符、外部路径、缺少任务记录等真实输入错误。

验收：A 下载失败/B 完整，B 完成而 A 明确未完成；B 文件被替换时正确阻止 B；A resume 不重做 B；required/optional 全量任务数不被缩减。

### P1-2 草稿模板出口与正式交付分开

对应：F04、F19。

修改位置：`production.py`、`template_engine.py`，复用现有 template_mode。

| 请求目标 | QA 待审核时的行为 | 最终表述 |
|---|---|---|
| 生成/QA | 正常停在当前目标，保留待审状态 | 图片生成完成，仍待审核 |
| 草稿模板 | 继续已有 template stage；图片地址为空时明确记录 | 草稿已生成，未正式交付 |
| 正式模板 | 维持当前审核、发布图片、字段和 family 范围要求 | 未满足则不能宣称正式完成 |

删除：不区分模板目标的 QA 后提前返回。不要新增 auto-approve；不要把本地图片路径伪装成公网图片地址；不要引用源商品图片替代生成图。

验收：单次草稿调用可到模板；失败 child 不丢行、不伪造图片；父子关系正确；正式图片未批准时仍不能形成正式模板。

### P1-3 现有执行循环改为完成即补位

对应：F15。

修改位置：`image_generation.py`、`image_provider_routing.py`，不建立新的 batch runner。

调度规则：

1. 使用当前执行循环维护待执行和正在执行任务，复用当前候选/任务状态作为唯一持久化权威。
2. 某个 future 完成即提交候选并释放该 lane，立即从有资格任务中补位，不等整波最慢请求。
3. 同一 child 默认一个在途角色，保持 provider 主偏好。优先并行不同 child，而非把一个 child 的角色任意拆给三个 provider。
4. 按剩余角色数和既有耗时记录估计 child 工作量；没有历史数据时按剩余张数，不为评分额外请求模型。
5. provider 故障时沿现有备用逻辑处理；将实际选择写入现有事件/结果，剩余未执行角色参考当前健康信息。已成功图绝不为“统一 provider”自动重画。
6. 队列等待不记作付费模型失败；所有 provider 暂不可用时有界等待后以现有 retryable 结束。

| 可用 provider | 预期行为 |
|---|---|
| 0 | 不发送请求；保留成果，有界等待/可恢复退出 |
| 1 | 正常串行推进，不因未达到三路而拒绝启动 |
| 2 | 资源允许时至少可同时推进两个独立 child |
| 3 | 资源允许时三个独立 child；空闲槽及时补位 |
| 后续更多 | 同一 registry/容量逻辑自然处理，不写死 provider 数量 |

删除：每一波创建线程池并等待全部结束的屏障、按 provider 个数写死的特殊分支、仅为填槽而重复提交任务的行为。

验收：模拟一快一慢，快槽在慢请求结束前已经接到下一任务；每个 logical task 同时最多一个请求；只有一个 child 时不虚报三路并发。

### P1-4 在现有 admission 中统一内存与容量约束

对应：F16。

修改位置：`image_generation.py`、`image_provider_common.py`；复用现有跨进程租约，不加资源 controller。

- 峰值估计包含参考与返回图像展开、编码缓冲以及当前放大后端峰值；不只用压缩文件大小乘常数。
- 准入必须考虑其他 factory 进程尚未实际分配的已承诺内存，避免多个 job 同时把同一块可用内存都算作自己的。
- 资源预留只在实际可启动请求时取得。持有预留等待 provider 槽时必须有界；避免锁顺序反转和空占资源。
- 租约只记录占用者和资源承诺，不记录第二份 pending/running/completed 任务状态。候选完成和 job 状态仍由当前权威管理。
- 释放覆盖成功、异常和子进程退出；不得删除仍有活进程持有的租约文件。
- 不将已计入操作系统使用量的内存重复扣减。先用离线压力测量校准，再采用保守上限，不能用一个未经验证的公式承诺不会 OOM。
- 正在执行的正常请求不因可用内存暂降而被随意终止；限制后续准入。确实无法启动一张时明确资源等待/可恢复退出，不强行至少启动一个。
- 非法并发值不能转为不限流；复用当前静态配置校验提前指出具体参数。合法的一路配置始终可用。

删除：配置解析失败返回不限流的分支、无条件最少放行一个任务的低内存行为，以及重复的独立容量估计。

验收：低/中/高可用内存三档离线场景；两个 job 同时争取最后容量不会双重放行；进程退出资源释放；无异常常驻后台进程。

### P1-5 时间预算沿现有调用链传递

对应：F17。

修改位置：`production.py`、`final_source_intents.py`、`vision_gemini_client.py`、`copy_writer.py`、现有 transport。

- 作业预算采用单调时钟，嵌套请求使用剩余预算，不能每次切 provider/修复文案重新拿一份完整总预算。
- 现有分类 SHA 去重和 2-3 路并发保留；只对确实缺证据的源图进入视觉恢复，缓存有效则复用。
- HTTP、队列等待、子进程等各自可中止点遵守剩余时间；不能以 Python future timeout 代替实际终止底层请求。
- 已发送请求若结果不确定，记录不确定状态与请求标识，不立即盲目再发以致双重收费。
- 截止前不再派新任务；既有超时回收逻辑负责处理在途请求，已提交候选保持成功。
- 现有进度记录区分排队、模型、重试、OCR、本地处理，不再只报一个总运行时间。

验收：全部 provider 慢响应时能有界结束；切换 provider 不刷新总预算；中断后 resume 只恢复未完成项，不重复生成已提交图。

## 六、P2：重构唯一语义，提升产品质量

### P2-1 保留源图真实卖点，消除碎片 OCR 的上游损失

对应：F11。

修改位置：`final_source_intents.py`、当前视觉参考与 func story 编译职责。

- 利用现有 OCR 位置/行结构把相邻词恢复为有依据的短语，不将整张图所有碎片随意拼接成一句话。
- 关键词可辅助判断，不能再作为唯一“允许成为证据”的门槛。保留可信原文、源图位置和来源绑定。
- 事实机制、营销形容、品牌道具文字分开；不把“质量很好”当机制，也不因含 storage 就授权整个段落。
- FuncStory 从可信证据选择标题/标签，保留独有机制；不强制每图塞满两个标签，不生成全局通用套话。
- 有效部件数量、嵌入边框、防滑等不能在原文被丢弃后从常识猜回。

删除：唯一白名单式卖点许可、无用途的短句截断及证据丢失后的泛化填充。

验收：Embedded Design/Keep Mattress in Place/No Box Spring Needed 在确有源图证据时被保留；相似词不授权未经观察的结构；图文绑定能定位到源图。

### P2-2 测量只有一个展示表达，原始 OCR 只作证据

对应：F12、F06。

修改位置：`image_tasks.py`、`image_prompt_compiler.py`，沿现有 measurement_authority。

- 相同“对象+轴+值+单位”的记录规范化为一个展示文本，但源图中不同对象的相同数值不能合并掉。
- `64 in` 与 `64"` 可以是同一个测量的不同表达；无单位的 `37.5` 不自动变成新增尺寸。
- 无法明确关联时保留源图测量关系，不猜标签、单位或另一条箭头。
- load capacity 与长度区分，承重图标可以换风格，事实对应关系不变。
- 原始 OCR、规范化记录、渲染展示不再三个入口同时发号施令。

删除：measurement_groups 与任意 text_artifacts 并集后全部强制渲染、同一 callout 重复发出指令的逻辑。

验收：规范表达只出现一次；部件不同的同值尺寸仍完整；箭头端点和对应对象保留；文字间距修正不改变事实。

### P2-3 修正色彩计算，再修正按表面投影

对应：F07、F08、F09。

修改位置：`palette_registry.py`、`palette_registry.yaml`、`visual_design_kit.py`、`image_prompt_compiler.py`。

计算修复：

- 明确 HEX/HSL 生成的值为编码 sRGB，在现有 colour-science 转换中正确解码后计算 Lab/色差。
- 当前生产依赖中固定实际使用的色差定义与可追踪版本，不用非等价近似距离悄悄替代同一评分。依赖准备属于发布前环境核对，不在每个任务中联网安装。
- 数学修复后重新检查已有阈值尺度，不能沿用错误尺度再宣称质量分数提高；分数仍只用于选择/诊断，不成为成品 QA 硬门槛。
- 所有候选不理想时不无限生成色板或阻断任务；保留有限选择与诊断，不能伪报“已满足审美”。

投影规则：

| 图中实际表面 | 使用的唯一权威 |
|---|---|
| 售卖商品颜色/材质 | 当前 child 产品事实与有效参考，不由装饰色板重配 |
| 可编辑墙壁/地面 | child room 对应令牌 |
| 可编辑床品/靠枕 | child textile 主次令牌 |
| 少量装饰 | child accent，不能扩成大面积床单 |
| 字体/icon | child graphic ink 与现有字形规则 |
| 箭头/引导线 | child graphic line，允许与文字有明度层次 |
| 白底类目主图外部背景 | 现有纯白策略，不引入 room 令牌 |

func 只要有可编辑床品/房间，就投影适用令牌；无房间的 size 不强塞房间。不得通过长篇追加限制实现，替换当前 role 二选一投影逻辑。

市场品质改善只在算法与投影修好后，用已获认可的真实样本修订本地参考参数；不恢复白色固定蓝灰、原木固定陶土的路线表，不宣称在线网站已进入生产设计。

验收：同一 child 各角色的适用令牌一致，源商品不被重染；不同 child 可有不同组合；数值色差标准样本正确；实图配色统一性需要整套检查。

### P2-4 程序、Gemini、编译器只各管一件事

对应：F10、F13、F21。

保留职责：

- 程序：事实、引用关系、适用场景边界、child 色彩/图形令牌、流程状态。
- Gemini：在证据内选择场景与布局意图、光线表现、具体机制的表达，不重新设计商品或重复选配色。
- 编译器：按已有合同投影，不另写第二份产品规则、不覆盖规划中的合法设计意图。

修改顺序：先列出实际字段消费者，再调整响应 schema，删除必然被程序覆盖的请求字段及覆盖代码；把 edit_contract 的 preserve/replace/forbid 与最终生图语义统一成一个入口。

Prompt 保留当前基本段落即可：ROLE 表达该角色任务；REFERENCE 表达唯一参考及商品/测量边界；STYLE 表达适用令牌与规划；TEXT 表达批准文字；OUTPUT 表达输出格式。

不设新的目标字数硬门槛。记录修改前后字符数和内容差异，但只有语义真重复才删；事实、图标色、测量关系和反重构边界不能为缩短数字被删除。

类目泛化在当前事实/规划中处理：确有儿童/过渡床证据才固定儿童房；成人床不套用 Montessori 描述；信息不足时使用保守的卧室用途，不从一个颜色或 Queen 尺寸单独推断受众。床架 main=lifestyle 不变。

验收：修改一个权威字段能在最终请求看到预期唯一变化；无消费的旧字段清零；场景光线不被后续泛化文本覆盖；四类目正常编译。

### P2-5 文字判定精确化，不增加 QA 阶段

对应：F05、F06、F14。

修改位置：`image_prompt_compiler.py`、`image_qa.py`、现有文字契约。

| 内容 | 处理原则 |
|---|---|
| 已批准的信息图文案 | 按现有契约展示与检查 |
| 普通无品牌书名/道具字样 | 不因“有文字”一律失败；不得变成商品声明 |
| 明确第三方品牌/商标 | 依现有品牌限制处理，源图存在不构成授权 |
| 明确新增且无事实依据的承重等声明 | 属于事实问题，不能全部归为普通道具警告 |
| 低置信或无法定位的 OCR | 保留已有人工复核，不猜品牌、不制造硬失败 |
| size 数字未识别完整 | 不等于数值错误，不能自动拒绝 |
| 明确可证实的数值矛盾 | 与对象/单位绑定后依现有事实 gate 处理 |

只使用现有可得 OCR/事实信息，不能为了判断书脊品牌再加入一轮视觉模型。若现有信息无法区分，诚实保持人工复核边界。

删除：把所有 func 合同外文字视为道具的分支、与允许普通书名相冲突的泛化无文字限制、源图文字存在即可视作授权的表述。

验收：同一组样本同时覆盖普通书名、品牌、新增商品声明与模糊字样，分别验证误拦和漏检；不恢复历史“一处 OCR 不确定整套失败”。

## 七、P3：模板收敛与冻结实图验收

### P3-1 模板条件判定只修明确缺口

对应：F19、F04、F02。

修改位置：`template_field_plan.py`、`template_engine.py`，不修改主图政策和默认业务值。

- 将现有条件项分为已适用、已不适用、无法确定，减少能明确排除的重复告警。
- 条件风险计数不等于必须填字段数，不将 221/673/262 等展开计数转成整批硬阻断。
- 已填值遵守模板合法值；未知值不从旧示例抄取、不填猜测值。
- 在现有 listing_data/plan/audit 中明确可用图片、缺图、父子行、highlights、事实来源和实际模板模式。
- 保持现有工作簿包写入与完整性检查，字段修改不破坏其他 XML/宏/校验数据。

验收：父子关系、五点、描述、highlights、单位和默认值正确；新文件可读取；计划与单元格一致；草稿缺图明确标记，正式模板只含有效批准图片地址。

### P3-2 零付费验证先覆盖行为，不按模块堆测试

最低行为矩阵：

| 场景 | 预期 |
|---|---|
| 活任务执行 repair | 不改活任务状态 |
| A 源图临时失败、B 齐全 | B 继续，A 明确未完成 |
| 已成功候选 resume | 不重新调用生图 |
| 草稿目标且待审核 | 到模板，保留待审核 |
| 事实 300/文案 900 lbs | 对应 copy 字段失败 |
| 等价单位与不同部件同值 | 分别正确等价/保留 |
| 具体机制短语与普通道具文字 | 证据不丢、不互相冒充 |
| func 含床品，size 无房间 | 仅投影各自适用令牌 |
| 0/1/2/3/N provider 可用 | 有界推进，不依赖固定三家 |
| 一快一慢 provider | 快槽及时补位 |
| 跨 job 争抢容量/内存 | 不超卖，不遗留活租约 |
| 预算耗尽/结果未知 | 不无限重试，不伪造成功 |
| 模板条件未知 | 草稿可出，正式限制仍有效 |

以上优先扩展/合并现有测试，不表示每行必须新建一个测试文件。阶段编辑时只跑定向测试，整个实施批次收尾跑一次默认生产套件；后续代码若再改，其此前通过结论失效，需对应重验。

### P3-3 实图测试边界和成本控制

本报告不授权实际调用。实施时必须在用户批准的测试范围内执行。

**接口区域能力小实验：**先选一家现有 provider，两个有代表性的 size/func 输入，各做有/无有效区域请求对照，最多 4 次调用，失败不自动扩大到所有 provider。此实验只验证接口行为，不能代替普通生产区域生成者的验收。其他 provider 的能力验证单独计入事先批准的预算。

**同 child 全角色 A/B：**先核定该 child 当前应生成 N 张，修改前 N 张、修改后 N 张，基础预算为 2N，不固定为四张。两组使用相同输入、事实、provider、分辨率、scope；只变更被验证的代码版本。模型随机性需注明，不把一个偶然较好样本当统计结论。

- 两个代码版本仅存于隔离测试工作区，生产不保留旧新开关。不得用旧缓存替代新版本结果。
- 不并行修改提示词、provider、事实输入和上采样配置，避免无法归因。
- 四类目扩展在代表性 child 通过后开展；先给出每个 child 角色清单，总调用上限为实际清单之和。
- 重试只针对明确失败且获准的任务；预算计入底层 transport 重试，不只统计候选文件数。
- 超出调用/费用/时间上限、出现系统性结构错误或内存错误时停止扩大测试，保留已完成产物与原因。
- 不因审计仍有美学建议而自动再生一轮，也不为 provider 一致性重画已通过图片。

**冻结约束：**测试期间代码配置指纹不变；需要改代码时结束当前测试并说明具体缺陷，再开始获准的新验证。不同版本结果不得混合声称整套通过。

### P3-4 逐图验收清单

验收材料按 child 拼接，并保留角色源图对照，全部角色参与。

1. 商品：数量、颜色、支撑/连接、门/抽屉/层板、轮子、杆件和可见状态是否一致；不凭“看起来像”通过。
2. size：数值、单位、对象、箭头端点与测量方向；不只检查 OCR 字符出现。
3. func：具体机制是否保留，有无虚构结构/新卖点，局部图是否仍来自同一商品。
4. 场景：房间用途符合已知商品，不强制所有床为儿童房；布局和道具与源图有实质区别但不改变商品。
5. 配色：同一 child 的床品主次色、墙、地面、accent 与 graphic 语义稳定；光照变化不能掩盖换色。
6. 图形：同语义文字/icon 使用一致墨色，箭头/线可有受控层次；无不需要的阴影底板，字号和间距可读。
7. 道具：普通无品牌文字允许；疑似品牌标记具体位置，不把所有单字母都判违规。
8. 明亮感：产品暗部仍有细节，白色不过曝，材质不过度平滑；属于人工品质验收，不新增自动亮度门槛。
9. 模板：全角色生成数量与 scope 一致，草稿/正式状态明确，地址和事实字段与当前产物绑定。

尺寸或结构错误不能因“配色变好”被忽略；配色评分提高也不能弥补商品变形。

## 九、删除旧逻辑与变更范围

实施前后都要搜索确认以下旧行为是否仍可达：

- 显式区域任务静默丢 mask 的降级。
- 容量关键词存在即可授权任意承重值。
- 全局 retryable 下载阻断无关 child。
- 不区分草稿目标的 QA 提前退出。
- 整波等待完毕才再次补任务。
- 非法并发配置解释成不限流。
- job 活跃时可直接 repair 状态。
- func/size 无条件丢 room 令牌。
- 对 Gemini 合法设计字段的无条件覆盖。
- edit_contract 维护一套、最终 prompt 另写一套。
- 原始 OCR 清单全部强制渲染及卖点唯一关键词许可。
- 所有合同外 func 字样一律当普通道具。
- 与当前文字政策冲突的跨角色无文字限制。

清理范围仅为被替换的生产行为及其测试，不等于清空历史文档/任务/资产。保留审计证据，但不得让旧缓存和 schema 在新生产入口重新生效。

## 十、完成标准与实施后报告

每个实施批次交付以下简表，不以“已优化”代替证据：

| 项目 | 必须报告 |
|---|---|
| 变更 | 新增/删除/修改的生产文件，实际增删行数 |
| 清理 | 物理删除的旧运行路径、schema 读取和测试 |
| 本地验证 | 精确定向测试及默认生产套件结果、数量、时间 |
| 实图验证 | scope、代码指纹、provider、全部角色、实际请求数、重试数、逐图结论 |
| 交付 | 草稿或正式模板，不混称；图片地址和缺失项 |
| 未完成 | 能力未验证、接口结果不确定、人工待核实项 |

三个完成层级：
