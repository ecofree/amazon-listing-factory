## 为什么会发生

### 1. 产品保留合同存在，但主要是文字约束

`core/image_tasks.py:_edit_contract` 已要求保留 geometry、proportions、finish、parts，也列出了床头、围栏、支撑和床腿。因此不能说系统完全没有保真要求。

但同一合同把首图定义为 transport edit base，把附件作为同子体证据；实际请求没有受保护的主体区域。图像编辑接口本身不等于产品像素被锁住。当前正常生图依赖模型在整幅重新构图时自行保持这些关系，实际输出未做到。

### 2. 规划有展示目标，却没有把主体编辑边界落实到执行

scene_02 的 visual_goal 强调 spacious、accessible side entryway，presentation 要展示 open side passage。模型输出放大了入口。该目标与失真方向相符，是可能的诱因；无法仅凭提示词证明模型内部因果。

更确定的缺口是：同子体参考虽齐全，“固定入口”只解决了它不是活动门的问题，没有可靠约束入口终点、侧围栏覆盖比例和构件排列。目标机位、环境和展示重点的自由度仍会影响产品几何。

func_02 已经规划为 detail_only，编译提示词也要求不要重建整件，但输出依然画出大范围整床。因此该图还存在明确的模型执行偏离，不能把全部责任推给规划。

### 3. 版式重设计与产品几何保留没有被有效隔开

`core/image_prompt_compiler.py` 的正常生成要求设计 framing、lighting、information layout，并拼入整个目标状态、设计方向和附件证据；产品约束则主要来自通用 preserve 列表和可见事实。

文字禁止改变几何已经存在，继续堆叠“不得重绘”无法补上执行边界。size 只用一张完整裸床原图仍然重绘，也说明单纯减少附件或换模型不是充分修复。

### 4. 审查通过与真实主体保真被混为一谈

现有生成前审查能检查来源和目标合同，不能证明未来输出逐个构件一致。本轮按用户要求只到生图，未运行自动 QA；人工复核又偏重前次问题是否消失，遗漏了整体主体对照。

不应把根因归结为“少跑 QA”。即使下游能拦住错误，也不能替代上游正确保留产品。

## 最小修复方向（本次未执行）

1. **在现有规划和编辑合同中明确同一条主体保留边界。** 保留源图支持的产品视角、轮廓、部件相对位置和连接；创意变化作用于环境、非售卖道具、文字和版式。替换宽泛或可能被误读的条款，避免不断追加重复提示词。
2. **整床／裸床／局部状态优先使用匹配该状态的现有源图。** 本样例 func 已有裸床 source_01，应评估把它作为裸床展示的主编辑依据；局部图保持已有细节范围，避免要求模型重新建立整床。没有证据支持的新视角不由模型臆造。
3. **核验现有 protected_mask 能力是否能保护产品。** 代码已经能传遮罩，但这轮没有使用；配置宣称支持不能当作真实保真证明。先用一张代表图验证，不直接给全部角色加遮罩：床品在围栏间、文字压在产品上等情况需要准确编辑区域。遮罩本身也不能被许诺为所有后端都严格保持像素的保证。
4. **在现有逐图复核中检查同一产品，而非只查上次错误。** 对照床头内外比例、围栏分段和局部根数、固定入口端点、梁柱连接；排除遮挡和透视误差。无需新增生产阶段或第二套事实控制器。

这是共用生图链的保真缺口，柜门、磁吸扣、安装面、金属床支撑件也可能受到影响；本报告不把尚未逐图复查的其他类目认定为全部重绘或全部失真。
