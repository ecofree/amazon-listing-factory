# 五项恢复缺口：本轮代码设计

仅代码和隔离测试；不读写原 job，不发付费请求，不初始化账本。基线是本轮工作树快照，不是 Git HEAD。

1. 原始证据路径：在原 Apify source owner 提供唯一 job/source/apify_raw/<marketplace> 定位；fetch/currentness/声明来源共用。raw_dir 只保留原始描述，不做多路径搜索或兼容回退。删除 measurement owner 的 raw_dir 重复拼接。
2. 轴向属性：声明尺寸仍由 measurement_sources 唯一 owner 提供。复用 dimension_axes，仅接纳类目显式列出的直接属性；保存原字段/完整原值/轴向投影/单位/SHA。拒绝包装、范围、无轴、冲突及跨子体。当前事实必须一致；旧规范化事实缺单位时，只能由相同原组合属性和明确轴向证明，不猜单位。
3. 声明式示意：授权请求明确选择 text_only 或 declared_diagram。后者仍原图编辑，只允许声明量的示意线，不是照片测量/校准。原始属性 JSON 不是图片附件；QA、人审、交付仍用同一 statement 证据和撤销规则。保持原 text_only 默认，不静默升级旧授权。
4. 原产物承接：候选 owner 内增加显式当前合同采用操作。前置必须是原规划 owner 认可的当前 ready task/prompt，不能由历史文件存在制造接受；原独立授权、prompt/native/来源和 source-ID 映射须精确核验。采用是当前操作者明确决定，不宣称两份不同提示词字面等价；新绑定引用原不可变 manifest，原付费记录不改。尚无当前合同的返回/拒绝明确缺口。旧 staging 只允许由原任务 owner 显式重新投影为当前合同，绝不恢复旧 object_kinds 权限读取分支。
5. 观察归属：在现有观察 owner 加明确 preview/apply 归属核证，按指定 cache 和全部原应用级请求的 SHA、原附件 ID/SHA、原子体事实确定唯一子体。记录在原 job 输入内，不改旧 cache/请求/计数。不明归属仍全局阻塞，已证明归属只限制真正所属子体；该子体未知继续阻塞，不得到新 allowance。

入口与结构保护：默认只读；apply 绑定提案 SHA、唯一决定和原因；job lock 下重新核证；重复同决定幂等。跨子体、证据漂移、错误 SHA、未知原请求、未批准当前合同一律拒绝。原图像请求/规划消费/回执不重置。新证据只证明本次发生的本地行为，不补写历史处理或 QA。

测试先 RED：factory-relative raw_dir、明确 DWH、示意合同、不同提示词/来源 ID 的显式采用及旧 staging 重投影、无 child 观察 cache 的跨子体保护。负例覆盖不明轴向/限定词、字段冲突、越界、旧决定复用、文件漂移、同子体未知保护、无当前角色接受不得采用。测试并入现有用例，不提高 100/60 默认准入限制。冻结后运行默认套件及临时副本回退反例。

替换/删除：raw_dir 拼接；声明处理里 text_only 的无条件假设（不是删除 text_only）；候选仅靠字符串相同的唯一承接限制扩展为有明确决定且当前接受的类型；观察无归属记录的无条件跨子体阻塞改成核证过作用域后判断。不能增加第二事实/规划/候选/QA 控制器，也不能删除真正未知的保护。
