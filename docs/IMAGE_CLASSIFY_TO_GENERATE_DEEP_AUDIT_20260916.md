## 11. F08/F10：重试、坐标与诊断

### 11.1 重试不能修复程序自己的合同矛盾

`visual_semantics.py:206-214` 的 response_validator 调用逐行校验后直接 True。逐行校验在 `:304-307` 把异常转成 failed 行，不抛出整批错误。

因此传输 trace 可以 success、validation_errors 为空，而业务观察全部失败。保留逐行结果本身是正确设计，不应恢复“一行失败重做全组”。需要把 transport success 与 semantic row result 明确区分。

本轮第二次输入仍保留同一双层事实表，repair_findings 只有概括错误，缺少字段路径和实际/期望 ID，重读 9 张也不能纠正接口本身。

### 11.2 轻微坐标偏差不等于事实错误

第一次响应中，一条尺寸端点 y=0.234，小于该视图 top=0.236，在 1500 像素图上相差约 3 像素；其余事实无需改变。第二次模型已修正，但引用 ID 错误仍让整条失败。

修正应只针对模型定位误差的局部表达：依据原像素确认并修正包围范围，或使用原有定向观察纠错；不能默认放过真正裁断部件的框，也不改测量值。不得引入另一个裁图控制器或无界循环。

### 11.3 摘要会掩盖故障位置

- `production.py:1099` 的 provider_request_count 只统计生图传输事件，0 不代表观察/规划没有付费请求。
- `production.py:1122` 的 source scope 统计依赖尚未形成的 ImageTask，classify 失败时把源图统计一起变成 unavailable，产生次生误导。

这些诊断问题不是图像 provider 坏了，更不能通过继续重生图消除。
