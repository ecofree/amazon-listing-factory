三、具体修改项目

P0-1：规划必须看到本次各槽位可用的编辑底图

根因：planning_reference_inputs 当前只选一个完整外观参考；规划又被要求不为未见图画坐标，并被允许据此输出 not_applicable。结果是正常场景和功能图失去保护。

  1. 依据现有 task_specs / output_inventory，为本次输出槽位收集实际可用的首张编辑底图，并保留子体外观锚点；按内容哈希去重，一次附在已有 child 规划请求中。
  2. 同一份附件清单同时驱动实际上传、attachment_number → source_id 映射、初次规划提示及已有修订提示。不得只增加图片而保留“唯一附件 1”的旧说明。
  3. 首张编辑底图从规划可见的候选中选择；其它原图仍可作必要事实附件。若现有审查发现底图需换成其它已核实原图，在现有修订中提供该图并重建区域，不能沿用旧坐标。
  4. 删除“未见首图即可不使用蒙版”的许可。少了输入就是规划输入需要修正，不能伪装成产品不适用。

验收：所有实际首图都能对应当前附件／修订附件；当前 54 项“未见图”理由消失。8 个子体继续各自产生完整输出槽位。附件数量增加后的内存与请求时长在现有资源控制下测量，不提高资源门槛或请求轮数。

P0-2：把产品归属和目标可见性分开判断

根因：当前将部分产品部件当成可编辑背景，又同时要求不得遮挡任何源图可见部件。这使裸床加床垫、半透明柜门换环境等正常编辑目标产生冲突。

判断统一规则现有字段如何表达
它是不是产品？所有销售主体、确认随售配件及可见构件都是产品，包括异色、浅色、细杆、背板、凹槽和内侧木面。颜色不同不等于摆件。沿用观察的 objects / sale_membership / product_features；不把真实承托板写入非产品列表。
目标中哪些仍要可见？由当前目标状态决定。允许床垫正常覆盖承托板；不允许扩大织物遮挡来掩盖侧梁、床腿或连接关系的改变。在现有 presentation.state 明确必要遮挡；region_intent.targets / parts 对应目标仍需保留的可见构件。
哪些需要像素区域保护？目标仍可见的实际产品构件。裸架 size／结构 func 包括承托板和中撑；有床垫的场景需保护仍外露的床头、侧梁、床尾、床腿等。当前部件候选选择；正点放在应保留的构件内部，不能以计划正常覆盖的区域作必须保留的锚点。
哪些环境可以变化？非随售床品、摆件、房间、产品孔隙中的背景。随售床垫、沙发面料、座椅软包则仍属于产品，不能因为是织物就放开。editable_objects 只列非产品；布艺和玻璃等类别依据销售归属与材料事实判断。

优先选择已有床品、已有正确门状态、没有覆盖产品的源图文案、且符合目标机位的原图，减少不必要的状态变化。尺寸事实仍来自已核实的尺寸原图；尺寸原图可以作为辅助事实附件，首张底图不必为了尺寸文字而选污染更重的图。

验收：胡桃床 main 的承托板即使正常被床垫覆盖，也不能被归类为非产品；该床 size 要检查承托板、中撑与边梁完整性。审查结论必须说明实际范围，不能把“外露框架覆盖”写成“所有源图可见结构均覆盖”。

P0-3：实例限定、部件补漏与局部结果归属使用同一份合同

根因：整件语义候选和命中正点仅能提供候选，不能证明每根构件完整，也不能证明同类背景对象已排除。后续审查把少量锚点命中或泛泛的“完整”描述当成充分证据。

  1. 规划从当前原图与已有产品证据自动列出当前角度可见且目标中必须保留的主要部件。按形状和物理归属拆分，不能只按主色选择木面。
  2. 同类多实例按现有 object_id、局部范围和正负点限定。观察将多件作为一套时，仍保留该套身份，在已有 parts 中限定各可见成员；不得为了分割虚构新的销售对象。
  3. 整件语义分割提供候选；异色、细杆、内侧或凹槽等薄弱部件使用当前部件语义查询。只有已有审查发现具体漏选或误选，才用一次局部交互批次纠错。
  4. 审查在原图、候选与覆盖图之间确认：主要部件、目标成员数量、孔隙、非销售摆件、局部范围与父对象。先选正确候选，再处理具体漏选；不按最大面积或最高分自动批准。
  5. 沿用已确认构件不可被删除、局部删除需反例负点、范围不得越过父对象等现有约束。确认的支持集合必须来自应保留部件，不能先把背景污染的整件候选全部确认后再无法修正。
  6. 继续使用现有目标／部件／局部修正数量上限及一次纠错预算。修正后在原有审查预算内复核；不为每个部件增加 Gemini 调用。

验收：主要木面或中撑漏选必须能在已有审查中定位；白床 size 的栏杆间白底／尺寸线误选要减少；药柜补漏继续有效，且不删除既有确认构件。双树一套应覆盖两株；单树不能因批次中其它变体是两株而被扩成两株。

P0-4：固定底图坐标的蒙版必须与目标布局一致

根因：蒙版使用原图坐标，现有指令却仍允许裁切、等比移动或缩放产品，有时又要求源图构件位置不变。两种要求不能同时交给模型。

  • 使用该固定蒙版的任务，保留首图的产品位置、机位、尺度与透视；改变背景、床品和产品以外的图文布局。删除该路径中冲突的移动、缩放和重新构图指令。
  • func／size 继续参考图编辑：尺寸值与端点、门覆盖范围、安装面、连接关系仍由现有事实与角色合同约束。
  • 局部特写可以保护其实际可见部件，现成多插图底图可保护对应位置的真实产品片段。若目标要求重排产品插图、换角度或改变安装状态，先在现有规划中改用支持该目标的原图或调整目标；不能靠关闭蒙版放行冲突。
  • 传输对底图和蒙版进行相同几何缩放；继续使用原生 mask 参数和底图第一附件绑定。蒙版哈希、输入变换与请求回执沿用现有记录。

验收：尺寸图不会一边提交原坐标保护区，一边要求产品任意缩放重排；已有本地哈希链继续一致。模型实际是否移动或重绘，必须看生成图，不能由请求字段正确替代。

P1-1：含玻璃／镜面的任务按部件处理

根因：二值蒙版无法同时把玻璃纹理像素锁住、又把同一像素中的旧背景彻底放开。整块不透明保护会保留旧环境；整张不保护则丢失柜框等可保护构件。

  • 保留柜框、门边、把手、支撑、可见内部实体等能够独立识别的构件；孔隙中的环境保持可编辑。
  • 在现有 special_surfaces 中标明真实的透光／反射表面；从现有材料证据编译简洁要求，保留材质、边界和连接，允许其所呈现环境随目标场景变化。
  • 这类表面不作“像素不变”的保证。已有审查分别检查不透明构件保护区与透明／反射材料合同；最终实图检查门板纹理、数量、厚度观感、框体和反射关系。
  • 删除“含透明／反射表面就整张 not_applicable”的笼统许可。真正不能提供有意义保护区的任务，须由现有审查给出具体证据和边界，继续遵守原有参考编辑合同。

验收：玻璃柜门不会把旧摆件一起固化，且框体保护仍有效。若实际模型仍改坏材料，应报告为该编辑能力尚未通过，不能把一个漂亮的新房间当作通过证据。

P1-2：删掉冲突提示词，保留有作用的事实关系

提示词保留四类内容：实际首图／辅助事实来源、目标仍可见产品保留规则、可编辑环境或图文目标、已核实的尺寸与功能关系。产品的实例和部件清单用于规划与区域审查；生成提示不重复粘贴整套观察目录。

  • 用一条通用产品保留规则替换重复的床架专用长清单；产品身份、颜色、材料事实继续由当前事实合同提供。
  • 删除“整个床形轮廓不可改”与“床品可换”、“所有源图可见部分都不可被遮挡”与“裸床加床垫”等冲突表述。
  • 保留门与开放格的覆盖关系、固定入口、安装面、尺寸端点、配件使用条件和准确数量。这些语义不能从蒙版推导。
  • 直接规定原生蒙版保护的是哪些目标可见区域，环境修改不得改变仍可见的产品结构、色泽、纹理、材料和连接关系；不再为每个 ASIN 增加永久特例。

验收：同一任务不存在两条互相冲突的保留要求；文字、尺寸和关系事实没有随提示词压缩丢失。保持通用规则并允许规划自动适配当前产品，不承诺识别模型能取代所有事实约束。

最后保存的 kit 版本计数为 8 次规划＋19 次审查＋5 次修订。应重点减少额外审查和修订的触发原因，同时避免测试过程中反复改代码和合同、再重新跑整批。统计依据为已有请求轨迹及版本预算，调用明细可逐项核对。

24／16 是输入完整、结果一次有效、没有网络重试时的设计基线，不是已验证承诺，也不是新增的全局硬门槛。正确性所需的复核保留，异常追加要说明原因，不能靠漏审或少生成图片达成数字。

5.2 先分清哪些变化需要重新调用哪个环节

现有程序已经有成功源图保留、child 缓存、_local_evidence_repair 和按绑定 key 批量审查。此次扩展这些路径，不建立另一套缓存或控制器。保持最终 kit／任务的综合当前性；复用旧规划草稿不等于复用已经失效的蒙版或批准。

实际变化需要执行可继续复用的内容
没有语义变化；恢复任务或继续生图现有文件、哈希与当前性校验。有效观察、完整规划、区域、批准与候选；不增加 Gemini 调用。
一个原图的文字、尺寸或对象归属证据被纠正该源图的现有观察修订；重新编译和检查依赖它的角色，必要时合并一次局部规划修订。仍有效的其它源图观察与无关角色。若更正改变全局销售数量、子体身份等，则扩展到确实依赖它们的全部角色。
SAM worker、权重或区域算法变化，产品事实与视觉目标未变重新计算受影响区域，并批量审查新的区域证据。原视觉方向与角色草稿；不因区域执行版本变化自动重新调用 child 规划。
一个区域需要补漏或去除误选现有本地 SAM 纠错；一个批量请求复核本次变化的区域与相关操作。其它区域与无关批准；不重复观察原图或重做视觉规划。
仅审查协议／判断规则变化依新规则复核受影响批准；批准政策发生变化时不能沿用旧批准。仍符合当前目标与输入的视觉草稿、有效区域；不自动要求重新设计。
一个角色的文案或图文表达变化该角色及对应事实、设计操作的审查；如果改动共享设计，再扩展到真正依赖的角色。其它角色与无需改变的区域。
子体身份、材料、销售数量、关键结构、共享视觉目标或规划核心规则变化重做受影响子体规划及相关审查；这是必要重算。能够证明仍有效的其它子体。不能为了少调用把旧事实或旧合同冒充当前结果。
生图超时、重发或切换生图模型现有 generation 重试／回执规则。未变的观察、规划、区域和批准；不联动 Gemini 重规划。

具体代码目标：当前 _kit_input_revision 将 region_runtime、CLAIM_REVIEW_POLICY 与规划输入放在一起；而 _local_evidence_repair 又要求新规划提示与旧提示不同。应在这个现有局部修订路径中支持“规划决策未变，但区域／批准需刷新”，按现有源图、事实、目标和政策证据判断，重新生成当前完整 kit。不能简单删除综合指纹中的版本绑定，使旧蒙版或旧审查悄悄变成当前。

绑定审查继续使用当前 design_binding_request / claim_key。核实哪些事实确实影响该角色：产品身份、数量、材料、结构仍是必要依赖；不相关的陈述不应无条件使所有角色失效。依赖不明确时保留原严格校验，先补证据，再缩小范围，不能猜测复用。

5.3 每次请求处理整批问题，修正导致多轮的内容缺陷

  • 初次 child 规划一次看到该子体所有当前编辑底图，并返回完整角色清单、区域意图与目标状态；输入不足不再触发后续成批修订。
  • 产品事实绑定、构件覆盖、实例归属及必要图文关系在已有同一批审查中处理。按已有内容哈希去重实际附件，并使用候选接触表；不为每张图、每个构件开一个 Gemini 请求。
  • 已有审查发现的区域错误合并成一个本地纠错批次；规划错误合并成一次受影响角色修订。后续审查仅提交实际改变的证据与未解决操作。
  • 不同父对象、不同底图或不同目标保护范围不得为省调用强行合并。近似边缘可以接受；主要构件漏选、删除产品或错实例仍需处理。
  • 保留一次纠错后的必要复核；修复本方案中的源图／目标混淆、遮挡冲突和笼统不适用判断，减少误报引发的来回修改。
  • 所有 Gemini 请求继续沿用现有物理请求预算、失败归属和回执，不新增全局调用硬上限。失败追加按现有失败类型处理，不能通过更换输入版本循环获得重试。

5.4 分区检查、A/B 和完整冻结共享同一份有效规划

第六节第二步只建立一次当前规划与分区。第三步 A/B 复用它的事实和生成文本，第四步完整冻结继续使用已通过的当前 kit、任务及区域；不同验证步骤不是三次重新执行 classify＋brief 的理由。

带蒙版对照图只有在任务、提示、参考、模型及候选登记都与正式槽位一致时才可复用；否则只作隔离实验依据。无蒙版控制图不导入正式候选，不能把实验分支变成生产回退。完整冻结仍保留全部 73 个槽位。

5.5 调用效率的验收和记录

  1. 正常完整观察＋规划＋首轮审查以 24 次为设计基线；已有有效观察时规划与首轮审查以 16 次为基线。必要修订、复核和网络失败独立列出，禁止只报告成功次数。
  2. 相同完整输入、有效产物的重复恢复，新增 Gemini 请求应为 0；生图重发或换模型在合同未变时亦为 0。
  3. 仅 SAM 实现变化的行为测试应证明重新生成区域及审查、Gemini 视觉规划调用为 0；局部源图修订证明其它有效源图不被重新观察。
  4. 单角色／单区域修改只触发依赖的修订和批准；批准仍绑定新内容，不能以少调用为由接受旧哈希。
  5. 在当前日志中记录初次、输入变化、区域变化、协议变化、语义纠错或网络失败的触发原因，以及实际请求、排队未发送、输入版本、有效复用、token 使用和耗时。统计由现有轨迹汇总，不增加一套预算控制器。
  6. 默认测试套件通过行为断言验证调用范围；实测验证上述基线是否成立。调用数量超出预期先报告责任原因并精准修复，不增加全局“超过数字就全批停止”的门槛。

七、跨品类如何自动适配

复用的是归属与可见性规则，不是床架坐标，也不是每种产品新增一段永久提示词。现有规划模型依据本次原图和销售事实自动输出目标、部件、选区与可编辑对象；SAM 执行区域计算，现有审查纠错。

共性情况自动处理方式
异色／异材质部件按销售主体和物理连接选择；浅色板、金属螺件、深色饰条不因颜色不同而被排除。
孔隙／细杆／凹槽保护构件自身，开放孔隙中的非产品背景；薄弱部件用局部语义及点纠错。
多个销售成员依靠现有销售成员身份、数量、局部位置与负点；一套多个成员不等于随意并入背景同类。
门或机构不同状态选择对应实际原图，状态与连接不靠 SAM 发明；换状态需重新确定底图和保护区。
附属织物／摆件依据随售归属判断。产品自带软包要保留；源图普通床品／摆件可变。
透明／反射材料实体框架分区保护，材料与环境呈现关系进入现有合同并实际验证。

本次真实证据覆盖床架、仿真树、浴室柜、药柜；其它类别仍需代表性图片验证，不能宣称已经通用通过。新类别的销售事实与类目支持仍走现有项目机制，SAM 接入不会自动激活尚不支持的类目。

后续正常批次的用户职责是确定编辑目标与不可变的产品事实、审核最终图；系统负责将这些要求转换为具体区域。若一个新类别反复漏选，定位其现有观察／规划／分区／审查责任，修正通用规则或该类已有事实定义，不让用户逐 ASIN 手工涂蒙版和追加产品限制。

八、最终验收与交付

  1. 输入正确：实际底图全部可追溯，无未见首图的假性不适用；所有槽位保留。
  2. 分区可用：目标需要保留的主要构件与成员完整，明显背景误选受控；边缘近似不单独阻塞。
  3. 合同一致：产品归属、正常遮挡、特殊表面、布局及蒙版坐标互相一致；尺寸、文案和安装事实不丢失。
  4. 真实结果：逐图对比产品外露结构、数量、比例、颜色、纹理和材质，以及预定环境修改；不只看生成图是否漂亮。
  5. 效率可解释：共享现有 worker，复用同底图且合同一致的查询结果；规划、区域和批准按第五节的依赖范围刷新。正常基线、必要追加和异常发送分开统计，不复用失效结果，不承诺尚未测出的提速。
  6. 变更收口：交付新增／删除／修改文件、近似增删行数、物理删除的旧路径及测试、定向与生产测试结果和时长、实图通过／失败／未验证项目。
推荐决策：把输入完整性、保护效果和调用复用放在同一轮最小整改中完成，再按有限对照和完整冻结顺序验证。各验证步骤共享当前有效规划，调用效率和图像质量一起验收。现阶段不能承诺所有新类目自动完全精确，或正确蒙版保证模型绝不重绘；这两项要以实际输出证据判断。
