# 自动产品分区与主体保护：最小实施方案（已批准，隔离验证中）

日期：2026-09-22。用户已批准执行。第一阶段已做自动定位与点位复核，发现床架点位归属错误；精细纠错接口仍待落实，尚未进入生产接入。详见 [执行记录](../test_runs/sam3_auto_correction_20260922/README.md)。本版替换本文件此前“等待远程凭据／优先 fal”等过时建议；历史测试回执和逐图报告保留。

最新约束：用户明确只使用免费 HF，暂不新增服务。已沿用现有 Demo 完成 4 次局部文字纠错请求，补选有改善、排除失败；[本轮实际结果](../test_runs/sam3_auto_correction_20260922/free_text_correction_01/执行结果.md)。下文涉及其它远程资源的条件不作为当前执行动作；不再要求 FAL_KEY。

## 一、推荐决策

采用现有 Gemini 确定商品归属和编辑范围、远程 SAM 3 提取精细区域、原规划审查定位错误、现有 generate 发送 mask 的方式。

**分区准备放在 brief 内、任务指纹冻结之前；保护执行由 generate 负责。先完成精细纠错与真实生图两个开发验证，再实施生产接入。当前免费 Demo 仅用于小样，不先成为所有图片的强制生产依赖。**

不增加用户业务阶段、独立审批入口或逐图手工步骤。会增加内部计算、附件和远程依赖，不能把“不新增流程”理解为没有额外成本。执行按第七节顺序推进，不使用用户已否定的旧床架 skill。

## 二、实证与未解决缺口

| 实测 | 已证明 | 未证明 |
|---|---|---|
| Gemini 三张多边形分区 | 本次粗轮廓不足以保护细构件和孔隙 | 不代表所有视觉定位能力不可用 |
| SAM 3 全图三张 | 细轮廓明显改善，返回 7 个候选 | 最高分不等于完整商品，不能合并全部实例 |
| SAM 3 局部三张 | 床头、花盆各返回 1 个候选且改善；柜体 0 个候选 | 未实现完整纠错；零候选不等于没有产品 |
| 局部坐标和部件词 | 人工视觉定位有修正价值 | 尚未验证 Gemini 自动定位后的闭环 |
| mask 通道与早期生图对照 | 程序可以传 mask，已有输出仍重绘 | 传输支持不能证明像素锁定或产品保真 |

两个实质缺口仍在：**精细纠错接口尚未落实；当前生图线路尚未通过主体保护效果验证。** 不能把它们写成已经完成的接入条件。

## 三、按商品事实确定保护边界

保护当前销售产品可见构件的结构、连接、颜色、纹理和材质；商品归属沿用已有子体事实和源图观察。SAM 不决定配件是否随售，Gemini 不凭生成目标授权不存在的结构。

| 内容 | 处理规则 |
|---|---|
| 床架横梁、栏杆、床腿、屋顶饰条、烟囱、凹槽木面 | 保护，包括深浅不同的材料；不能只按颜色选 |
| 可替换床品、房间、摆件，以及栏杆缝中的这些内容 | 可编辑；不能把床的外接框全部保护 |
| 柜门、把手、铰链、层板、背板、内壁 | 按销售构件保护，暗部不应被当作孔洞 |
| 树枝叶、树干、随售盆体和安装件 | 按事实选取；不能按候选分数判断销售范围 |
| 镜面、透明件 | 边界和结构需保留；反射/透视内容按编辑目标处理，另需样本验证 |
| 移除物件或变更机位后新显露的结构 | 需要其它源图证据；蒙版不能补出未经核实的产品 |
| 文字和箭头覆盖产品本体 | 定位冲突，优先由原规划选择对应结构明确的底图；不能为了删字任意开放主体重绘 |

以上是边界示例，不写成三个类目的固定分支。初版编辑保持选定底图的产品机位和可见构造；背景、床品、文案及版式可设计。不能一面保护原坐标，一面要求无依据的换角度、开关门或大幅移动。size/func 继续走参考图编辑。

## 四、现有环节中的具体接法

现有链路：

`build_visual_design_kits → _finish_image_briefs.compile_reviewed → review_planning_bindings → build_image_tasks → build_image_prompts → generate_one`

### 4.1 brief 内准备区域

1. 原规划复用对象归属和 product_sources，指定保护对象/部件、可换内容和必要的位置提示；不要求 Gemini 描精细多边形。
2. 对实际第一底图 product_sources[0] 调用分割。角色 source_id 是证据锚点，不能默认与编辑底图相同。
3. 现有 review_planning_bindings 同时看源图和区域预览，检查漏选、误选和实例范围，复用审查预算、deadline 和失败记录。
4. 合格区域随现有 brief 保存，由 resolve_edit_references 单向投影为第一 edit_base 的 protected_mask，然后冻结任务指纹和提示词。
5. 原编译会在审查前后 checkpoint，需确保未完成区域绑定的角色不会提前变成 ready；其它成功角色继续落盘。

### 4.2 一次纠错同时处理补漏和误选

初次分区后最多一个纠错轮次。轮次内每个实际请求均计数，不把“一个轮次”藏成无限部件请求；小样测量后固定物理请求上限并记入现有尝试记录，续跑不重置。

- 漏选：补回经事实确认的构件，如烟囱、背板、盆身。
- 误选：去除床品、背景和摆件，但保留挡在它们前面的栏杆、柜框等产品。
- 选错实例：核对整件、局部、重复嵌图的身份，不机械选最高分或并集。
- 零候选：记录未识别，不替换成全黑/全白蒙版冒充成功。

修正必须基于真实精细区域或修正后的原始蒙版，更新范围外保持不变。框只定位，不直接填满或扣空矩形，不全局补洞。补选不能替代排除，不能用粗背景区域减掉前景细构件。

当前免费 Demo 的文字接口可返回区域；点击实现只添加正点，返回带点预览，尚不满足可编程精细纠错合同。下一步只验证一个能接收定位信息、返回原始 mask 的远程接口，不建立多供应商自动轮换。若需新账户、付费或自建托管，先落实资源条件，不悄悄增加项目必需依赖。

### 4.3 generate 提交并执行保护范围

复用 `generation_reference_mask_bytes → generate_with_provider_retries → multipart mask`。保护区 alpha=255，可编辑区 alpha=0，绑定实际第一输入图。

- 原图和 mask 使用一致的方向、裁切和缩放映射，同时核验最终传输尺寸和 SHA。
- 重试保持源图、mask 和任务指纹不变；不重复分割。
- supports_mask 仅表示传输支持，删除“可强制像素不变”的错误注释。
- 替换当前引用/构图语义中与保护目标冲突的内容，不叠加提示词。
- 保持现有模型分工；主线路和既有 GPT Image 2 候补分别验证真实保护效果，不能按名称推定一致。

官方说明 GPT Image 的 mask 是编辑引导，可能不精确遵循边界。正确蒙版必须继续由实际输出验证，不能直接称为主体保真通过。

### 4.4 修复与恢复共用同一绑定

- targeted_edit 更换第一底图后，不沿用原图坐标；同一区域模块对当前候选和授权修复范围重新绑定，待修产品部件须保持可编辑。
- 无法形成有效修复区域时保留现有修复失败，不静默取消 mask，也不新增重绘退路。
- 相同源图、相同销售/保护范围与有效处理版本复用一份区域；变体、底图、范围或映射改变时，只重做受影响区域。
- 唯一绑定保存在 brief，沿用任务指纹、回执与 candidate manifest，不加 mask_jobs 或第二套缓存。
- 状态查询、currentness、local_finalize 不调用分割；mask 改变使相关旧审查、任务和候选绑定失效。
- 补齐合同 mask 与实际 original_mask_sha256/mask_sha256 的核对。

## 五、最小生产修改范围（验证后执行）

| 位置 | 变更职责 |
|---|---|
| 新增 core/product_region.py | 唯一区域调用、坐标映射、区域文件及源图绑定；不决定事实、规划或任务状态 |
| visual_design_kit.py / visual_design_kit_compiler.py | 在原 brief 中准备和绑定，扩展必要字段/校验 |
| visual_semantics.py | 原设计审查加入可定位区域问题与责任分流，复用审查预算 |
| image_reference_context.py | 投影 protected_mask，统一第一底图职责 |
| image_generation.py | 候选修复换底图后重绑，恢复不重推理 |
| candidate_state.py / api_registry.py | 实际 mask 回执核对，纠正能力描述 |

image_tasks 与 transport 已有 mask 指纹/传输能力，优先复用，只有验证出缺口才修改。不增加调度器、独立 QA 或第二套事实控制器。删除被替代的冲突提示语和过时能力说明；实验代码不进入生产导入链。

新增生产模块小于 800 行；已有超过 2,000 行的文件不净增长。测试合入已有生产合同测试，删除替代后重复的断言。

## 六、避免新增整批阻塞

1. 隔离验证期间不让 SAM 成为生产新前置条件；实验失败不影响当前生产运行。
2. 接入后失败仅影响该源图/范围涉及的角色；其它 ready 角色继续，不能因一张柜体零候选退出整批。
3. 超时、额度不足沿用原 deadline 有界结束，不等待第二天、不无限轮询、不要求日常逐图手绘。
4. 不以无 mask 生图、复制源图或空白蒙版伪造完成，也不新增无保护降级分支。
5. 同源同范围复用，避免按角色重复分割；生成沿用既有并发，提高并发不能增加每日 GPU 额度。
6. 免费账户当前 5 分钟/日只能支持有限验证，尚不能保证批量吞吐。预估量或稳定性不满足生产时，先落实一个适用的远程资源方案，再切换生产。

不增加整批阻塞不等于外部服务永远可用。若全部目标都依赖失败服务，就无法保证全部出图；不能用错误图片掩盖这一边界。

## 七、执行顺序与明确收口

### A. 精细纠错验证

继续现有三个 ASIN和原图，不重新找产品。核实一个远程接口的输入及原始输出合同，随后每图最多一次有明确目标的纠错。

Gemini 在隔离实验中自动给出实例和错误位置，实际驱动纠错；人工只核查结果，不替 Gemini 填坐标或手修蒙版来声称自动化通过。三张须覆盖补漏、误选排除、暗色平面和细部件孔隙。记录物理请求数、返回文件、耗时和已知费用。

通过要求：关键构件完整、可换物没有明显误保护、实例对应正确，孔隙与边缘可用。不能用置信分、选区面积或平均 IoU 代替部件检查。失败时定位责任，不无限换词测试。

### B. 真实生图验证

仅使用分区达到要求的样本。先三张各做同源图、同目标、同路由的带/不带 mask 对照，最多 6 个计划请求；结果用于有限样本比较，不能估计普遍成功率。

通过后，补 size、func 各一张，核查多面板、旧文字与结构交界；同步安排实际使用的 GPT Image 2 候补验证。新增请求前明确样本、路由和目的，不扩成所有模型×所有图片矩阵。

保留原始输出与最终放大图，逐项检查可见结构、数量/间距、连接、颜色、纹理、材质，以及背景/床品是否真正完成替换。测试止于 generate，随后逐图检查，不自动运行正式 QA。

**正确蒙版下主体仍改变：归入生图执行问题，停止扩大分割和提示词。源像素保留/合成属于不同实现决策，不在本方案内自动切换。**

### C. 证据成立后接入

一次覆盖初次生成、候选修复、结果恢复的绑定，避免首轮有保护、修复丢保护。最小行为检查合并到已有测试：

- 第一底图和 mask 的身份/SHA/尺寸一致，错误绑定不发请求。
- 复用与失效正确，状态读取与恢复不调用模型。
- 一个角色失败不阻塞其它 ready 角色。
- 修复底图变化不能套旧 mask，授权修复区仍可编辑。
- 实际传输 mask 与任务/回执一致。
- 预算跨续跑保留，不因角色修订获得无限额度。

编辑期间定向测试；结束生产套件只跑一次，遵守 ≤100 例、≤60 秒。复用实测样本确认接入未改变有效输入。其它未测视觉类型保持未验证，不能宣布任意产品全面通过。
