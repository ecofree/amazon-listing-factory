# 主体保真：重新归因与受控实验方案

日期：2026-09-26。状态：供用户审核。本轮仅检查现有代码、请求、原始图片并生成离线证据；**新增生图 0，生产修改 0**。

## 一、先纠正此前的验证方法

此前实验提供了真实失败证据，但不足以完成根因判断，主要有四个问题：

1. **B/C 不是对旧流程编辑方式的完整对照。** B 在当前任务上替换部分规则，新床提示词从 3,988 字符增加到 5,117；C 为 5,094，仅比 B 少 23 字符。它仍包含受众、完整产品描述、目标状态、观察摘要、多层权威解释。不能把 C 失败解释为“直接原图编辑提示词也失败”。
2. **没有与五月旧图统一评分。** 五月图只证明主要床架布局能保留，未逐项证明纹理、五金全部不变；前报告又把九月部分微小纹理差异或“尚未核实”当作整体不通过依据。应保留明确结构错误，降低未经充分定位的纹理结论强度。
3. **把同网关模型切换说成了线路对照。** 现有七个生图配置均为 `subrouter.ai/v1/images/edits`。`gpt-image-2` 与 `gpt-image-2.5-sunburst` 的对照只能叫同网关模型配置对照，不能证明独立供应商/网关差异。
4. **事前没有把因果判断和下一步绑定到结果组合。** 发现一个可疑词就再试一次，信息收益有限，也容易不断改变问题定义。新的实验必须先固定假设、对照、检查项和停止条件。

旧 main 按保存脚本、当前保留 style_profile 和 Apimart 包装重建约 3,619 字符，本身也不算极短。因此，**不能将问题简化成“长提示词必然重绘”**。真正要比较的是：文本是否把图片中的产品当作实际编辑对象，还是反复将它描述成要重新呈现的目标。

## 四、可靠的处理方向

### 4.1 产品事实继续由现有事实层管理

销售归属、正确变体、颜色、尺寸、文案仍使用现有权威。修复不能通过丢弃事实验证、照抄错误源文或把别的变体改色来实现。

### 4.2 规划给出可执行的编辑目标

在现有规划中选择与展示状态匹配的底图。房间、床品、图文排版允许改变；已有底图的可见产品结构与连接不能为买家目标重新设计。要展示不同状态，先用已有对应源图；不借一句状态描述让生图模型补造隐蔽构件。

### 4.3 编译器输出一份明确的编辑合同

需要验证的候选改法：产品图负责可见外观与连接，提示词负责“保留什么、允许改什么、改成怎样”，删除没有执行价值的受众和重复产品叙述。保留所有当前设计目标值、事实与文本授权，不引入新的保真控制器。

**本轮已准备两份可读的直接编辑提示词草案，未发送：**

- [新床草案](../test_runs/preservation_diagnosis_20260926/new_bed_direct_edit_draft.txt)，2,719 字符。
- [旧床草案](../test_runs/preservation_diagnosis_20260926/old_bed_direct_edit_draft.txt)，2,708 字符。

两份草案沿用现有提示词分段和合同校验。目标状态、STYLE、TEXT、OUTPUT、产品身份、类目限制和允许修改内容沿用 C；新床的现有 6-inch mattress 状态也未偷偷改掉。删除受众、观察摘要和重复权威解释，以便检验“完整描述合同”与“直接编辑合同”，并不宣称较短文本天然更好。

草案不写“补回第几根栏杆”“删掉 C2 螺钉”等针对失败图的答案。否则测试的会是记住这张错误，不是普通产品保护能力。

## 五、建议执行的实验：先固定一张难例，做 2×2 交叉对照

### 5.1 只回答两个问题

- H1：直接编辑合同是否比当前完整 C 合同更能保持源图产品？
- H2：同网关的模型配置是否显著影响这一效果，或与提示词存在组合效应？

这里的“明显改善”是有限样本的开发证据，不是统计显著性或生产成功率。

### 5.2 首批固定 8 个计划结果

源图固定为 B0DSSKTXXW 的原始 main，选择它是因为已有明确的数量和入口连接反例。**此时不再两原图、多个角色一起铺开。**

| 条件 | 当前完整 C 合同 | 直接编辑合同草案 |
|---|---:|---:|
| cxk / gpt-image-2.5-sunburst | 2 次 | 2 次 |
| cxk / gpt-image-2 | 2 次 | 2 次 |

使用同一 cxk 配置族，尽量固定账号配置与端点；两个模型仍只代表网关报告的配置别名。qc_yc 不在首批掺入，避免同时改变账号配置。

**固定条件：**原图字节与 SHA、单附件顺序、无 mask、房间/床品设计值、目标状态、文案授权、quality high、请求尺寸、原始输出处理。禁止自动切模型、局部修图、压缩重编码或加第三份提示词。两份提示词生成前冻结完整内容与 SHA，生成期间不修改。

**执行顺序：**预先排定两轮四条件，每轮每条件一次；第二轮用相反顺序，固定同线路串行，记录时间。历史 C 仅作参考，不能替代这次新对照组，以降低不同时段与选择样本的影响。

**请求上限：**8 个逻辑结果，首批最多 12 次登记物理提交。未知结果沿用用户已有每任务最多三次重发授权，但还须服从该总上限；达到上限就保存不完整结果并说明，不能为了凑齐成功图越过预算。524/超时不算质量失败，不将重复计费隐藏在 8 张中。

### 5.3 生图前固定同一套检查项

检查对象是可见产品，允许整件产品在画布中平移或等比安排；不要求房间、床品或整张图片像素一致。

| 项目 | 新床明确检查内容 |
|---|---|
| 数量 | 床尾两端粗立柱之间 11 根细栏杆，不混入远侧栏杆 |
| 连接 | 入口立柱在侧梁上端的连接，不增外贴延长段、底部连接片或外露螺钉 |
| 固定开口 | 入口所在侧、横梁连续关系与端点，不变成可开合门 |
| 床头 | 屋顶饰条、烟囱、壁龛边界及相对关系，不将凹槽随意扩大或补造 |
| 外观 | 自然木色与深棕饰条；选定前立柱、床头板两个可见表面，检查是否换成不同材质/纹理形态 |
| 遮挡 | 必须检查的入口连接和床尾不能被新毯子/摆件遮到无法判断 |
| 编辑目标 | 房间、床品和指定摆件有实际改变，不能靠近乎复制源图获得保真 |

每项只有“保留／确认改变／不可判”三种记录。“确认改变”必须给源图与结果局部对照及具体部位；光照明暗、压缩细节或无法定位的纹理差异先记不可判，不直接断言重绘。

不以总分抵消结构错误，不将不可判自动计为通过。只核对上述预先指定的可见部位，不在看完结果后突然加一个此前没有采用的微观标准。五月旧图也按相应的同一原则重新标注，不把“历史成功”作为免检标签。

将输出使用中性编号整理，检查结束后再揭示分组，降低偏向新方案的风险。人工逐图复核属于本次开发实验，不新增生产 QA 阶段。

### 5.4 结果直接对应处理，不继续猜词

| 结果组合 | 支持的判断 | 下一步 |
|---|---|---|
| 直接合同在两配置都重复更好，完整 C 有对应错误 | 主要修复方向在合同组织/信息投射 | 优先修改现有编译与源视图约束；不能宣称某一句或字符数单独有效 |
| 某模型配置在两种提示词都重复更好 | 配置因素更值得优先处理 | 限定到已验证模型配置；不新增规划规则来弥补供应端问题 |
| 只有“直接合同 + 某配置”表现好 | 两因素有组合效应 | 同时保留该已测组合验证；不能挑一个因素宣称唯一根因 |
| 四组都好 | 难例没有复现 | 不宣布任何修复有效，也不据此改生产 |
| 四组都错，或每组两次互相矛盾 | 首批不能获得可靠区分 | 停止扩样与生产替换；整理违约部位，再决定是否需要真正独立供应端或编辑能力验证，不自动接 SAM |

新一轮复测不能“确认根因到一句英文”，但可以将下一步从无边界试词缩小到合同、配置或组合三种责任范围。

## 六、条件性确认与生产落点

首批有清晰差异才追加旧灰床 B0FHD8QQ81：胜出条件 2 张、最相关对照条件 2 张，最多再 4 个逻辑结果、6 次登记物理提交。原图中确实存在的立柱拼接缝不判新增；检查三阶梯子、上下铺/拖床关系及预先指定的可见表面。

因此整套诊断最多 **12 个计划结果／18 次登记提交**，第二批不是默认执行。未获清晰差异就停止在首批，不扩成四 ASIN 全角色冻结。

如果结果支持提示词修复，先在**现有** `image_prompt_compiler.py`、`image_tasks.py`、`image_reference_context.py` 修正实际需要的合同表达；规划/审查中相冲突的源视图自由条款同步替换，沿用现有字段和版本失效机制。删除被替代条款，不保留长/短双控制器，不把实验选择器接进生产。

如果结果主要支持配置因素，则不为凑齐原六文件范围而改规划代码。任何生产变更都需按现有小套件验证；床架 main 的诊断不能自动宣称 size/func、柜体、树全部通过，跨角色/类目只在原因明确后按原方案验证。

本方案无新服务、无新业务阶段、无逐图人工制蒙版要求、无新生产门禁。实验性评分不进入业务运行流程。
