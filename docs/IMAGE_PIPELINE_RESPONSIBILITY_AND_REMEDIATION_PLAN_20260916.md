# 图片生产职责边界与整改方案

日期：2026-09-16。

性质：待确认方案，本轮不实施生产修改、不生图。结合当前工作区与 `IMAGE_CLASSIFY_TO_GENERATE_DEEP_AUDIT_20260916.md`，修正上一轮仅按故障点组织整改而职责边界仍不够明确的问题。

## 1. 目标与不可改变的边界

目标不是复制源图，也不是让程序自动设计一套图片，而是：

> 从可靠商品证据出发，由 Gemini 规划每个 child 的完整视觉表达，由图像模型执行产品保真的参考图编辑，程序负责可信数据、正确传递和稳定执行。

最终应满足：

1. 产品身份、变体、真实部件、结构、材质、销售数量和尺寸不被改变或编造。
2. 背景、普通床品、墙面、地面、非售卖道具、摆放、构图和信息图样式可以重新设计。
3. 同一 child 的床品、环境组件、字体和图形角色有一致设计；不同 child 可以不同，不设 family 固定色板。
4. func/size 仍是有产品参考依据的编辑任务，不改成无依据的新产品渲染或 Pillow 文案拼贴。
5. 所有请求图片都有明确结果，不用少生成图片换取“流程通过”。
6. 事实失败、接口失败、provider 失败、资源等待和主观质量不足明确区分。

不增加 stage、controller、QA、候选流程、feature flag 或第二套 prompt。保留既有主图类目策略、模板默认值和生产主流程；不涉及 SP-API。本轮修改范围只针对图片链路职责与已有故障，不顺带改文案/模板。

“不造成新的阻塞”不等于取消必要事实检查或承诺永远零失败，而是不能用设计偏好、重复合同、格式歧义和不相关依赖阻塞生产。

## 2. 首先纠正“程序负责事实”的含义

程序负责事实的身份、来源、存储、换算和传递，不等于程序能凭规则知道图片里的床架是什么、哪种颜色好看、哪条文案具有商业价值。

| 判断类型 | 决策主体 | 程序能做什么 | 程序不能做什么 |
|---|---|---|---|
| 商品记录、变体归属、来源 | 已有商品事实链路及有依据的模型观察 | 保留出处、隔离明确冲突、验证引用 | 猜测哪份矛盾数据一定正确 |
| 图片里有什么产品结构、文字指什么 | 现有 Gemini 观察 | 提供原像素、保存定位、验证引用和坐标 | 用关键词代替视觉理解 |
| cm/kg 到英寸/磅 | 程序 | 确定性换算、合理显示精度、保留原单位 | 改变测量对象、把“单层承重”改成“总承重” |
| 房间、配色、道具、排版、功能表达 | Gemini 视觉规划 | 传递品牌要求、类目政策、工具数据 | 按产品颜色硬选固定设计或替模型重排画面 |
| 某种描述是否改变产品、是否有证据 | 现有事实语义审查模型 | 限定审查问题、验证审查记录、定位责任 | 假装正则能理解全部自然语言 |
| prompt 怎么交给图像模型 | 当前编译器 | 忠实投影、引用展开、确定性去重 | 重新设计、补造卖点、拼接历史禁止句 |
| 成品像素的实现 | 图像模型 | 按角色提供证据、设计和接口参数 | 本地擅自补画结构、补写模型遗漏文字 |
| 超时、并发、预算、重试、状态 | 当前 controller/执行器 | 按配置和资源调度、保存回执、有限恢复 | 因审美不满意无界重生或启动另一套调度 |

核心分工：程序不是设计师；模型不是商品事实的自由改写者；审查模型不是第二个美术总监。

## 3. 产品不变与画面可变必须区分

| 情况 | 是否允许 | 边界 |
|---|---|---|
| 换床单、枕头颜色、数量、形状 | 允许 | 普通非售卖床品；不误导包含关系 |
| 更换墙面、地板、摆件、书架、灯具 | 允许 | 不需要先给源图道具逐个编号或证明一一替换 |
| 移除床垫展示已有排骨架 | 允许有依据的展示 | 参考证据支持该产品结构，不能凭空补画被遮住的支撑 |
| 给裸床架增加床品 | 允许 | 不遮掉本图必须表达的功能；不声称随货包含 |
| 抽屉打开/关闭、柜门状态调整 | 允许有依据的呈现 | 状态不等于永久结构；不能改变抽屉数量或机制 |
| 改角度、裁切、功能图面板数量 | 允许 | 新角度本身不是失败理由；不能因此编造关键部件 |
| 局部图没显示全部抽屉 | 可以 | 裁切/遮挡不等于删除实体，不要求每张完整展示所有部件 |
| 白色床架变原木、木架变金属 | 不允许 | 背景自由不包括售卖产品换色换材质 |
| 总宽 64 英寸写成 60 英寸 | 不允许 | 渲染文案来自现有测量权威 |
| 只看到排骨条却新增不明白色边框 | 不应凭空执行 | 使用同 child 已有对应证据，或由现有规划调整表达 |
| 蓝色枕头“不够高级” | 质量意见 | 不因主观审美新增 QA 硬失败 |
| 同 child 两处给同一枕头不同颜色指令 | 规划内部不一致 | 在已有规划环节解决；不是产品事实错误，不归 QA 发明新门槛 |

“允许调整”不等于默认改变销售事实；“证据不足”也不能被扩大成禁止一切新视角、新场景。

## 4. 逐环节职责

以下是现有环节内部的职责拆分，不代表新增生产阶段。

### 4.1 输入与源图归属

位置：现有 source_fetch、asset_manager、商品 family 记录。

- 输入：请求 ASIN/child、上游返回的商品记录和图片 URL。
- 程序负责：来源、下载、完整性、child 对应关系及文件身份。
- 不负责：看到图中有木色，就自行认定整张不是白色产品。白色床架的内部木色排骨条可能完全正确。
- 原始 gallery 包含错误变体，不应假定下载成功就等于证据可信。
- 不新增抓取流程，不改历史 jobs。

### 4.2 图片分类与联合观察

位置：`core/visual_semantics.py:observe_child_sources`。

- Gemini 负责：图片用途、产品外观与关键结构、文字实际含义、测量对象、具体变体矛盾、必要产品视图定位。
- 程序负责：稳定 ID、输入顺序、引用存在性、可解析格式、坐标有效性、保留逐行成功结果。
- 输出是产品证据与用途，不是最终构图，也不是源房间设计清单。
- 只观察产品及必要的随货/非随货争议，不清点普通墙面、床品、摆件的颜色、位置和数量。
- 对不同用途保留必要结构证据，不以“少一张图”为目标把另一种机制的视图去掉。
- `unknown` 只在依赖该事实时才产生实际影响；无关背景不明不能阻塞商品观察。

针对 F01：删除事实编号双重表达，使用一套规范 ID。优先复用已有事实身份，不为了节省几十个字符建立第二套别名。来源路径可以作为元数据，但不能成为另一种可竞争的引用 ID。

### 4.3 功能事实与尺寸整理

位置：`core/final_source_intents.py`、现有测量转换函数。

- 模型负责区分“产品机制/部件/数量/限定条件”和“广告修辞/品牌/普通道具字样”。
- 程序负责保留模型给出的有依据的语义、关联来源、单位换算和事实引用。
- `marketing` 与 `product_label` 不是决定商业重要性的规则。不能保留 High-Quality、丢弃 Embedded Design。
- 不改成“所有 product_label 都必须生成到成品”：品牌标记、表面文字、无关标签仍不能被升级成宣传文案。
- 测量事实必须连同对象、轴、条件一起传递；相同数值但对象不同不能去重。
- 数量与限定条件不可被拆散成失去语义的独立数字。
- 对语义不清的文字使用原有观察纠错；不增加另一次全量模型解读。

针对 F02：child 商品事实必须在现有 child 级上下文中取得，不再挂靠首图。局部修复缩小的是图片范围，而不是把全局商品事实一起删掉。删除 source.product_claims 的首图特殊行为及依赖它的回退读取，不用每图复制全部事实补洞。

### 4.4 参考选择与实际附件

位置：`core/image_reference_context.py`、现有 kit/task 的 reference 构造。

- Gemini 观察提供可用产品证据目录；视觉规划选择本图需要的主视图、局部或核验视图。
- 程序执行选定裁图、来源绑定、SHA、坐标转换和附件排序，不自行判断哪个结构“不重要”。
- 同一个产品不同机制的局部不能被当成重复图；不要求保留所有原面板或把所有核验图显示在成品上。
- 观察时的输入精简建议不能成为后续规划永远无法使用其他已确认产品视图的硬限制。
- 不做自动补全遮挡结构，不用擦除源道具来伪造“干净产品证据”。

针对 F04：把现有附件构造收敛成一次确定性解析。规划审查消费本图真正会发送的产品附件清单；ImageTask 和生成端复用该清单，不各自重新筛一次。复用/迁移现有函数并删除旧分支，不新增附件 controller 或第二份可独立修改的清单。

审查可额外读取原页核对来源，但必须区分“原页可见”与“生成输入可见”。原页某个未发送的角落不能用于证明生图已经获得该结构。

针对 F07：只有像素与坐标框等价时才共享一个物理附件；它可承担产品和测量两种用途。附件编号及测量定位同时更新。不同范围的 size 裁图不能简单按来源相同去重。

### 4.5 Child 视觉规划

位置：`core/visual_design_kit.py`，继续由现有 Gemini 调用完成。

Gemini 决定：

- 根据产品类别、用途、用户和市场目标确定场景，不把所有床架都当儿童床，也不忽略确有依据的儿童属性。
- 本 child 的非产品配色、床品/道具组件、材质质感、光线和生活场景。
- 每张图的沟通目的、镜头、重点、排版、功能表达与文字布局。
- 同 child 的字体层次、文字/引导线/徽标等语义角色和一致性。
- 选取能支持目标表现的产品证据，给功能文案绑定事实。

程序只提供用户要求、现有类目政策、不可改商品事实、输出图片清单、可用证据和合规设计参考。不能决定“白床配蓝灰”“每张左标题右产品”“所有徽标都与床架同色”。

当前字段虽名为 family_art_direction，本方案的设计单位仍是 child。不为名称统一而进行全仓重命名，也不借此增加 family 配色控制器。

输出数量按当前测试/生产请求和现有清单执行；源图锚点用于事实归属，不把源图布局变成必须继承的模板。Gemini 不可以用省略困难角色让任务看似完成。

### 4.6 配色工具与设计参考

位置：`core/palette_registry.py:planned_palette_diagnostics`、现有设计参考加载。

- 当前配色工具计算亮度、对比度和色差，代码明确为 diagnostics_only；它不是当前的自动选色器。
- 数学指标可以解释颜色关系，不能证明“优雅”“美式真实”“高转化”。
- Gemini 负责设计；工具负责计算和诊断。程序不按一个分数替换模型的颜色，不恢复固定路线表。
- 同一 child 的同一目标组件只定义一次外观；不同 child 可以独立设计。产品本体的颜色、材质不进入可改非产品色板。
- 文字、线条、徽标可以使用不同但协调的语义角色；同角色跨图一致不等于所有元素一个颜色。
- 现有诊断的缺失/未解析不应阻塞生产，不额外增加一轮“配色模型审批”。
- 参考素材只提供获批范围内的设计启发，不提供产品事实。没有获批包可以由 Gemini 自主设计，但不能把它报告成“已验证素材迁移”。

本轮不把配色诊断改造成另一套推荐引擎。设计效果靠规划、执行和经批准的实图对比证明，不能继续用“工具已安装”代替效果。

### 4.7 现有规划审查与局部修复

位置：`visual_semantics.review_planning_bindings`、`visual_design_kit._finish_image_briefs`。

- 审查模型负责：产品事实是否被改变、功能文案是否有依据、实际附件是否支持拟展示的结构、尺寸对象是否正确。
- 程序负责：引用/记录对应、请求预算、问题定位、现有有限修复调用。
- 不负责：重选色板、要求装饰数量一致、要求源图角度/构图/面板不变、打审美分。
- 计划内部的目标配色统一由规划者负责；不是把整个 child 交给第二个设计模型重新决策。
- 源图观察错误回到现有 observation_corrections；设计输出错误回到原规划的局部修复。不得让下游编译器偷偷修改上游结论。
- 修复仅改变错误所属字段/角色，不让一条尺寸问题引起全 child 配色重做。
- 共用设计如果本身出错，只修改现有唯一共享定义及受影响任务；不在单张图内创建例外色板，不默认推倒整套 kit。

自然语言事实冲突必须由现有语义审查处理，不能声称一个 HEX 正则可以识别“60 英寸”和“64 英寸”的真实对象冲突。审查同一角色的拟执行指令时一并看事实，不增加第二个审核请求链。无需重审无关成功角色。

### 4.8 任务形成与 Prompt 编译

位置：`core/image_tasks.py`、`core/image_prompt_compiler.py`。

- ImageTask 是执行快照，不是第二次设计。
- 编译器只展开引用、统一单位显示、输出角色必需内容和接口格式。
- 不补造床品、不选颜色、不改文案卖点、不用类别模板覆盖 Gemini 的构图。
- 不将所有历史失败原因拼入每张图的 prompt。
- 不把同一尺寸/配色分配分别从多段自由文本反复拼出。

应明确现有字段的唯一职责：

| 内容 | 唯一权威 | 其他字段的处理 |
|---|---|---|
| 产品身份、材质、原有 finish、销售组成 | 现有产品事实和对应产品证据 | 色板不再定义产品本体 |
| 尺寸、承重、测量对象、单位 | measurement authority | creative_brief/显示文案不重写数值 |
| 功能标题、标签、限定词 | display_copy 及其事实绑定 | visual_goal、设计参考说明不提供额外可渲染文案 |
| 墙面、床品、道具等组件外观 | child palette_direction | 单图选择组件，不另外定义颜色和材质 |
| 字体家族、字重、层级、间距 | typography_direction | 不在此再选文字颜色 |
| 文字、箭头、徽标等角色色 | graphic_direction | 不在其他风格段再次分配颜色 |
| 相机、布局、视觉焦点 | image_direction 的构图内容 | 不复制商品规格或共有配色 |
| 产品附件及测量坐标 | 本图实际 reference 清单 | 不以生成前重新筛图改变规划的依据 |

不是看到某个词重复就删：同一个数字可属于不同测量对象，同一个结构词可分别承担事实和构图作用。只消除责任重复，不能抹掉必要语义。

自由构图描述不能成为绕开以上权威的通道。具体落地是先修改规划字段的职责和返回示例，再同步唯一编译投影；发现自然语言冲突，交原规划/现有事实审查处理，不以正则擅自重写整句。必要时替换现有混合字段，而不是添加一个新字段同时保留旧自由描述继续运行。

这里不承诺“自然语言合同可以百分百静态验证”。目标是减少可独立下达同类指令的位置；剩余模型错误需由原有语义环节和实图验证发现，不能通过收紧所有设计自由来掩盖。

### 4.9 生成、重试和资源调度

位置：现有 image_generation、executor、provider_routing、production。

- 图像模型按该 child 的事实、参考和设计完成图片，func/size 保持参考编辑性质。
- 程序选择已启用且支持角色/附件能力的 provider，按内存和真实资源组限制并发；不为每个模型名称虚构独立资源。
- 响应落盘、恢复已收到结果、本地后处理和原有候选机制保持原链路，不新增二套执行器。
- 已知传输失败按已有预算重试/备用路由；未知请求结果先核对已有回执，不盲目重复付费。
- 程序合同错误不换 provider 碰运气；配色不好看不自动无界重生。
- 编译任务不匹配、实际附件缺失必须在发送前指出责任方，不能静默换成无图生成。

### 4.10 成品 QA、发布与模板衔接

- 现有模型观察产品/文字证据，现有 QA 决定硬事实和发布条件，不增设另一轮审美审核。
- 结构、部件数量、尺寸对象、事实文案、错误变体、明确不符类目主图策略属于硬问题。
- 布景与源图不同、普通书本有非品牌文字、主观上不够高级，不成为新的自动失败条件。
- 同 child 设计一致性要检查和反馈，但不以像素 HEX 相同或色差阈值作为新增自动 QA 硬门槛。
- 缺少模型验收证据仍为未确定，不冒充通过；缺图不冒充全量完成。
- 发布/模板只消费现有合格结果，不反向重设计图片，也不提前把模板非图片问题塞回视觉规划。

## 5. 错误归属与影响范围

这张表是对现有异常和状态的责任约定，不要求新增一套状态机。

| 错误 | 责任方 | 处理范围 | 不得采取的行为 |
|---|---|---|---|
| 输入 fact ID 与校验不一致 | 程序合同 | 修生产接口并离线复现 | 让 Gemini 不断重试同一错误合同 |
| White child 中明确是 Natural 外框的源图 | 来源/观察事实 | 隔离该图；不影响其他可靠源图 | 静默把 Natural 当 White 或拒绝整 family |
| 未知源床品颜色、摆件位置 | 无需建立的非产品状态 | 不进入事实合同 | 新增道具识别后要求全部一致 |
| 模型观测框轻微偏差 | 观察定位 | 原有局部纠错；仅影响依赖它的证据 | 任意放宽全部坐标，或重读所有源图 |
| 目标展示的产品结构没有实际参考 | 规划证据选择 | 用已有同 child 证据在原规划内补齐/调整 | 编译器补画，或无条件删除该功能 |
| 商品尺寸在自由描述中被改写 | 规划事实语义 | 原有事实审查和局部修复 | 加一句“以另一个字段为准”继续发送冲突 |
| 同目标组件出现两种设计定义 | 规划内部 | 修唯一共享定义/错误单图表达 | 建单图覆盖层或审美 QA 闸门 |
| 布景、色板不够漂亮 | 设计质量 | 冻结实图审阅后给出明确设计反馈 | 自动无限再规划、再生图 |
| provider 确定超时/配置不支持 | 当前执行器 | 有限重试/备用路由/明确缺口 | 自动启用用户停用路由 |
| 请求结果未知 | 当前执行器及已有回执 | 对账/恢复，必要时明确待处理 | 假设失败立即重复收费 |
| 进程退出状态仍 running | 当前 controller | 原有生命周期收口 | 新增后台调度状态机 |

无关角色可以继续，但全部必需角色未完成时仍不能报告整 child 全量完成。仅当共享身份/事实真正无法确定时，才需要暂停依赖该共享事实的全部角色。

## 6. 针对上一轮发现的实施顺序

### P0：先修事实接口，结束无效重试

范围：F01、F02、F09 中与当前配置冲突的断言。

- 统一事实 ID；删除旧双层编号及对应旧 schema/fixture，不加兼容别名。
- 让现有 child 事实独立于源图子集；初次规划、局部修复共用同一来源。
- 删除依赖首图持有所有事实的读取路径，不恢复每图复制。
- 更新当前 provider 意图的测试；不能为旧测试绿灯而停用 QC 或启用 AICOST。

通过标准：本轮实际响应中的合法引用通过，真实变体冲突仍隔离；非首图局部修复有完整必要事实，其他角色不重新规划。

### P1：修产品事实与执行证据，先解决重绘条件

范围：F03、F04、F07、F10。

- 纠正营销/结构标签的事实投影，保留机制、部件、数量及限定条件。
- 把产品观察目录、规划选择与实际附件明确分工；必要结构不在选择过程中丢失。
- 让现有规划审查与生成使用同一实际附件映射。
- 同像素多用途附件一次发送，引用同时更新；不同裁切范围保持区别。
- 坐标问题使用已有定位修复；不能把本轮约 3 像素偏差直接推广成无条件容差。

通过标准：func_02 的“内嵌防滑结构”能追到实际发送像素；产品标签不再被类型筛选吞掉；背景与源图不同仍合法，关键结构缺证据不能被 supported 掩盖。

### P2：单一设计权威与单一编译投影

范围：F05、F06。

- 从可改色板移除产品本体职责；保留 Gemini 对非产品设计的自由。
- 尺寸、文字、组件外观、字体、图形色、构图分别由现有一个字段组负责。
- 改动规划请求/schema/示例、返回编译和最终 prompt 同步完成，删除被替代的输出路径。
- 不新建“强约束补丁段”，不设为了字符数达标而删语义的任务。
- 自然语言事实冲突仍交现有语义审查；不新增审美模型、评分或审核流程。

通过标准：输入不再同时下达 White/black metal 或 64/60 英寸指令；同 child 的设计定义唯一；新背景、新床品和新镜头仍可表达。提示词更短是副作用，不是唯一验收目标。

### P3：现有恢复诊断与开发验证收口

范围：F08、F09 及全部修改的跨环节验证。

- 日志明确记录传输成功、观察有效行、规划结果、生图请求和等待阶段，不用“成功”混称。
- 在当前 controller 内处理终止状态，缺 ImageTask 不应抹掉已有 classify 统计。
- 替换当前生产链路中的旧测试/fixture，按行为覆盖关键边界，合并重复案例。
- 生产文件增删同步，扫描旧 schema、旧读取、旧 fallback 和旧测试引用；不迁移历史任务为新生产输入。
- 定向测试优先，最终生产套件只跑一次，保持 <=100 项且 <=60 秒；不跑历史全发现套件。

通过标准：错误可归责、成功结果可复用、任务数量可核对；不再以“多数单测通过”替代实图质量。

上述 P0-P3 是开发整改顺序，不是生产新增四个 stage。

## 7. 必须删除与必须保留

| 删除/替换的行为 | 保留的能力 |
|---|---|
| fact_* 与 product.* 并存的引用歧义 | 稳定事实引用及真实 quote 校验 |
| 首图承担 child 全局事实的隐含规则 | child 共享事实、局部图片请求 |
| marketing-only 决定功能事实的旧假设 | 产品文字语义分类、品牌与普通道具文本区分 |
| 已识别结构被选择器永久排除但文案仍使用 | 必要产品证据、按图有目的地选择附件 |
| 用未发送原页局部证明生成已具备结构依据 | 原页来源核验、实际执行附件验证 |
| 产品材质/finish 作为可改场景色板 | 产品保真、Gemini 自主设计房间床品 |
| 多字段重复发出尺寸、颜色和显示文字指令 | 单一权威和必要的构图表达 |
| 为表示不同用途而无条件重复发送相同像素 | 多用途语义、测量对象和坐标映射 |
| 固定过时 provider 开关的测试 | 当前角色能力、用户停用决定和执行恢复测试 |
| 模糊 success/请求数统计 | 逐行成功复用、真实阶段结果、费用可追踪 |

不能为了“彻底清理”删除引用校验、变体隔离、事实 QA、已保存响应恢复或必要测量证据。也不能保留旧实现作为默认关闭的 fallback。

## 8. 最小验收集与冻结实测边界

开发验证使用现有测试与本轮已授权证据，不增加生产环节：

| 验证对象 | 应证明什么 |
|---|---|
| 实际观察响应 | 合法事实编号通过，真实变体冲突与引用错误分别处理 |
| 非首图局部修复 | 必要商品事实不丢失，其他角色不被重做 |
| 结构标签与数量 | 8 根排骨条/内嵌结构等不会因类型归类消失 |
| func_02 实际附件 | 拟显示的产品结构有执行证据，不只审查端看过 |
| 尺寸/材质反例 | 错误描述不能与正确事实一起发给生图模型 |
| 合法设计自由 | 换床品、背景、道具和构图不被旧一致性要求拦截 |
| 附件去重和定位 | 同像素复用不破坏 label/endpoint 所属附件 |
| provider 与恢复 | 用户停用路由不被请求；确定失败与未知结果分开 |

不会承诺用单元测试验证“好看”。生产测试数量预算通过合并/替换旧案例满足，不在已有 100 项之外机械再加八组测试。

真实冻结测试必须再次得到用户批准。批准前只做离线开发验证，不能以“E3 曾授权”为理由擅自启动新的付费轮次。

获批后使用同一床架 child 的全部角色图片，代码/配置/输入冻结；先核对任务和真实附件，再请求生成。逐张比较产品与 size 结构、具体功能事实、child 设计统一性和场景效果。成功图复用，确定失败角色按预算处理，不为修复一张整组重生。

一个床架的通过只能证明该 canary，不能冒称全部类目通过。跨类目实图验收另行确认范围，不在首次冻结时自动扩大费用。

## 9. 本轮结论

上一轮审计发现的事实接口错误、修复上下文丢失、功能事实过滤和参考不等价，必须修。但修法必须服从以上职责，不能再变成更多审查条款和优先级 prompt。

最终要保留的是：一个事实来源、一套 child 设计、一次忠实编译、一套执行与恢复。不同组件间可以传递只读投影，但不能各自重写同一个事实或设计决定。

本轮只新增本方案文档。生产代码、配置、测试源码未改；未运行新测试、未调用模型、未生成图片。方案没有声称问题已修复。
