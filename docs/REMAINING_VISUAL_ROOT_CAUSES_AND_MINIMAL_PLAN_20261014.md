# 本批未通过问题：根因核查与最小修复方案

日期：2026-10-14。状态：只读诊断与待实施方案；本轮生产修改0、模型请求0。范围为上一轮原四个作业、五张问题图（白床两次结果）及白柜 scene_04。未扩查其他历史作业。

## 一、结论与需要纠正的表述

本次查到了可验证的具体断点，不能再把这些问题都归为“模型随机”或“提示词不够强”。

| 问题 | 本次确认的原因 | 尚不能证明 |
|---|---|---|
| SAM已有较完整候选却未选 | 程序按各unit最高分初选；物理计划更新后直接进入confirm，隐藏替代候选且不允许改选。此次不是Gemini看完所有候选后选错 | 调整选择闭环就能补上SAM从未生成的部件 |
| 最后白床局部修复越界 | 实际请求没有mask；明确固定的圆窗仍被原生输出移动。另有修复目标错配：移动现有床并保留其纹理，无法验收原主体重绘是否恢复 | 网关内部处理与模型内部机制各占多少；再补一句指令就能保证不越界 |
| func结构关系错误 | 有错误源事实、过宽功能绑定、图形被当产品选中、具体窗口状态缺失和画布语义不足 | 纠正输入后所有模型输出一定正确 |
| 白柜规划阻塞 | 双柜来源未解决；连续提交“改成单柜+接受旧区域”；反馈未给出具体依赖变化和补丁后剩余错误 | 只恢复一次调用就可完成新底图和新区域确认 |

上一轮“已有完整候选却选错”需要精确改为“**程序最高分初选后，规划确认没有得到替代候选的选择机会**”。上一轮白床“位置修复”的结果也不能作为整件主体保真修复的验收。

## 二、SAM：补齐现有选择闭环

### 证据

`core/product_region.py:400-408` 对每个semantic unit选最高分非空候选。白玫瑰杆-only得分约0.910/0.897，盘+杆约0.479/0.493；海棠Step 1杆-only约0.699219，盘+杆约0.626953。分割置信分数不是必需部件覆盖完整度。

三张树图新的region均为 `repair_round=0`、`delta=null`，最终selection与程序初选一致。较完整候选已经落盘，出现在 `candidates_00.png`；sealed请求证实最终confirm只发源图、初选overlay和anchor_details，未发候选图/候选列表，响应只允许accept/blocked。

需区分历史展示：白玫瑰左侧的完整候选曾在首轮修规划请求中展示，但该轮执行的是补齐第二树的物理计划；重建后又按分数初选。新右树候选与海棠新步骤候选，则没有进入随后确认的可选择审查。不能把它们统称为“模型从未见过任何完整候选”。

规划器确实看到了有缺口的最终overlay却接受，视觉确认也有误判。白玫瑰圆盘无正点，零anchor冲突不能证明完整；海棠既有正点落在圆盘，也有正点落在手部，不能改成“全部正点命中”硬门槛。未发现候选ID、分数、导出像素或生图mask身份错配。

原因链：现有 `visual_design_kit.py:321-330,419` 将改变物理计划后首次prepare产生的新候选视作已修改结果，进入confirm；`planning_contract.py:22-25` 关闭提议能力；`planning_feedback.py:116-119` 随之隐藏替代候选。**尚未做过候选选择，却被放到了只确认当前初选的位置。**

### 最小修改

1. 在原调度器区分“新物理基础产生、尚未经过候选决策的初选”与“已经执行改选/局部纠错、等待确认的新结果”。前者走已有 `decide_region`，后者仍走已有 `confirm_region`；依据当前region身份与已有操作记录，不重置作业预算。
2. `decide_region` 展示已有候选图和实际ID，允许优先选择现有候选。默认最高分仍可作初选，但不视为产品完整性结论。
3. 将只选择已有候选与新SAM推理的权限分清：纯select不发SAM请求，不因之前重建新物理基础而失去选择机会；跨对象ID、无效候选、改变实际像素后的确认规则继续保留。
4. 真实改选后的组合仍走现有确认。禁止在未看过新组合时直接标为通过，也不新增一个QA模型或常规确认步骤。

实施必须同步修改现有pending执行准入、操作预算判断和 `apply_action` 的共享额度语义；只修改work_kind/展示候选，仍可能被后续准入挡住纯select。不能增加第二套额度账本，也不能让纯select权限放开已耗尽的新SAM推理。

**成本边界：**初选正确时，该次原规划调用可直接接受，正常轮次不增加；真正改选时，可能使用一次已有确认调用。预算不足时保留具体方案/结果，不能为“零新增调用”提前接受或暗中加额度。

**不能做的替代：**不选面积最大的、不盲目并集、不提高全类目覆盖率门槛。药柜整圆窗保护带入箭头/装饰正是“更大不等于更好”的反例。海棠Step 2尚无覆盖圆盘的完整候选，应使用既有局部纠错能力处理具体缺口，不能宣称单靠重选已解决，也不要求每个叶缘像素完美。

## 三、局部修复：改正目标与已有入口的使用

### 已查明

最终白床请求的第一附件确为candidate1，第二附件确为source_03；发送SHA与原文件一致，未缩放，mask为空。代码 `core/image_generation.py:464-473` 有意移除源坐标蒙版，避免套到不同布局的候选上，这一点应保留。

首次“禁止源坐标却要求恢复源位置、标题又占目标位置”的硬冲突已经修掉。最终请求明确固定右侧两圆窗，但原生返回仍移动右下圆窗/标签和床头柜。不能继续用已删除的首次冲突解释最终失败，也不能归为本次SAM失败。

另外，该请求要求移动既有主床且保持它的现有结构纹理。若目标是修复旧主体重绘，这个验收任务本身不充分；只看是否搬回原位无法验证结构与木纹是否回归真实产品。

### 最小处理

- 先在原问题记录中列清实际结构/纹理缺陷，不把任何位置差异都当结构错误。本轮未确认新增床尾栏杆数量错误。
- 真正局部缺陷沿用 `targeted_edit` 与现有reason：明确具体构件、允许变动对象、固定对象、腾空背景怎样填补。若只是移动位置，床头柜不能笼统包含在“main bed view”中。
- 整件几何/纹理已不可信时，显式选择已有 `revise --mode full_redraw`。这个已有分支实际是 **SOURCE EDIT REPLACEMENT**：同job、同child、同role追加revision，使用原source与当前已绑定mask，不是从零文生图，也不需新建SAM流程。
- 不新增关键词自动路由，不把所有失败都送回原图重做。不要继续要求“保留错误候选结构”又验收“所有重绘恢复”。

这里没有证据支持再新增一套通用提示词禁令。明确边界只能减少歧义，不能承诺模型完全不越界；真实失败必须如实记录。

## 四、func：修当前可见状态及图形含义

### F1 海棠安装连接杆

源图Step 1中杆帽与圆盘分离；原观察却写 `Pointed spike inserted upwards through the center aperture of the circular disk`，并原样进入最终提示。操作说明“插入”被当成已经发生的实体连接。新图跨过空隙生成杆件，与该错误输入方向一致。

**修法：**在原源观察说明中分开当前像素状态、文案描述的下一步动作、隐藏结构。仍用 `physical_facts` 记录可见分离/接触/遮挡；操作文案仍归 `text_observations`。规划state按每个必要窗口保持当前状态，不能统一成最终已装好。重核这张相关源，保留旧响应，不用手工改历史事实。

### F2 药柜引线与替代层板

`adjustable_shelving` 同时包括层板、调整窗和门打开的事实；标题和说明都绑定它。一个feature归属正确，仍不能确定新增引线的具体落点。源图没有该跨窗引线，新图却指向门板。

此外，SAM查询写成整个圆形callout，实际蒙版保护了整个圆窗、图形箭头、替代位置及装饰。源观察已识别ghost positions，所以不能重复说全部是观察没识别。

**修法：**

- 在现有feature事实与规划中明确真实层板/侧壁/支承、同一层板互斥替代位置、说明箭头，SAM查询实际零件而非圆窗版式。
- 调整 `_copy_associations` 的语义：target是事实/功能归属，标题/步骤标题不因此必须新增引线。物理标签如需引线，使用实际可见功能部位；尺寸箭头继续按measurement合同处理。
- 本图跨窗引线没有必要，可由原规划不添加；保留时必须说明实际落点。不能全局禁止引线，也不能用整柜任意点代替层板位置。

### F3 海棠树冠补全、地钉比例

source_02整图 `whole_view` 因右侧完整树而成立，但左窗口树冠被裁切。原feature事实没有写左窗口裁切状态；最终通用禁止补全仍未被执行。

**修法：**通过现有feature事实与presentation.state明确“左窗口裁切、右窗口完整，各自保持可见比例”。不把整图whole_view改成detail、不强迫重复创建左侧parts、不凭右树补齐左树。比例仍以原像素为证据，不创造数字尺寸。

### F4 白玫瑰庭院与悬空

graphic_canvas分支仅排除room staging，而state又提户外安装，允许模型把附件展示理解成户外使用场景。地钉比例则是已要求保持但仍发生的执行偏差。

**修法：**仅在现有graphic_canvas分支明确无完整室内/室外布景；必要的局部土壤剖面、花盆和墙面安装关系仍按本图证据保留。源图裸露地钉展示不等于已经插土。禁止扩大为所有func都不许有环境。

## 五、白柜：让失败反馈能指导一次完整修改

### 已查明

最新请求包含上次错误、原3项合同问题、9张原图和当前SAM诊断，并非没传反馈或没有替代图。模型连续三次只把“双柜”文字改成“单柜”，同时 `accept_current_region=true`。source_05的右柜仍unknown，蒙版只含左柜。

只读反事实证明：仅去掉提前接受标志，依然剩右柜归属错误；使用现有source_03的单柜证据并一起更新源、选区、状态，合同错误为0。后者只是内存可行性验证，不能当作已保存的新规划或新图验收。

当前5/6次调用，停止是同类无效操作累计3次；不能说额度已耗尽。

### 最小修改

1. 原字段契约具体说明哪些实际变化会使旧region失效；有未解决合同错误时不再提供无效的裸accept操作。保留合法纯文字修正后接受同一有效region的能力。
2. 维持原子拒绝。对被拒绝补丁在内存计算实际依赖变化和剩余合同问题，再通过现有 `last_operation_error` 一次反馈：product_state改变了目标实例、提前接受旧region不合法、source_05的cabinet_02仍未知。
3. 不只返回笼统physical dependencies；也不自动把true改成false后执行，不把错误文字变成扩大可写权限的理由。
4. 原规划器从已提供的明确单柜图（如source_03）选择符合目标者，同时修正 `product_sources + region_intent + product_state + visual_goal`。保留scene_04的交付槽位和客厅用途，使用既有新区域确认。
5. 若坚持双柜源，应回到现有源事实责任解决第二柜身份；不自动删除、改成道具或断定两柜随售。未知对象检查范围保持原样。

尚余1次调用不一定够完成换底图及确认；保留原预算、失败记录和回执，不以新job或计数清零伪装恢复。

## 六、实施顺序和验收边界

### 第一批：只修可确定程序缺陷

在原 `visual_design_kit / planning_contract / planning_feedback / planning_provenance / product_region` 中修候选决策时机、选择与推理权限、具体事务反馈。删除被替代的“新候选直达只确认”和笼统错误分支，不保留第二套路径。无需新模块或新控制器。

### 第二批：纠正已定位的语义输入

修改原 `visual_semantics` 观察说明和 `image_prompt_compiler` 功能绑定/graphic_canvas措辞。沿原入口只重核相关证据和规划；不新增关系图谱、全角色必填字段或另一视觉模型。白床按真实缺陷选既有修复模式，不为它再增加生产路由。

### 定向正反例

- 新物理基础的候选不被隐藏；初选正确直接accept；改选后必须看到实际组合；纯select不触发SAM，跨owner仍拒绝。
- 白柜“改状态+接受旧region”被拒且返回具体字段与剩余源问题；纯文案修改的合法接受不被误拦；明确单柜底图的原子修改通过合同检查。
- 功能文案的事实绑定不强迫标题生引线；尺寸箭头仍保留；graphic_canvas限制不扩散到合法安装演示/场景。
- 使用实际落盘结构与原失败回复作夹具，复验身份、保存/读取和原任务库存；不以mock成功证明视觉正确。

合并替换现有相关测试；默认套件仍≤100例、≤60秒，最终冻结后只跑一次。本轮只是方案审计，没有重跑生产套件。

### 修改后的实图验证

继续原五张问题图与白柜槽位，先验证旧错误输入/选择机会确已改变，再按原预算验证输出；没有改动的请求不重发。白床若验收主体保真，就从原source执行现有source-edit replacement，不再用位置搬移测试代替。

逐图检查对应缺陷：Step 1分离空隙、真实/替代层板、引线实际落点、左树冠裁切、地钉比例、固定窗位置。保留旧候选、原始响应、预算、未知回执；不新建job、删失败槽位或增加自动返工。

**不新增完美蒙版门槛、覆盖率门槛、全类目语义拦截或强制QA。** 本方案能够针对已确认的程序及输入缺陷；真实编辑模型未遵循约束的剩余部分仍要以改后实图判定，不能提前承诺全部通过。
