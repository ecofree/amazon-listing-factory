# GPT Image 主体识别小样实测

日期：2026-09-26。范围：仅验证原图主体选区表达，不更换场景，不接入生产。

## 1. 结论

**本次证据支持模型能够辨认床架的大体主体，但不能确认它能准确分出每个可见产品像素。四张生成选区均不合格，不能直接作为产品保护蒙版。**

这两个结论需要分开：

- 输出包含房子形床头、烟囱、栏杆、床腿和侧面入口，床品大部分及房间大部分留黑。不能把这解释成模型完全不认识产品。
- 将输出叠回原图，屋顶、栏杆、横梁和凹槽均有明显偏差，表现为结构简化和局部位置变化。知道“这是床架”没有转化为准确的空间选区。
- 这项测试同时要求视觉辨认和黑白图绘制，不能直接观察模型内部的识别结果。不能仅凭生成选区失败，认定内部识别错误，也不能认定直接编辑照片必定失败。
- 本次不支持“必须加入第三方分割模型”的结论，也不支持“所有问题都已证实只有提示词造成”的结论。

## 2. 固定条件

- ASIN：B0DSSKTXXW。使用上一轮原木房子床的同一张原图，1500×1500。
- 原图 SHA256：`f52fcb090732d9eddb04c6ac53f0c4beb816698a4a0da40786542e71127aee93`。
- 单张原图，没有提供人工正确蒙版，没有把预设检查点图交给模型。
- 提示词明确售卖品为床架，床品、枕头、散放物及房间不属于产品；没有逐项告知屋顶、烟囱等部件的答案。
- 要求输出原坐标上的黑白选区：白色为可见床架，黑色为其余内容。要求保留孔隙，不补画隐藏表面，不裁切、不改变视角。
- 两个现有模型配置各重复两次，顺序为 GPT-2、Sunburst、Sunburst、GPT-2。每次源图和提示词相同。
- 通过现有 `generate_with_provider_retries` 与回执路径执行，未修改生产控制器或提示词编译器。
- 两配置均走 `subrouter.ai/v1/images/edits`。名称是网关配置及回报名称，底层模型身份没有独立核验；本次不是独立供应商对照。

## 4. 哪些问题能够确认

1. **主轮廓表达不是精确选区。** 输出虽像床架，但局部变形、上移和简化使其不能直接保护源图木材。
2. **壁龛没有被表达为实际可见表面。** 四张都出现规整的矩形孔，原图中可见木质内壁与摆件没有逐个区分。这个问题涉及语义/可见面表达，也受到整体局部错位影响，不能把每个错误点都单独归为物品识别错误。
3. **栏杆与缝隙不对应。** 孔隙并未全部填实，但白色细杆没有与源图细杆逐根重合；保护区会同时漏掉木材、覆盖旧床品。
4. **重复调用仍有差异。** 同配置两张在床头孔宽度和构件位置上不同。样本量不足以评价哪个模型更稳定，也不能归因于某个确定采样参数。

## 5. 评估边界

测试前选定了 19 个内部点；查看输出前保存了判定规则。诊断叠加只做全图等比尺寸转换和阈值 128，不平移、不透视对齐、不修补。

人工检查发现局部几何不对齐，因此不把点命中数量当作“识别准确率”，也不报告全图 IoU。点检查仅用于定位漏选与误选。落在白区并不证明该部件被正确识别。

绿色叠加是本地检查图；模型真正输出的是单独黑白图。原始图没有经过修复，叠加也不是模型生成照片。

**方法自身的限制：** 要求生图模型输出纯黑白选区，可能促使其生成简化的床架示意形状。这是与结果相符的解释，尚未用独立对照证实。因此本测试不能独立拆开“模型看错”与“模型看懂后画偏”。更不能用它替代真实照片编辑效果测试。

本轮只有一张复杂床架图。未测试柜体、树等类别，未验证产品颜色、纹理和材质保真，未验证更换环境时主体不变。

## 6. 对项目方案的影响

1. 不应再将“模型不认识床架主体”作为已经确认的根因。现有证据更支持：模型能表达主体概念，但输出时仍会简化或改变几何；在哪些条件下能够保留原图仍待直接编辑对照验证。
2. 本次生成选区不接入生产，也不追加 SAM、人工涂图或自动纠错流程。
3. 原图直接编辑路径仍值得验证。下一次有针对性的实验应固定原图、模型配置、附件顺序、目标场景和输出参数，只比较现有完整提示词与去掉主体重构/机位冲突的直接编辑提示词；每组重复两次即可形成第一轮四图对照。
4. 该对照应预先固定可见栏杆、连接、入口、木色、纹理、材质的检查部位。只有环境变化而主体保持，才能作为正面证据；不能以“整体看着类似”替代。
5. 若两种提示词都出现明显结构变化，先查现有编辑请求能力与路由证据，再决定下一项对照；不继续无界叠加提示词。本轮未执行该后续实验，此前模型×提示词八图方案也未执行。
