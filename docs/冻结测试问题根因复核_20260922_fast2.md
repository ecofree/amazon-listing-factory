## 三、图片问题：现象、来源与责任环节

### R01 原木浴室柜：场景图改变了整个柜体结构〔严重；图 50〕

- 对象：`B0H1VSH5GM / scene_02`，调用标识 `gpt-image-2.5-flare`。
- 源图：上部一扇滑门遮盖半边，另一半保留开放层；中间独立开放格；底部两扇门。
- 候选：上部变成两扇加长玻璃门，中间开放格消失。整柜变为上下各双门，门数量、门覆盖范围和分区关系都改变。
- 观察与规划链：源观察使用 `doors fully closed`；规划写成 `all doors closed`，只选择 `source_03`；审查以“单柜、闭门、餐厅场景与源图相符”为由给出 supported。
- 实际任务的 `product_facts` 主要是类型、颜色、规格与售卖数量，不能单独约束这台柜的具体分区。通用的“保持门、层板、柜体”也没有纠正已被抽象掉的门归属。

**根因判断：** 观察把局部门状态扩大为整柜状态；规划与审查没有保留“哪一扇门覆盖哪个区域”的关系，生图阶段据此补成常见对称柜型。重绘由图像模型完成，但上游已经给出含糊且带误导的状态。不能把它完全归为随机画坏。

**最小处理：** 在现有观察／规划字段中纠正滑门数量、覆盖区域和中间开放层，替换 `all doors closed`；当前附件不足以辨认这些关系时才选同子体补充参考。复核现有 product_depiction 对这些实际关系的审查，不增加一套结构控制器，不全局强制多附件。

### R02 棕色药品柜：上部双门被拉长到整柜〔严重；图 12〕

### R03 白床：把固定入口缺口画成带铰链的活动门〔严重；图 39〕

- 对象：`B0DSRTM3HX / func_02`，sunburst。
- 候选右下放大框新增铰链、活动栏门和开合箭头；主画面近侧围栏又连续封闭，与放大框所表达的入口状态不一致。
- 当前源图呈现侧边入口缺口，未提供活动门叶、铰链和开合机构证据。源文有 `Open Gate`，观察出现 `opening gate section`，规划 visual_goal 沿用 `open gate design`，文案也沿用 open gate。
- 规划的 presentation 实际是 `detail_only` 和 `open side entrance section`，候选却重建了完整床体并增加活动机构。

**根因判断：** 原始营销词存在歧义，观察／规划没有区分“可出入的开口”和“能转动的门”，模型将词义具体化成额外机械结构。现有通用“不得新增隐藏连接”约束已经存在，不能再声称问题只是没写这句话。

**最小处理：** 现有观察以可见固定缺口为依据；规划与文案改用证据支持的入口表达，删除会暗示可动门的说法。展示已知入口，不设计无证据的开门动作。不能仅替换单词而保留新增铰链的视觉方案。

### R04 白床：12 英寸箭头落到错误高度〔严重；图 41〕

- 对象：`B0DSRTM3HX / func_04`，sunburst。
- 8.5 和 12 两个值都在源图和 measurement_authority 中：前者是侧梁底部净空，后者被观察记录为床板层高度。
- 源图的两个标注上端不同；12 英寸标到较高的侧梁上缘附近。候选两条箭头上端都落到侧梁下缘，画成同一层位的两种高度。
- 对“12 英寸精确对应床板哪个面”的判断还应回到源图确认；目前观察把它命名为 slat level 的精度超过直接可见信息。这个不确定性不影响“候选两箭头落到同一错误层位”的判断。
- 规划仅写低角度床侧净空，没有确保两个目标高度在目标视图中可区分。提示词已有 measured_part 和箭头应适配输出几何的要求；模型仍未执行到位。

**根因判断：** 不是未授权尺寸；是源端点解释、规划视角与模型箭头执行之间没有对齐。单次输出不能证明固定发生，但“有数值和部件名即可正确画线”的假设已被本例否定。

**最小处理：** 在现有尺寸观察中收紧实际端点解释；规划沿用能看清两个高度的源支持视角。若该功能只表达净空，12 英寸没有必要时可由现有规划取消选择；不能靠新剖面或虚构床板来补足证据，也不能自动删除所有困难尺寸。

### R05 原木浴室柜：近义文案重复，技术画布未执行〔图 46〕

- 对象：`B0H1VSH5GM / func_02`，sunburst。

- 同时任务是 `graphic_canvas`，实际提示词明确不做房间布景，候选仍保留明显房间场景。功能信息还在，不能把这个直接改判为 func／scene 分类错误。

**根因判断：** 同一特点被产品文案和源图文字分别选入，现有成套规划没有收口；字符串校验只能挡完全重复，无法替代语义选择。画布问题则是源图影响和模型执行偏差。

**最小处理：** 在现有设计规划中为同一特点只选一个展示位置和一份文案；替换冲突内容，不加同义词黑名单。保留现有 role，核对 graphic_canvas 执行。Sliding 与 Gliding 是近义表达，撤回旧报告“源语义丢失”的说法。

### R06 黑色药品柜：调节间距关系仍不清楚〔图 2；需修正表达〕

`B0BYCY68SG / func_02` 的主柜大结构保留；局部放大框和多条 1.5 英寸箭头没有清楚对应相邻调节位置，容易读成板厚或其他层间距。不要仅因出现两块实体板就判定新增层板：其中一块可能是本有的固定层。

这里确认的是标注归属不清，不是确认整柜新增层板。最小处理仍由现有尺寸关系与替代位置表达负责，不新增层板数量的粗暴全图计数规则。

### R07 仿真树：单张可读，但成套重复占用图位〔图 29、31〕

单棵 `B0DBHKHFK6 / func` 与 `func_03` 都反复介绍三球、三根桉木树干、PE 藤和草面四个特点。一个由主产品源图派生，另一个来自功能源图；换排版没有形成明确的信息分工。

## 四、漏图与错误阻断

### R08 原木床整变体未生成：变体资料冲突被当成图片错误

`B0DSSKTXXW` 原始抓取就存在冲突：title 尾部是 White，variantAttributes 为 Natural；当前 family 中 variation_values.color、specs.color 为 Natural，model_number 为 GX11001NA-T-UH，图片也是原木。

九张分类任务都报 source_variant_conflict，理由明确同时承认图像符合 Natural 型号和规格、但违反 White 标题。随后 brief 报 `No current product evidence is available for this child`。

**根因：** 数据源的标题冲突已进入事实输入，变体识别没有合理区分明确的当前子体变体字段与相互矛盾的标题；不是这九张图都错色，也不是单纯 brief 超时。

**最小处理：** 在现有子体事实决议处处理有来源的颜色冲突，并把决议给观察使用。当前子体属性、型号和多图一致时，不允许单独的矛盾标题覆盖它们；证据仍不足时才核对该子体抓取。不可关闭全部颜色冲突保护，也不可把源图重新标成 White。修复后从受影响分类／规划继续，单跑 generate 不能补齐。

### R09 原木浴室柜 func：全局门数误杀局部门数〔确定性程序缺陷〕

`2-Door Lower Cabinet` 描述下部两扇门；整柜已确认三扇门，包括上部一扇滑门。现有规划审查已支持这个局部描述，编译仍报 `display claim contradicts resolved facts: number_of_doors`。

`core/product_family.py:115` 的正则找到任何 `2-Door` 就与整柜 number_of_doors=3 比较，没有部件范围。`core/visual_design_kit_compiler.py:533` 又先运行这项比较，之后才使用文字证据审查。

本次只读复现：`fact_statement_issues('2-Door Lower Cabinet', {'number_of_doors': {'status': 'confirmed', 'value': 3}})` 返回 `['number_of_doors']`。

**最小处理：** 修正现有同一事实比较函数的作用域；整柜对整柜，局部声明用其拥有的部件证据。保留真实矛盾拦截，不通过删除正确文案来掩盖缺陷。该函数同时覆盖抽屉和层板，具有跨类目同类风险；尚未发生的案例只能列为风险，不能计入本轮失败数。

### R10 双柜阻断与双棵树放行：审查对象不一致

同一批出现三种不同结果：

1. 原木浴室柜 `scene_04`：计划确实写两台柜，售卖一台。按当前普通场景规则，阻断有依据；应修正现有计划。
2. 白色浴室柜 `scene_04`：修复后的 draft 已写 `Single freestanding tall cabinet`，并选择 `source_05` 加单柜 `source_00`；repaired 审查仍以 edit base 有两台拒绝，又声称目标计划两台。这是**把源图数量当目标数量**的明确误判。
3. 双棵树 `B0DBHJQZYZ / scene_03`：计划写 `One topiary tree`，审查因源图是一棵而支持，最终只生成一棵。当前审查指令对普通 main／scene 明确使用 sold_unit_count、真实套装仍按套装表达，因此它与项目现行规则不一致。不能称作生图随机漏画，也不能凭本例推导所有单件特写都必须画全套。

`core/visual_semantics.py:670` 附近已经要求区分源图与目标、套装与局部图，问题并非完全没有规则，而是本批审查执行不稳定。

**最小处理：** 在现有审查输入／结论校验中，围绕目标 presentation、role/scope、已确认售卖数量和所选参考进行比较；修复理由必须针对真正的目标。使用已有同轮修复能力纠正冲突。不要另加一套“源图有两件就禁用”的控制器，也不要一律放开套装数量。

### R11 白床主图：过载错误被归为配置失败

实际失败角色是 `B0DSRTM3HX / main`。回执记录 flare 一次、gpt-image-2 候补一次，后者返回 HTTP 400，业务码 `image_account_selection_timeout`，消息为系统过载／账号排队。

- `core/image_provider_transport.py:255` 的暂时拒绝识别没有包含这个业务码。
- `core/image_provider_common.py:269` 的配置错误分类把 HTTP 400 归入 configuration。
- `core/image_generation_executor.py:309` 对 configuration 开该线路的运行期熔断；又因本次已使用候补，当前调用到此结束。不能把全部终止原因简化成“400 直接退出”。

本次离线调用错误归类函数，可稳定复现 `ProviderConfigurationError / configuration`。这不是用户配置错误，也不是图片质量失败；外部拥堵是真实原因，本地归类扩大了影响。

**最小处理：** 在现有传输错误入口按经核实的业务码识别这种暂时拒绝，复用既有重试预算和候补规则。只改具体错误语义，不把所有 400 都重试；也不把“返回明确拒绝”和 524 的未知结果混为一类。不能保证修正分类后网关一定立即恢复。

## 五、撤回和限定上一份审计的判断

### 防倾倒件两张图：不能认定本轮新增安装错误

图 47、55 的源图已经以板件局部和向外伸出的锚栓／螺钉展示套件。生成图主要延续这个表达。源图本身不是完整已安装墙面的证据，不能仅凭没有墙面就断言本次把正确安装关系重绘坏了。

`2 Anti-Tipping Kits` 是数量声明，局部示意只画一个代表性细节不自动等于数量矛盾。也不能要求模型凭空补齐看不到的墙锚与固定面；那会主动造成新的重绘。

结论改为：**源图安装表达有限，不足以验收实际安装示意；本轮未证实新增安装关系错误。** 若后续图的任务明确升级为安装说明，才需要对应安装证据；本次不新增这项流程。

### 审计方法自身的问题

- 旧报告把文件可读、缩略图看起来正常和结构正确混在一起，没发现门覆盖范围、固定入口与可动门的差异。
- 用“文案提到 anti-tipping”推导必须展示完整墙面连接，超出了当前源图证据。
- 把实际主图缺失写成“主图／场景稳定”，遗漏生成失败；把整个原木床变体未形成任务压缩成笼统的规划问题。
- 旧缩略图按组名标示，不能代替子体 ASIN 标识；本次对照页逐张使用真实 child + role。

因此删除旧的 57／3 通过统计，保留可定位的问题记录，不再用剩余张数推算“全部通过”。

## 六、共同原因，以及本轮修复效果的实际边界

1. **结构名词存在，部件归属仍会丢失。** “门、层板、入口”不足以代替门覆盖范围、开放格位置和固定／活动关系；R01、R02、R03 已在不同产品上体现。
2. **有事实值，不等于有正确图示关系。** R04、R06 的数值有出处，端点和替代位置表达仍会错。
3. **现有审查既有漏判，也有误阻断。** 泛泛 supported 不是对输出像素的检查；源图／目标混淆又会把已经正确的修复挡住。R09 是程序确定性错误，R10 是模型审查与目标没有对齐。
4. **单张任务可生成，不等于成套设计有效。** 多个来源的同义卖点和相同功能图重复，问题早于生图出现。
5. **图像模型确实改善了场景、光线、排版和清晰度，也会新增结构。** 本轮多张结构／尺寸问题发生在指定的 sunburst，另一张发生在 flare；样本受角色分配和失败转候补影响，不能据此排名模型或断言某个模型必然安全。

已有改动的作用是把事实、来源、数量、尺寸和候补记录得更可追溯，部分候选也保留了正确结构；本次证据不足以宣称结构重绘、尺寸箭头、文案重复已经解决。继续加长通用“不要重绘”提示词不能替代上述具体修复。
