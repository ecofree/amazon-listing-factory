# 实图未收口问题：最小整改与双渠道验证方案

日期：2026-10-01。

状态：model-share-fixed 已注册并启用；本文件其余代码整改为待执行方案。本轮没有发送付费生图请求。

## 一、结论与范围

当前需要同时修复三件事：目标合同准确表达受保护实例；现有审查能够在已有预算内完成最终蒙版复核；生成服务实际执行保留要求。

前两项有明确代码或合同缺陷，按下面方案修改。第三项必须用固定输入的真实输出判断，不能承诺接入另一 provider 就一定解决重绘。

沿用当前流程：

> 观察与事实 → 子体整套规划 → SAM 区域 → 现有规划审查／局部修复 → 提示词编译 → 生图。

范围保持本次四家族、八变体、74 图位。只到生图，逐图检查。保留当前 SAM 3.1 INT8、四次审查预算、一次区域交互纠错和现有全局并发上限。

本方案不要求逐像素精确分割。必要产品部件要覆盖，正常孔隙、合理遮挡及细边缘误差可接受。

## 三、确定执行的最小整改

### R01：让审查确认当前蒙版，消除支持结论反复改版

**根因：** 当前复核即使只补 `product_depiction` 等其它项，仍要求返回 `region_selection`，随后再次执行 `apply_review`。区域已经返回 supported，也可以换候选或增加确认记录，重新导出内容键，刚取得的审查随即失效。

原木床 func 最后一次有效响应又改变了蒙版选择，四次预算耗尽后没有最终版本复核。这是衔接与收敛缺口，增加次数不能作为主修复。

**修改位置：** `visual_design_kit.py::_finish_image_briefs/compile_reviewed`；`visual_semantics.py::review_planning_bindings/_planning_review_rows`；`product_region.py::apply_review`；`visual_design_kit_compiler.py::design_binding_request`。

**实施：**

1. 区域 supported 表示确认当前实际展示的合并蒙版。要改选择或执行交互，明确属于待修区域，更新后在已有预算内复核。
2. 仅补其它 operation 时，只提交缺失项，不要求重新选择区域，也不执行区域修改。
3. 已审查的像素确实改变，必须重新复核；不得因删除面积小就自动通过。
4. 设计绑定 key 保留底图、事实、目标、共享设计和区域 intent／input_key；删除随候选选择变化的完整 product_region 引用。区域改变只使区域结论失效，不连带推翻无变化的文案和产品关系。
5. 用现有 region_content_key 单独核对实际区域。替换 product_region.content_key 的过宽定义，使其绑定底图、最终蒙版、意图及实例保护归属；纯确认记录变化不重审视觉。完整 reference.sha256 仍校验 artifact；apply_review 的决策缓存父版本使用完整 SHA，防止元数据版本碰撞。同步替换 _export／read_region 的旧哈希路径，提高 policy，不迁移或兼容旧记录。
6. 在现有四次预算内为修改后的最终蒙版保留复核机会。最后一次复核只判断当前版本，不能一边标 supported，一边再开启未复核的新选择。正常的“选择→确认；规划修复后选择→确认”在原额度内闭合。
7. 已耗尽预算的同一输入不重置记录；代码或实际合同修订形成当前新版本，按现有版本规则处理。网络超时、反复漏项或真实复杂纠错仍可能用尽额度，不能承诺全部26图位必然通过。

**删除旧行为：** 对任何补审查强制区域重选；supported 仍无声修改实际蒙版；纯确认元数据导致整个视觉审查失效。

**验收：** 补一条其它结论不会改蒙版；真实蒙版变化仍明确待复核；原木床 func 在当前版本取得最终内容绑定后才能生成。

### R02：按 operation 回收有效结论，补缺项而非丢整行

**根因：** 原木床一次响应漏了必需 `product_region`，使同一绑定其它有效关系同时丢弃；一条文案缺 reason 又消耗补审查。当前逐角色回收还不足以保留同一角色内的合法结论。

**实施：**

1. 在当前解析器与审查结果存储中保留身份、输入和 operation 均有效的 findings；缺失项单独 pending。
2. 同一绑定重复身份、未知身份继续拒绝；重复 operation 不产生有效结论。
3. 补审查只请求尚缺 operation／文案，保留其它有效项。
4. 编译仍要求所有当前必要项有效；事实型文案缺理由、缺证据时仍不通过，不生成默认解释。
5. 玫瑰树 func_02 的标题、两个标签和 func_05 的 product_depiction 一并进入已有待审项集合，不额外增加独立审查阶段。

**修改位置：** `visual_semantics.py::_planning_review_rows/review_planning_bindings` 与当前 kit 的结果回收。

**删除旧行为：** 一个 operation 漏报导致同绑定所有有效项丢弃；重复发送已有效结论。

**验收：** 漏一区域结论时产品关系保持；补齐前不能编译；文案失败只影响实际依赖它的角色。

### R03：将目标数量的精确比较交回现有程序合同

**根因：** 白柜 scene_04 目标明确一柜、蒙版只选左柜，模型仍因源图双柜返回 contradiction。当前提示词已经要求区分，继续增加同义提醒没有可靠价值。

**实施：**

1. 在 design_binding_request.required_facts 投射现有 confirmed fact_resolution 中的 `sold_unit_count` 及证据引用，作为普通 main／scene 整件图的数量约束；编译器和生成指令使用同一个已确认事实值。
2. 不让 Gemini 新填一份售卖数量，不在程序中覆盖它的错误描述来掩盖矛盾。presentation.state 描述所选实例的可见结构与状态，数量由上述唯一事实约束承担。
3. 源图出现数量记录输入场景；不能单独否决已经指定单实例的目标。观察的 object_id 可能代表一组产品，不能把 target ID个数硬当售卖数量。
4. Gemini 继续确定实际选择了哪一实例、是否混入另一柜、结构是否可保留。当前 typed product_depiction 失败需结构化指向具体目标关系与证据引用；销售数量类理由不能冒充结构关系。错类别仅使该项待补审，不自动放行，也不触发无关整套重规划。不得用 reason 字符串搜索“两柜”等词实现判断。
5. 删除由 Gemini 自由文本重复裁决销售数量的旧要求。局部、尺寸图及多格视图沿用其现有范围，多张视图不能当多件售卖产品。

**修改位置：** compiler 的 design_binding_request.required_facts、visual_semantics 的当前 typed finding 解析与 depiction 职责、当前 task／prompt 数量投射。不新增 presentation 数量字段及其整套 schema 分支。

**验收：** 源图双柜、目标一柜、销售一柜允许进入编辑；销售两件却目标一件的普通整件图仍失败；多格细节不误判数量。

### R04：局部修复使用对应部件的实际视图范围

**根因：** `validate_region_intent/prepare` 允许 part 的插图框在整件主图框之外，但 `validate_region_review` 要求所有修复都在主图框内。白床 func 下方排骨条插图因此可能无法合法补选。

**实施：**

1. 修复整件使用该 target 的 crop；修复既有部件使用同 parent 下该 `part_id` 的 crop。
2. `region_repairs.part` 必须引用已有部件；新增部件通过已有 brief repair 先确定归属。
3. 多个视图各用自己的范围，不合成一个覆盖整图的大包围框。

**修改位置：** `product_region.py::validate_region_review` 及现有区域审查输出说明。

**删除旧行为：** 所有部件修复都受整件主图 crop 限制。

**验收：** 白床下方插图的补选被接受；越出插图、跨另一实例或任意命名部件继续拒绝。

### R05：区分错误材料点、未选择候选和真实漏选

**根因：** 原木床 func_03 的凹槽插图正点落在可编辑的小老虎摆件上，同时凹槽木面也漏选。现在用一个零命中错误混合了这两件事，容易把摆件一起锁住。

**实施：**

1. 在已有 overlay／候选图画编号正负点及部件对应关系，不增加审查轮次。
2. 现有 point_diagnostics 显示该部件的候选命中与合并命中。程序负责坐标诊断，Gemini 判断点是否落在真实产品材料上。
3. 同一 product_region finding 明确责任：点错走已有 brief repair；已有候选没选修选择；点正确且没有可用候选才走既有一次交互纠错。
4. 白床凹槽点先核实实际木面，不能为了使检查通过而把整片凹槽连摆件保护。

**修改位置：** `product_region.py` 现有视图导出、审查选择；`visual_semantics.py` 的当前诊断投射／typed finding。

**删除旧行为：** 把全部零命中统一当 SAM 漏选；错误点未纠正就消耗一次交互机会。

**验收：** 凹槽木面有保护，小老虎／时钟／相框可编辑；排骨条等真正重大遗漏不能被批准；不设全点命中率或保护面积门槛。

### R06：让后续选择明确保留已确认部件

**根因：** 当前审查输入包含 selection，却没有明确投射 `confirmed_components`。蓝镜柜 scene 后续选择漏掉此前确认的内部层板，整件候选又没完全覆盖该局部，触发产品支持删除拒绝。

**实施：**

1. 将现有 confirmed_components 与 owner／part／candidate_id 加入同一输入投射。
2. 在当前响应有效性检查中定位候选变更丢掉的确认支持，报出具体部件和删失像素。
3. 另一个候选完整覆盖原确认支持时允许合法替换，不机械要求相同候选 ID。
4. signed merge 继续保底。删除非产品必须有对应归属和反例，不能通过静默并集、裁剪删除或取消保护来绕过。

**修改位置：** `visual_semantics.py` 当前 region_inputs；`product_region.py::validate_region_review/apply_review`。

**删除旧行为：** 让模型看不到确认责任，直到区域应用末尾才报笼统支持删除错误。

**验收：** 蓝柜层板保留；真实产品删除被拒绝；覆盖完整的候选替换不产生新阻塞。

### R07：统一实例保护，删除竞争目标与重绘措辞

**根因与边界：** 原木柜已经改变比例；玫瑰树已经统一姿态。玫瑰树 identical／full upright 是竞争目标风险，尚未证明是唯一根因。当前 selected-instance 编译分支只覆盖 scene，main 仍使用笼统 selected-product 表述。

**实施：**

1. planner／reviewer 的实例规则统一为：同款、同型号表示身份；各实例保留第一编辑底图各自的主要轮廓、姿态、尺度、结构与可见状态。
2. 在已有 revise_plan 中替换玫瑰树的竞争 state，不在后面再堆另一组保真提示。
3. 编译器将已知数量、whole_product、带蒙版的实例保护范围用于 main 和 scene；每个选中实例保持各自原位置、比例和机位。func／size 保持局部及代表视图语义。
4. 当前 edit contract 的通用保护对象指向选中源图实例，已有类别结构事实继续保留。
5. 原木床 func 明确主图保留原有床品，下方现有局部视图展示排骨条；不得把局部插图事实执行成整张裸床重建。
6. 当前 full_redraw 外发措辞改为“从原图重新执行现有编辑合同生成新候选，选中产品继续保持”。删除 EXPLICIT FULL-REDRAW／Redraw a complete candidate 等竞争要求。内部版本模式保持；该入口不是本次两图的实际原因。

**修改位置：** `visual_design_kit.py`、`visual_semantics.py`、`image_tasks.py::_edit_contract`、`image_prompt_compiler.py::_role_content`、`image_generation.py`。

**验收：** 原木柜比例与门／层板关系保持；两株玫瑰树仍逐实例对应原图的主要枝叶姿态；床品可编辑，实际可见床架保持。代码合同通过之后仍需第四节实图验证。

### R08：在现有回执内保留原始返回图

**根因：** 当前 finalized／rejected_content 清理会删除 `.bin`，最先两张镜柜的原始返回字节已经无法事后比对。

**实施：**

1. 既有 receipt 同目录保留 `.bin` 与其已有 SHA；继续清理 `.http/.partial`。
2. 调整 settle_candidate_response，已 finalized 且仅保留 `.bin` 时不反复执行清理。
3. 使用现有回执、候选和最终图关系查询，不新增素材清单或回执权威。
4. 本轮修订后的新请求开始留存，不扫描、迁移或重建历史 jobs，也不重新付费索取已删除原图。

**修改位置：** `image_response.py::finish_response/settle_candidate_response`。

**删除旧行为：** 候选提交成功后删除已付费原始图；将持久 `.bin` 错认作待清理状态。

**验收：** 原始图 SHA 与回执一致；已完成回执可正常结算、不会被再次提交；原始／最终图能独立比较。

## 四、只保留一个有边界的能力实验

### 1. SAM 局部先验：离线条件实验

现有第一次 interactive 主要使用 pure points，先前 semantic 候选没有成为该局部的先验。调用行为已确认，收益未知。

固定现有原木床破碎局部，比较 pure points 与同实例、同部件、同 crop 的合法局部先验；Gemini 0 次、生图 0 次。不得使用全图混合蒙版或其它实例作先验。

只有覆盖更好、没有误锁床品／摆件、没有跨实例时，才在原有同一次 interactive 调用中接入。无收益则保留现行路径，不换整套权重、不扩大测试集合。

这一条件实验不作为其它已确定代码修复的前置依赖。

### 2. 两组 provider 的固定输入实图对照

在 R01—R08 完成且原始图能留存之后，固定两个已有失败样本：

| 样本 | 两组路线使用相同 model 字段 |
|---|---|
| 原木柜 B0H1VSH5GM／scene_04 | gpt-image-2.5 |
| 玫瑰树 B0GG3DF88S／main | gpt-image-2.5-sunburst |

每样本分别用 CXK、model-share-fixed 提交一次，起始共 4 次。每组保留同一原图、同一蒙版、同一编译提示词、quality、size 和附件顺序；只能改变凭据路线。

现有角色路由会覆盖调用方的 providers。实验使用现有测试执行器准备完整任务后固定该路线、清空备用 reserve，沿当前 generate_one／finalize_candidate 执行；不新增生产 pin 参数或控制器。回执路线／model 与预定不符的样本不能用于对照。

这比较的是同 model 字段的两组服务执行，不独立证明代理下游真实模型身份相同。

**停止与判定：**

- 两边仍发生明显主体变化：停止扩量，保留原始回执；不继续随机加词、换模型。
- 仅一边通过：最多在通过路线对两个样本各确认一次，总量不超过 6 次物理提交，失败／重试也计入。
