# 两张互补蒙版对照：实测结果与责任边界

日期：2026-10-17。范围：检查现有其他 provider，选一条路由，仅执行两张互补蒙版诊断；不修改生产代码，不重跑商品图。

## 1. 直接结论

**ModelShare / gpt-image-2.5-sunburst 能生图，但本次两张对照均未执行预期的蒙版保护。**

重绘在**远端服务返回原始图片之前**已经发生。本次实验排除了 Gemini 规划、SAM 分割、本地请求封装漏传／反转 alpha、本地解码换图、RealESRGAN 超分和候选合成作为这两张图的起因。

进一步区分 SubRouter 转发、ModelShare 网页反代适配、实际图像模型执行，仍缺远端内部记录。两张黑盒结果不能证明模型收到了正确蒙版，不能把责任直接判给 GPT 模型。这是已明确的可观测边界，不是继续修改商品提示词的理由。

## 4. 证据怎样定位环节

### 本地发出前：正确

在真实 `urllib.request.urlopen` 调用前旁路保存实际 `Request.data`，不修改请求。解析该 multipart 验证：

- 存在独立 `image` 和 `mask` 文件字段；并非把蒙版当普通参考图。
- 原图逐字节一致；蒙版均为同尺寸 RGBA PNG。
- PNG 优化改变了文件 SHA，但 alpha 数组逐像素不变。
- 两张 mask 的 RGB 完全相同，alpha 逐像素之和等于 255。
- 模型、提示词、质量、背景、尺寸完全一致。multipart 随机 boundary、请求标识不同属于传输元数据。

### 远端返回：错误已存在

- 原始 HTTP 响应单独保存，再验证其中图片字段解码的字节 SHA 与 `native.bin` 完全相同。
- 两张原生图都改动保护区；没有执行超分、局部合成或候选写回。
- 响应 `revised_prompt` 与提交文字一致，但这仅证明响应回显一致，不证明真实模型实际接收了同样文字和蒙版。
- 响应没有真实模型标识；配置中的 sunburst 仍是路由别名。

因此：**当前这条端到端服务的蒙版保护验收失败**已被直接证明；“程序没上传 mask”“SAM 没选全导致这两张失败”“本地超分改坏”被本实验排除。

### 远端内部：证据不足以继续拆分

当前观测同时兼容：转发时丢弃 mask；反代适配时压平／未转换 alpha；执行端收到正确 mask 却未遵循。两次输出的任务区域均不随 alpha 交换，能说明本实验未观察到预期分区效果，不能证明所有情形都完全忽略 mask。

## 6. 最小处理方向

**优先核实并修复远端接口的蒙版语义映射。当前证据不支持继续针对这两张失败修改 Gemini、SAM 或商品提示词。**

将以下两条实际请求绑定到检查：

| 对照 | 平台请求 ID | 上游请求 ID |
|---|---|---|
| A | `20261016232925261663564btg4EPOx` | `5c774db3-5a1c-4f8f-9077-876c3a96e7b7` |
| B | `20261016232955466359545PLXdqrQd` | `5430f741-8fbd-4c2f-8e04-446684ed61c2` |

需要的最小远端证据和处置：

| 找到的证据 | 责任与最小动作 |
|---|---|
| SubRouter 入站有 mask，出站缺失／alpha 改变 | 修网关文件字段转发或 PNG 处理；沿用现有接口 |
| 网关完整转出，ModelShare 适配后丢失区域信息 | 修该商家的网页反代区域编辑映射；仅声明 image-edit 不够 |
| 实际执行端收到正确 alpha、图像对齐，执行端原图已经越界 | 才能归因到该执行模型／版本的蒙版遵循；该路由不能承担当前强保护要求 |
| 执行端原图正确，网关下发图错误 | 修远端输出后处理 |

这不是新增生产流程或扩大拦截，只是本次根因调查所缺的远端边界证据。平台口头“已修复”不能代替上述记录。若服务不提供记录，也应明确记为该路由无法证明 mask 语义、且已实测失败；不能继续当作已验收能力。

白床烟囱／顶盖漏保护是另一个已经观测到的本地问题，仍需保留其修复，不能用本次远端失败抹掉。反过来，即使漏保护补齐，也无法解决这里“完整半幅蒙版仍被修改”的远端问题。

本次两张诊断不证明原商品三张的全部缺陷具有同一根因，不外推所有 provider 或所有 GPT 图像模型都失败。两家其他 provider 的目录可读性与 ModelShare 的两次真实生图分别报告。
