01

审计结论

这不是一份“旧任务为什么没跑完”的复盘，而是对当前设计能否支持下一批新任务持续、可控地完成的判断。最优先的不是再加恢复命令，而是先统一合同、补全事务和业务生命周期。

ROOT CAUSE / 01

语义合同没有真正单源

“允许什么”在规划、生成、QA、界面中多次手写。字段存在不代表每个消费者理解一致。DA01 和 DA02 是直接反例。

ROOT CAUSE / 02

保护有入口，生命周期缺出口

防重复、拒绝过期、冻结范围都正确，但 prepared、预算耗尽、试验升级、新版本替换没有完整的合法状态转换。

ROOT CAUSE / 03

局部权威成立，全局协调仍靠名单

各 owner 有回执和决定，调度却靠字符串和手工列举字段感知变化；新增能力容易不进入唤醒与结算链。

ROOT CAUSE / 04

证据、输出目标、计算依赖混层

完整图库变成完整输出；全文件/全家族/全仓 hash 又代替精确影响范围，既多花钱又多阻塞。

ROOT CAUSE / 05

验证偏重形状，缺少语义与生命周期反例

结构合法、哈希一致、mock 返回 pass，并不能证明实际合同一致、图片正确或整条新任务流程可完成。

优先处理的 9 项 P1

“P1”表示应在扩大无人值守使用前处理，不表示已发生资金损失或安全事故。本轮没有确证 P0 级事故。

应保留的设计：不要把保护机制当作应删除的障碍
  • 保留唯一 production 控制器与事实/规划/候选/QA/发布权威；本轮没有发现需要新增另一个审美评审器的理由。
  • 费用准入有固定域、订单身份、fenced lease、原子预占和未知防重发。应补全生命周期，不应删除这些保护来换成功率。
  • 已有候选不被当作“缺图”；原生结果先保存，本地失败不等于再付费生成。
  • 源图、候选、原始属性、明确文本与模板工件有 SHA 绑定；无轴尺寸和不明确事实不会随意补默认值。
  • 发布同 SHA 幂等、异内容拒绝覆盖，远端成功信息先保存。问题是缺显式替换，而不是应该恢复静默覆盖。
  • 已实现部分成功保留，必要角色与可选资产分开判断；文案返回的任务级失败并不一律阻断有用图片工作。
  • 模板有业务/来源预检，真实枚举和工作簿包完整性核验；未把本地包交付伪装成 Amazon 平台接收。
  • 四类 manifest 独立声明，两柜合法共用 CABINET/storage；“共用基础类型”本身不是混类证据。

本轮纳入

  • 当前 core/products/scripts/schemas/tests 的源码及结构；配置只讨论当前契约与作用域。

  • 全新临时样例、故障注入、25 组机制探针，以及当前默认生产测试套件。

明确排除

  • 不扫描、读取、恢复或迁移过去 jobs/、旧输出、旧账本；根目录名称列表不构成作业内容审查。

  • 不做真实模型质量、账单、线上吞吐、GPU 或安全渗透验收；没有外部 CVE/法规检索。

风险由现有结构和验证范围推导出的设计局限。不当作已证实的结果错误或已知安全漏洞。
P1 / P2P1：先补正确性/安全/核心闭环；P2：计划性改善可靠性、成本和可维护性。优先级与证据强度分别判断；没有伪造百分制成熟度。

目标设计边界

新设计的验收对象应是这些业务不变量，而不是“又增加了几个命令”。它们可以在原有架构内逐步实现。

  1. 语义一致同一 annotation_mode、业务声明与事实状态在所有消费者中的允许/禁止集合一致。
  2. 身份不漂移源证据、输出目标、候选版本、费用请求、人工决定各有独立稳定身份；更换一个不偷偷重置另一个。
  3. 未知不变免费没有结果、HTTP 错误、零 tokens 或本地失败不能自动证明供应商未执行/未收费。
  4. 局部隔离完整库存仍保留；执行失败与当前性按真实依赖传播，而不是因为共享一个 JSONL 就全停。
  5. 可恢复事务每个 prepared 状态都具备明确查询、续做或安全退出，不要求手改 canonical 文件。
  6. 明确决定可观察领域操作成功后，状态与调度可准确识别一次完成；自然日志变动不是新授权。
  7. 查询无副作用预览、状态、当前性检查不结算、不写 marker、不购买模型；命令才承担持久化。
  8. 门槛前置可确定的本地依赖、输出容量和配置错误，在新增不可逆付费动作之前暴露。
  9. 同 SHA 幂等，异内容有事务既不静默覆盖，也不让正常迭代永久卡死；原版本和原接受保持可追溯。
  10. 验证不夸大工程接入、默认套件、模型硬事实 QA、人审、完整交付、Amazon 接收分别记录。

不建议的整改方向

  • 不新增自动重生器、自动 unknown 重发或第二个审美模型来“提高通过率”。
  • 不通过新工作区、新订单或换缓存键消除已用预算和未知结果。
  • 不为修复混乱而一次性微服务化、重写整个项目或引入第二套状态控制器。
  • 不把所有错误都改成 pass/默认值，也不通过删掉未完成子体、角色或证据降低分母。
  • 不把“全仓统一哈希”当成所有阶段的语义依赖，也不只从哈希删字段却仍发送完整旧上下文。
  • 不把 100/100 测试通过、SAM mask 或生成模型自述当作真实图片质量证明。
