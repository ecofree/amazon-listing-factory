# 剩余阻塞与真实验收工作计划

依据：[当前实施记录](IMPLEMENTATION.md)、[当前操作合同](OPERATIONS.md)。本次只制定计划，不执行网络、真实J写入、账本切换、授权消费、模型请求或发布。

目标：解除有依据可解除的阻塞，修复浏览器验证环境，再用原2子体17槽证明完整上架包。最后一步仍不包括提交Amazon。

## 一、先分清三类事项

1. **真实业务资料／模板适用规则**：不是代码可以猜出的值。必须先取得依据，再让原field plan判断；不能把“未知”批量改为false/Not Applicable。
2. **浏览器启动超时**：目前是隔离环境／工具链验证失败，不等于已证明页面有错，也不等于页面通过。先最小化定位，再测合成工作区。
3. **真实图与整包验收**：涉及真实状态、供应商和存储费用。必须单独批准范围和上限，不能借用过去授权或把离线测试当通过。

业务资料和浏览器环境两条线可以并行；真实生产必须等待静态门和执行授权满足。

## 二、阶段A：把缺项变成少量、可回答的问题

负责人：编码助手。

- 使用原J的明确输入副本、当前实际XLSM及同一template_field_plan重新生成诊断。
- 上次结果是business缺4／条件未决6，source缺9／条件未决178；178是行×字段，不能理解成要用户回答178个问题。
- 对每项记录：field/group、受影响SKU、缺值或未知条件、当前证据、证据缺口、是否可程序推导、负责提供者、阻塞阶段。
- 分为四类：已有数据可确定；卖家必须声明；模板规则需查证；真正单品冲突。
- 复用已确认值：safeplus/US/artificial_tree GTIN豁免、数量2/1、合法NUMBER_OF_ITEMS和Count类型修复。不重问、不编造GTIN，不重猜变体主题。

### A2. 一次收集真正缺失的业务依据

负责人：用户／运营提供，助手整理为输入档案。

|资料|所需粒度／要求|
|---|---|
|商家身份|明确seller_id；品牌不等于商家账户|
|制造商、产地|适用产品／SKU及来源。先复用已有有效配置／资料，只确认缺少依据或发生变化的部分|
|库存|两个实际SKU分别的可售数量，注明库存系统／核对时间和valid_until；不能把2件装的“2”当库存|
|履约、状况、运输模板|真实账户设置；不自动默认FBM/New|
|商家价格|逐SKU明确价格及币种／有效期，或明确允许使用来源List Price的策略；来源价格不是本店定价许可|
|电池、内置灯、危险品、包装层级|产品／供应商资料或明确业务声明；“仿真树”本身不是不适用证明|
|其他合规／适用条件|只问缺项矩阵确认需要的主事实；不预先要求用户填写全部FCC/Prop65等字段|
|图片URL合同|至少需要可用多久、对象保留到何时、验证窗口与保留政策依据|

只在隔离副本生成business-input-v2；数量／价格按准确seller+family+SKU绑定，动态资料有时效。检查0和false被保留，未知不被自动替换。

通过门：用户提供的真实资料已转成可复用档案，无跨SKU误用、无无来源默认；尚缺资料单列，不假设已补齐。

### A3. 查证模板条件，不用常识代替平台规则

负责人：助手查证，用户／运营确认账户特有条件。

证据优先级：当前工作簿说明／有效值 → 当前适用的Amazon官方字段或类目规则 → 账户设置／供应商资料 → 无法确认时保留异常。

- 需要联网或登录查询时先明确只读范围，沿用浏览器安全流程；不提交listing，不调用模型生产，也不把登录操作默认为执行授权。
- 每个根因保存规则来源、日期、template SHA、US marketplace、product type、触发条件与使用的主事实。
- 能推导的条件编译进原field plan；个别人工处置记录必须绑定SKU和事实版本。
- 不因“没有看到电池／证书”推断不存在；不把模板只写Conditionally Required当成可选。

通过门：同一正常scope不再逐格人工；本家族静态必填缺值／非法值／未知条件全部得到有依据的处理。尚无图时，只允许明确的copy/publish等上游依赖等待。若规则仍无法确认，留在阻塞清单，不进入付费生产。

## 三、阶段B：修浏览器验证环境（与A并行）

负责人：助手；用户只在确需环境权限时介入。

### B1. 定位启动卡点

- 保留两次失败日志，不延长超时反复碰运气。
- 依次验证：CLI本地诊断 → 独立浏览器空白页 → 最小localhost HTML → 合成工作台。
- 每一步检查进程退出／CDP就绪／stderr／超时点；特别核查Windows启动器参数、独立profile目录、必要APPDATA/LOCALAPPDATA/TEMP环境、代理与域名限制。
- 一次改变一个变量。固定已有浏览器版本，不擅自下载安装、不修改系统代理、不接管日常登录profile。
- 浏览器和服务端使用独立目录、无生产凭据；网络只允许loopback。只关闭本轮创建的进程／会话。

通过门：从全新空profile可重复启动，加载localhost成功，结束后无本轮遗留进程。

### B2. 合成工作区交互验收

不启动真实dispatcher，不操作真实J／账本。使用合成订单和本地服务，验证：

1. 列表、心跳、费用未知、异常分组、归档／当前资格区分。
2. 业务表单未知、0、false及逐SKU值；错误输入和过期页面拒绝。
3. 具体receipt处置的默认未勾选风险确认；重复点击／回调幂等。
4. 来源SHA变化、非法路径、错误Origin/token拒绝。
5. 规划本地恢复／具体授权／独立次数授权不混成一个按钮；测试仅限合成数据。
6. 仅发布刷新确实只排publish/template，不排generate。
7. 当前资格失效不毁历史归档；归档损坏不能下载为成功。
8. 桌面和窄屏、控制台错误、网络请求清单、截图。

通过门：关键交互有证据，JS无未处理错误，远端请求0、真实授权0、真实生产状态变更0。工具环境若仍失败，只能标“受限未验”，不能用HTTP单测代替整页交互通过。
