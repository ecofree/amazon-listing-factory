# func 与 size 提示词构成审计

## 结论

当前 func／size 提示词包含必要的事实、编辑和设计约束，但组织方式存在三项主要问题：**保护规则重复、所有任务携带同一组具体故障说明、辅助图的完整产品描述进入局部任务。** size 比 func 长，主要因为尺寸关系逐项展开；不能靠删除尺寸主体、标签、来源和端点关系来缩短。

最值得调整的是现有编译器如何表达已验证的任务，不是增加新的规划、分割、QA 或再调用一次模型。长度只是诊断指标，不能当质量判据。

本轮只做审计，未修改生产代码、未运行生图、未调用 Gemini、未运行测试套件。新增的是本报告及隔离的长度分析脚本／文本快照。

## 1. 范围与统计口径

检查了当前 `image_prompt_compiler.py`、`image_tasks.py`、`image_reference_context.py`、`image_task_inputs.py` 及相关规划约束。

样本为 20260927 冻结材料中的 28 个 func、8 个 size。使用当前编译器，并按当前类目配置重新投影编辑合同，仅用于分析；**没有升级历史任务为生产输入，也不表示这些样本已经经过当前 Gemini 规划和审查。** 对黑柜层板和仿真树尺寸源图进行了目视核对。

更正上一条长度回答的口径：此前只重跑提示编译函数，保留了样本中的旧 edit_contract。此次同时按当前编辑合同投影，13 张 func 的可选道具说明各增加 53 字符，故 func 的范围和平均略变；size 不变。

| 角色 | 样本数 | 最短 | 最长 | 平均 |
|---|---:|---:|---:|---:|
| func | 28 | 5,118 | 6,694 | 5,707 |
| size | 8 | 6,217 | 7,079 | 6,630 |

单位是包含空格／换行的字符，不是 token。成套规划更新后，具体长度还会变化。

## 2. 实际提示词由什么组成

所有提示由同一个 `compile_task_prompt()` 生成，固定按五段输出。每张图另有 65 字符的版本头及间隔。

| 段落 | func 平均字符 | size 平均字符 | 实际内容与来源 |
|---|---:|---:|---|
| ROLE | 2,208 | 3,514 | 编辑任务、保留项、visual_goal、presentation.state、替代状态规则、各参考图 Observed 事实、已选尺寸关系 |
| REFERENCE | 1,286 | 1,157 | 附件顺序及权限、产品身份／颜色／销售数量、允许改动、类目规则 |
| STYLE | 1,158 | 1,142 | 摄影要求、环境模式、所选非产品组件、字体与图形色彩规则 |
| TEXT | 892 | 653 | 授权文案规则、尺寸标签例外、品牌／物体文字边界、标题与标签角色、实际文案块 |
| OUTPUT | 97 | 97 | 输出一张方图、不输出解释／水印 |

四舍五入可能造成总和差 1 字符。

### 2.1 程序、Gemini、源图各负责什么

- **程序固定模板**：编辑而非重建、主体保留、首图／辅助图权限、禁止擅增文字、尺寸关联解释、输出格式。
- **类目配置**：床梁护栏、柜门合页、树冠盆等保留范围；可替换道具和角色要求。
- **Gemini 既有规划产物**：本图目标、展示状态、参考图选择、测量选择、文案、共享摄影／字体／图形设计。
- **源图观察与事实合同**：各产品部件的 physical_facts、已选测量数值及测量对象、产品身份和销售数量。

这些信息不是全部由生图模型自己决定，但最终被编译成连续自然语言，模型仍需理解相互权限。

### 2.2 func 与 size 的核心差别

**func：** 必须表达已证实的功能及演示关系；28 张中 6 张选了尺寸，因此 func 不是一概不允许尺寸。其余 22 张收到“不转移源图尺寸／不新增尺寸箭头”的规则，授权文案中的数量另有边界。

**size：** 8 张都有具体 measurement_groups。每条输出大致为：

```text
被测部位 / 轴向：显示值（证据 ID；源图附件序号；证据类型）
```

例如黑柜：顶冠宽 23.5″、顶冠深 8″、整柜高 28″、不同隔层的三个 8.5″分别列出。多个相同值不代表同一个位置，不能按字符串去重。

可见文案块本身很短：func 平均约 103 字符；size 平均约 21 字符。size 的尺寸标签放在 ROLE 的测量关系里，因此 21 字符不代表图上只显示这些字。大部分长度来自执行说明、设计说明和事实关系。

## 3. 主要发现

### F01：同一主体保护职责在多段重复

证据位置：`core/image_tasks.py:354`、`core/image_prompt_compiler.py:353`、`:371`、`core/image_reference_context.py:159`。

同一提示先要求直接编辑附件 1，再列主体 geometry／joins／viewpoint，随后说不重建整件、保留源图状态，再在附件总说明、附件 1 说明和 Reference authority 重述首图权限。功能／尺寸通用段又重述安装面与连接保护。

这些大多同向，并非每一条互相冲突，但会增加阅读负担、维护成本，并让同一职责在不同位置逐渐出现不同版本。不能证明“重复本身必然造成重绘”。

**处理建议：** 一处说明主体／机位／安装关系保护，一处列附件用途；其余段落只表达本图新增的具体信息。保留类目中真正特殊的实体关系，删除对通用保护句的同义复述。

### F02：具体历史故障说明被无条件用于所有产品

证据位置：`core/image_prompt_compiler.py:382`、`:444`。

- 36/36 张 func／size 都收到“同一部件的替代位置互斥，未占据位置用图示，不画额外实体件”。即使本图没有调节位置或状态切换，也发送。
- 14/14 张带尺寸的图均收到“不同高度不能终止于同一栏杆底面”“相邻孔距不能画成层板厚度／隔层”的说明，包括仿真树的球冠和花盆尺寸。

**这是已确认的模板适用范围过宽。** 无关文字是否实际导致某张重绘，尚无受控实图证明。

**处理建议：** 通用模板只保留“数值必须绑定各自被测对象及真实端点”。本图确实涉及替代层板、上下间距等关系时，在现有 state／measurement 描述中表达。不要再新增每类产品一串关键词分支，也不要直接删去真实任务需要的互斥状态信息。

### F03：局部任务仍接收辅助整件的全部观察描述

证据位置：`core/image_reference_context.py:85`、`core/image_prompt_compiler.py:386`。

source_reference 将该图的 product_features 全部带入 visible_evidence；func／size 的编译器对 edit_base 和 product_evidence 逐项串联 physical_facts，没有按本图选定的功能关系筛选。平均 Observed 段约 430／421 字符。

本组 21/28 张 func、5/8 张 size 有两张附件；其中 8 张 func 是 detail_only 加整件辅助。比如只演示床下净空，仍带入整张床的整体描述；黑柜层板图又描述整柜门面、顶底饰边和下方开放格。

**风险：** 已有观察事实在生图端可能成为第二份产品重建描述，与“只编辑这一局部”的主任务竞争。上一轮摄影实验已证明同路由会受辅助机位干扰，但不能据此断言这 26 张多附件 func／size 都失败，也不能删掉所有辅助图。

**处理建议：** 在现有规划选择中仅使用确有缺失事实的辅助图；将本图需要强调的关系收敛到已有 state，并由原有审查验证。完整观察保留在审计证据里，执行提示只投影必要内容；不是删除上游观察，也不是让程序凭词表猜哪些事实重要。

### F04：尺寸 ID 很明确，具体端点描述仍取决于上游语义质量

证据位置：`core/image_task_inputs.py:33`、`core/image_prompt_compiler.py:444`。

程序按 measurement_ids 取选定尺寸，保留对象、轴向、数值、source_id、occurrence ID 和证据类型。它没有把原始坐标当新图坐标，这一点合理。

但提示内不是每条都有清晰的起止面。有的行很具体，如“rail bottom”和“slat level”；黑柜上下两条调节距离的被测对象都叫 `internal shelf adjustment increment`，差别主要在 `_up`／`_down` ID 和源图中。模板同时告诉模型“ID 不是位置证明”，因此正确端点仍要从源图及 state 理解，不能说合同已经程序化锁住端点。

**处理建议：** 保留来源、数值、被测对象和重复位置的独立身份。优先在现有观察对象描述／规划状态中写清语义端点，比如“中间层板位置至上方可选位置”，再由原有审查验证；不要强加所有任务填写坐标的新门槛，也不要拿一段笼统‘端点正确’代替具体关系。

### F05：授权文字没有明显逻辑矛盾，但表达分散且规则过长

证据位置：`core/image_prompt_compiler.py:205`、`:219`、`:444`。

现在 TEXT 指定完整 authored copy，同时明确说尺寸标签在 ROLE 单独授权。这是有意区分标题／功能文案和尺寸标签，**不能直接判作双权威冲突**。数值来自 measurement_authority，也不能说是模型自由编造。

问题是模型需要在 ROLE、TEXT、Observed 和图片原有文字之间理解哪些能显示。文字规则本身约数百字符，实际文案反而很短。样本黑柜层板图还在正文解释 1.5″，并要求上下两处尺寸标注 1.5″；这是有意义的不同用途，不能全局“文字只出现一次”式去重。

**处理建议：** 将通用规则压成“只显示授权文案和已选尺寸；源图其余宣传文字不转移；尺寸按各关系出现”。现有文案与测量合同保持不变。重复数值按位置保留，重复营销句则在既有成套规划里处理。

### F06：设计部分有压缩空间，不能全部视作噪声

证据位置：`core/image_prompt_compiler.py:397`、`:413`。

STYLE 平均约 1,150 字符，含字体、7 个图形角色值、文字墨色／线条墨色边界、标题底板限制。这些承担成套设计，不能一刀切删除。可以将反复解释压成一次短约定，保留角色与值。

冻结样本的 photography_direction 还包含产品木纹、漆面和五金高光，而外层句子限制其只作用于非产品环境；对 graphic_canvas 又会出现“中性墙面阴影”与“不布置房间”并列。前一轮已修改新规划说明，要求不复述产品 finish；本轮是旧设计投影，不能据此宣称新 Gemini 仍持续产生同样内容。

**处理建议：** 先验证新规划是否遵守已有摄影字段职责。不能靠程序删除材质关键词来掩盖规划问题；技术底图的排版、配色和真实产品材质仍要分清。

## 4. 一个附带的长度边界事实

`PROMPT_HARD_LIMIT_CHARS = 8000` 当前被候选修订 `_compose_revision_prompt()` 用作剩余字符预算。普通初次 `assert_prompt_contract()` 没有统一的 8,000 字符检查，因此不能把这个常量称为所有初次生成都受执行的硬上限。当前 36 个样本都低于 8,000，不是本组已发生的超长错误。

不建议为此次精简增加“超过某字数就阻断”或直接截断：截断可能优先丢失尺寸及文案信息。应先删除重复说明，保持事实完整。

## 5. 最小调整顺序

1. **先精简固定模板**：合并保护／附件同义说明；将通用尺寸规则改为通用端点关系，保留本图必要特殊关系。主要落点是现有 prompt compiler、edit contract 与 reference prompt，不增加模块或控制器。
2. **再核对执行内容**：现有规划只选必要附件；完整 Observed 证据不自动等于本图必须输出的内容。保留 source／fact／measurement 审计链，不能静默移除必需证据。
3. **按关系验证，不按字数验收**：至少覆盖无尺寸 func、带上下重复尺寸的 func、detail_only 加辅助图、包含多个相同数值的 size；比较同一输入下提示投影及实图。只有确认有改善后才扩大测试。

暂不承诺 func 必须压到 2,000、size 必须压到 3,000 字符。简单三维尺寸与十项柜体尺寸天然需要不同信息量。验收应是“无重复权限、无无关案例指令、关键关系无丢失、实际输出正确”。

**需要保留的核心：** 首图编辑边界、销售实体归属、当前演示状态、必要事实和安装关系、已选尺寸与端点对象、授权文案、成套设计参数。可删的是围绕这些信息的重复解释和不适用于本图的故障案例。
