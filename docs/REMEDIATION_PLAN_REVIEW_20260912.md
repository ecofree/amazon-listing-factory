上次给出的整改方案仍有缺项和顺序风险，不能原样实施：

1. 不能把“结构审核缺失”统一扩大为所有 main/scene 的新增前置失败门槛；应限制确实依赖未确认结构的操作。

6. R7 应区分“当前支持证据选择过粗”的修复与“允许跨 source 另选完整展示视图”的能力扩展，避免一次改坏已明确的编辑边界。
7. 当前已有 9 图到草稿模板的实测；报告中“新版未跑到模板”的证据边界需要更新。但正式图片放行和多任务吞吐仍未验证。

建议实施顺序：**P0 事实与执行语义、QA时限 → P1 付费结果恢复与本地资源保护 → P2 现有调度器并发收敛 → P3 设计参考与视觉校准 → P4 干净冻结验收**。P3 的素材准备可与 P0–P2 同期进行，不是其前置依赖。

## 4. P0：事实、执行语义与 QA 时限

### P0.1 让一次审核的结果正确控制对应操作

修改现有 `review_planning_bindings → _finish_source_briefs → compile_visual_design_kit_response`，仍保留一个审核调用、一份结果和现有局部修复预算。

在结果内用逐项 finding 区分 physical_structure、measurement、copy_fact、design_binding；每项说明对应 source/view、具体观察、所影响的操作及结论。名称为实施建议，不额外建立 product-fact-review 控制器，也不复制新的产品事实权威。

- 确定改变产品、遗漏关键结构、错误归属、错误尺寸端点：相关 brief pending，现有局部修复消费同一批发现。
- 结构合并、隐藏独特视图、局部扩整体、状态迁移、风险裁图承担复杂结构证明：必须有支持该操作的真实证据。缺失或 inconclusive 不授权该操作。
- 保留可靠原始可见视图的一对一编辑、没有上述操作、没有已知事实冲突：普通设计判断缺失不新增全局阻塞；未核实内容明确保留，最后 QA 仍负责实际成图事实。
- 单纯“好不好看”、不同语义组件是否必须同色、风格偏好：交给既有人工设计评审，不转成硬事实失败。
- 全新物理状态若源图根本没有证据，即使审核模型声称 supported 也不能超越引用范围。

高风险与否应由真实引用、视图 disposition 和已知证据风险决定，不能允许规划模型自行标记 low-risk 逃避审核。局部任务 pending 不使其他 child 或可靠任务停止；约定数量仍完整列出。

同步修正审核缓存身份：绑定主源与被选辅助源的 SHA、source/view、实际裁图、用途、角色方案、共享设计和审核策略。C10 表明仅改辅助选择时当前 key 不变，必须清理这一遗漏。

### P0.2 修正证据范围与附件选择

沿用 `physical_views` 和已存在的裁图 provenance，计算实际像素宽高、面积及用途风险。不为每张图片新增独立视觉请求；把风险与本图打算证明的特征送入已有审核。

对细窄纹理特写保留有效用途；对无法证明抽屉形状的竖缝拒绝赋予该证明能力。明确区分“8 根板条这个文字事实”与“有完整 8 根板条的可见几何证据”。

辅助证据按被选 source/view/feature 精确传递，替换当前“选中 source 就附上其全部视图”的行为。身份始终使用 child＋source＋view，避免不同源的 view_01 混用。保留尺寸所需的原始测量端点证据，不能为了减少附件删除这些证据。

对标题或图形覆盖产品的源图，程序不能擦除后当作事实证据。优先使用同 child 的真实干净视图；没有时保持可证的局部用途或相关任务待处理。

跨 source 选真实 whole_view 的后续支持应在同一 brief 明确展示源和细节源，保持数量和状态。它需要同时替换 supporting-only 的旧限制、主参考选择和 QA 目标映射；不能偷偷在生图端换主源。本轮基础闭环可以先完成，不以该能力全面建成为前置条件。

### P0.3 替换 prompt 的错误作用域，不按字符数裁剪

保持当前单一编译器和 ROLE / REFERENCE / STYLE / TEXT / OUTPUT 结构。各语义只有一个负责输出的位置：

| 语义 | 权威与投影 |
|---|---|
| 商品身份、可见结构、状态、归属 | observation/产品边界，经 REFERENCE/ROLE 按当前视图引用 |
| 构图与信息阅读顺序 | Gemini creative_brief、evidence_usage；程序如实投影 |
| 房间、光照 | child 共享设计；仅对适用角色传房间字段 |
| 床品、内容物、道具颜色 | child 逐对象设计；本图存在且允许编辑就传递，不依赖是否造房间 |
| 字体、徽标、线条及背板 | child 图形语义分配，func/size 使用同一来源；允许不同语义有不同色值 |
| 显示文案 | display_copy/renderable-text；创作说明不再次增补显示文字 |
| 尺寸 | 原测量对象、数值/美制单位、轴和端点；不能被风格描述覆盖 |

具体替换：解除 `_presentation_system` 对 scene_objects 的 environment 总开关；`_family_art_direction` 的“无房间”语句不得暗示去除当前床品；`_product_boundary` 投影本图的 part_of、contained_in、occludes，避免模型重新猜归属。source_setting 保留有事实意义的位置关系，并在允许范围内继承非商品对象设计。

不恢复固定色板。ColorAide 等继续诊断 Gemini 的实际选择，不能因为数值合格宣称审美合格。不同 child 可以不同路线，统一性要求在同 child 内。

当前 prompt 实测：main 4392 字符，scene 3931–4044，func 4930–6312，size 5144。修改时输出旧/新最终 prompt 与语义归属差异，删除对应冲突句；不设统一字数硬上限、不截断事实、不把完整关系图重复塞入多个段落。

### P0.4 处理 QA 的真实时限问题

`observe_candidate` 仍显式给出 timeout_seconds=50、total_timeout_seconds=50、max_physical_requests=1。上轮唯一成功观察耗时 45.719 秒，另两张约 49.8 秒超时。这支持“时限过紧可能显著参与故障”，不能证明只要加长就必然成功。

移除这处独立 50 秒覆盖，复用当前视觉 scope 的有限请求预算，并受 QA stage/job 截止时间约束；保留请求数约束。当前通用调用默认请求预算 120 秒，可作为首轮校准起点，不能再从旁追加一套角色时限控制器。

当前只启用了 NUWA 的 vision_qa 路由；禁用路由不能静默启用。QA 失败后只补现有候选的观察，不重规划、不重生图。当前无 observation 的 unavailable 缓存本来就可以重试，这条能力应保留。

现有健康管理需区分请求内容、账号配置错误、未出站排队与暂时读取故障。账号鉴权失败继续明确停止该路由；瞬时超时可在原预算和同一 health 管理中有限冷却、最多单探测恢复，不能每张反复重试，也不能新增后台探测服务。预算耗尽保留待验收候选及缺项。

P0 验收：C1/C4/C5/C6/C7/C10 对应反例按用途得到正确结果；普通无冲突编辑继续；现有 QA 不再被额外 50 秒固定值截短；恢复 QA 的场景不会新增生图请求。

## 5. P1：先保护付费结果，再保护本地处理

范围：现有 routing worker、executor、candidate_state、image_upscale 与内存/文件 lease。P1 完成前保持现有并发规模。

### P1.1 修正远端、本地错误的归属

将 `_generate_admitted` 中远程调用与本地 finalize 的异常处理边界分开。远程有效响应已经到达后，本地 OOM、磁盘写入、放大和候选提交错误只进入本地恢复，不能继续 for-provider 循环。

源自远程内容的无效画布仍可按当前有界规则处理；不能把所有输出验证错误统称本地错误。关键依据是错误发生阶段与保存的原始响应，而不是异常文本中出现“image”还是“provider”。

### P1.2 把已有临时结果改为可恢复结果

当前 `_provider_worker` 会写 `.partial` 并原子替换临时 `.bin`，父进程读取后在 finally 无条件删除结果。这降低进程通信开销，但无法支持放大前后崩溃恢复。

改为现有 task/attempt 作用域下的 job-owned 原始响应文件，关联现有 request audit：logical task、attempt、请求及引用指纹、provider、远程请求号（若返回）、raw 路径、字节 SHA、结果是否完整。原始结果是处理材料，不能作为已接受图片，最终候选仍只有 CandidateManifest 一份权威。

worker 在报告成功前完成原始结果和绑定信息的持久化；父进程队列传递小记录和路径。删除“返回 bytes 后立即删临时结果、失败再请求 provider”的旧生产路径，不留双实现。

恢复必须覆盖：

| 中断位置 | 现有 generate 恢复行为 |
|---|---|
| 明确未出站 | 可重新准入，物理请求数保持真实 |
| 已出站、结果未确定 | 保持 unknown；若接口提供查询则使用原请求标识；无法查询则明确待核对，不盲目重发 |
| raw 完整且绑定可核实 | 仅恢复本地放大/提交，原物理请求数不增加 |
| raw 文件有但绑定不完整 | 核对已有 attempt/记录；不可按文件名、修改时间或“看起来像”自动认领 |
| 最终文件/manifest 已部分提交 | 复用当前不可变候选的原子恢复逻辑，防止重复提交 |
| 候选已提交、QA中断 | 只恢复 QA，已有候选不可原地改写 |

不把所有历史失败统一改成 unknown。新旧策略按有效指纹隔离；旧产物保留证据属性，不能默认为新生产输入。

### P1.3 GPU、内存和磁盘准入

本地放大用实际设备级的跨进程 lease，首轮单设备 1 个进程。该限制不能按 CXK/AICOST alias 分开。使用已有锁设施实现，不启动新服务。

在发出付费请求前为预期响应、磁盘缓存和后处理峰值保留合理额度；低内存先暂停新准入，让已有成功结果继续落盘与收口。最终处理应有可用的保留预算，避免“远端任务拿着内存等待 GPU，GPU任务又拿不到内存”的相互等待。

复用同一内存准入，把系统 available 与已承诺但尚未体现在 RSS 的峰值区分；不要既从 available 扣实际占用，又重复计入全部活动任务。不能只通过改变 semaphore 的动态 limit 就声称完成可靠字节预留。

待放大结果设条数与字节上限，并计入已在途的预留。初始 4 张只是基准候选值，需要由实际原始字节、最终处理内存和磁盘决定。正常完成后才能按现有保留策略处理自己的临时结果；不以空间不足为由清理批准候选或未知付费结果。

保持 Real-ESRGAN x4plus 和 1600×1600 最终交付合同。设备选择、tile、线程、30 秒放大预算和 PNG 压缩参数先用隔离本地样本测量后再定。不得通过增加 Lanczos fallback 提升表面速度，也不直接把 x4 模型参数改成 x2。当前 9 张均成功放大，没有证据支持立即更换放大器。

P1 验收：本地 OOM/磁盘失败均不增加模拟远端调用；raw_saved、manifest提交前后故障可恢复；跨 job 的同 GPU 限额成立；低内存不会杀死已经出站的请求。

## 6. P2：在现有调度器内释放吞吐

执行边界仍为 `generate`，不新增 CLI stage、daemon、第二个 job 状态机或 feature flag。内部将远程等待与本地 finalize 作为同一逻辑任务的执行状态，由当前 `_execute` 管理有限工作集合，任务最终完成仍以现有候选提交为准。

1. 删除 `used_lanes` 对整个 child 的在途互斥；同一 child、同一冻结设计下，不同 logical task 可以同时工作。同图同一 revision 仍唯一在途。
2. 派发位置按账号 `resource_group` 计数，补齐全局策略、角色能力、mask/多参考支持与主机资源共同约束。真实 provider lease 保持跨进程权威。
3. 保留 photo/infographic 的角色模型偏好和一致性，当前 child_provider_lock 只能表达路线偏好，不能继续成为全 child 互斥依据。若失去实际用途，应删除字段和测试。
4. 容量计算考虑已获准兼容 route 的可用集合，不能只看当前 primary；不要求七八个 alias 全部并发。备用组空闲且请求尚未出站时可派发已配置兼容路由，明确记录容量改派。
5. 远程成功持久化后释放远程 worker 的占位，使其他适合的任务出站；后处理用有界本地执行能力，仍通过同一个 `_execute` 收口。不能在 worker 内继续等待整条放大链后才补下一个远端任务。
6. 资源不足为 queued/deferred；0 次出站不计 provider 失败。全部可用资源为零时有界等待并按现有截止时间保留 retryable，避免空轮询或等待所有图片齐全。
7. 继续保留 unknown 不自动重发，停止/取消能够记录已在途结果。任务顺序兼顾已排队时长和可用资源，防止同组 alias 的队头占位饿死另一组。

当前配置宜先测 CXK 1＋AICOST 1、本地 GPU 1。增加 provider 后并发由新 resource_group、实际额度和主机预算共同增长；只加同账号模型不增加并发。若只剩一组可用则降为一组；若任务不符合剩余模型能力，明确排队/待处理，不能静默降低图像模型能力。

账号槽当前已经在远端返回后释放，真正需要改的是调度 worker 与本地链耦合。P2 不应为“释放账号槽”重复增加一套锁。

P2 验收：同 child photo/infographic 在两账号上的真实开始结束区间重叠；同账号 alias 不挤占另一账号位置；1/2/N 组和无可用组均有明确结果；慢 GPU 时缓存不越界；付费次数没有因并发增加。

## 7. P3：设计参考与实际视觉校准

保留 Gemini 对美学的决策，程序按当前真实产品事实限定执行范围。P3 解决的是设计质量与参考有效性，不作为所有正常任务的全局硬门槛。

- 首批床架、柜体各选少量摄影、func、size 参考，实际检查完整画面、信息层级、手机尺寸可读性和权利范围。对只有字体局部的裁片，仅赋予局部用途。
- 用户此前授权助手筛选“本轮测试参考”，可按该明确范围记录助手审核；不能扩写成 project-owner 批准或长期商业素材授权。当前 draft 包不自动恢复为 approved。
- 在现有设计包中使用真实审核记录、SHA 和适用角色。没有获批素材的任务保持现有 autonomous/no-reference 状态，无需等待整个素材库建设。
- Gemini 围绕该张图片的购买问题选择视觉中心、真实证据呈现、说明顺序及配色；程序不能用胶囊模板、固定圆框或源海报布局替代其设计。
- 子图固定的是同 child 的语义组件和对象分配。不是所有文字都必须同色；相同标题角色、图标角色、尺寸箭头角色的分配应一致。不同 child 可以设计为不同体系。
- 保留源图所有有效功能与尺寸证据；新设计不必继承旧商品海报的颜色、标题条、道具组合与排版。
- 先确认参考作用和基础结构，再做规划模型能力对照。不要同一轮同时换参考、规划模型、生图模型、后处理和并发，导致无法归因。

跨 source 的完整展示能力若实施，作为 P3 内一项明确的证据选择迁移：一份 brief、一个编辑合同，真 whole_view 负责整体、原 detail 负责细节；测量对象和状态分别绑定，完全删除原“不许用辅助整体”的冲突语句，并同步 QA 目标。没有真 whole_view 的图片仍不授权补全。

## 8. P4：有界、干净、能归因的冻结验收

这是一次整改验收安排，不增加到每个产品的日常生产步骤。当前请求仅为方案审计，本轮未发起以下付费测试。

### 8.1 先做非付费行为验收

在当前生产套件对应测试中替换错误或过窄的断言，不照搬 ZIP 的 22 场景新增 22 个默认测试。当前预算保持不超过 100 项、60 秒。

必须覆盖：结构未核实的合并与无风险编辑的区分；同 feature ID 不代表不同像素已覆盖；graphical canvas 仍有床品；容器/部件关系改变；辅助选择使审核失效；本地失败零新增远端请求；raw恢复；同group alias、多账号、无资源、慢本地、未知远端和取消恢复。

现有 `test_local_repair_keeps_view_inventory_and_rejects_uncovered_feature_ids` 中，有“复制 feature 后无审核也 ready”以及混合审核 inconclusive 仍 ready 的断言。需要按物理判断与纯设计判断分开改写。它们不会在生产时执行，但会在维护时鼓励保留错误行为。保护普通审美不确定不阻塞的测试应保留。

### 8.2 先难图、后完整 child

冻结提交、工作区内容、配置非密钥指纹、产品事实、源图 SHA、参考 SHA、规划版本和允许 route。没有模型输出之前，只能冻结规划输入；首次得到的规划产物随后也固定，防止对照期间悄悄换计划。

先处理同一 child 的板条局部、连接结构、尺寸图等难图。通过后复用该次生成的有效候选，补完该 child 全部约定图片，不再新建第二份整套重复付费。另一柜体 child 用于检验非床架适用性，初次范围保持小而完整。

有参考/无参考对照选少量代表图，固定产品、观察、文案事实、生图 provider 和后处理，只改变参考输入；规划随参考重新产生并被保存，这是被测试的变量。并发测试则固定已经生成的规划与每图分配，不同时更换设计。

费用边界分别列出预期图片数、计划/审核/QA调用、允许的重试与额外对照次数。若选用当前同一 Natural child，初始图片数为实际清单的 9 张，难图包含在这 9 张内。新增第二 child 以其实际清单计算，不默认每个产品都是 8 或 9 张。跨 provider 对照和定向编辑另列预算，不能藏在“重试”里。

### 8.3 完整视觉与模板检查

每个 child 出一份源图/参考/最终图对应表和套图联系表，逐张看结构、数量、状态、端点、功能文案与显示文字；再跨图检查床品、道具、背景亮度、字号、徽标、线条的语义一致性。不能只抽查 main 就宣布结构连续。

保留用户规则：床架 main 继续按 lifestyle；其余主图读取当前类目策略；size 不强制全部改白底；普通无品牌书本字允许；第三方品牌、误导文案与事实错误按现有规则处理；尽量无人，包含镜面反射；品牌、制造商、产地、数量、履约和 GTIN 默认值不在此轮改造范围。

两个终点分别记录：生成及草稿模板可以完成；正式图片接受/可交付状态仍受已有 QA 与已有批准规则约束。不能因为草稿 Excel 存在就说正式模板放行，也不新增每个 child 必须人工先审才能生成模板的规则。SP-API 不纳入本次整改。

速度验收使用 wall time、账号实际 in-flight 区间、worker空闲原因、GPU占用、内存峰值、待处理字节、真实请求次数和每组有效候选数。upscale 已包含在 finalize 中；失败请求耗时另计。不得把多个并行区间简单相加，也不承诺固定倍速。

停止条件：发现新的实质结构退化、未知请求未收口、内存/磁盘无法安全准入或达到约定请求预算时停止新增派发；已出站任务按记录收口。不得为了完成率循环重生或缩小交付数量。

## 9. 必须同步删除或替换的旧行为

| 原位置/行为 | 必须替换的结果 |
|---|---|
| design_review 缺失/inconclusive 对结构操作通用放行 | 同次 findings 按具体物理操作消费；纯审美不确定不变硬门槛 |
| review key 漏 supporting_sources 与实际附件选择 | 一份覆盖有效引用集合的审核身份 |
| environment=False 清空全部对象 palette | 仅过滤房间字段，保留本图可见对象分配 |
| 边界只输出 occludes | 输出当前相关关系和状态，避免全量重复 |
| 选中辅助 source 就附全部裁图 | 精确选择已绑定的 view/feature，保留必要测量证据 |
| observe_candidate 的 50 秒独立覆盖 | 复用 scope 预算与 stage/job 截止时间 |
| 临时响应成功后无条件删除 | 当前 attempt 可恢复的原始响应与绑定记录 |
| 本地 finalize 错误进入 provider fallback | 本地失败只恢复本地；远程内容错误单独归因 |
| used_lanes 全 child 互斥、used 按alias计数 | 逻辑任务唯一在途＋资源组容量 |
| 远程 worker 等全部本地收口再补任务 | 同一 controller 内有限远程与本地执行集合 |
| 对已撤回素材默认恢复 approved | 保留 draft；有效范围有真实审核记录后才使用 |
| 支持旧错误语义的测试断言 | 改为当前可达行为测试，删除过时分支覆盖 |

更改合同应同步更新生产者、消费者、验证、指纹和测试。旧 schema/cache 通过当前版本自然失效，不为通过新测试添加兼容读取器，不扫描迁移历史 jobs，不让旧候选或旧批准记录自动转为新版本放行。

允许保留单个旧版本作为只读对照证据；生产运行只保留一套行为。单纯调度变化不应无故改变产品事实或重写已有效的图片语义指纹；需要失效的范围按真实依赖确定。

## 10. 实施完成时应交付什么

每个阶段提交可审查差异，说明新增/删除/修改文件、增删行数、物理删除的旧路径、针对性测试及生产套件实际时长。测试失败时修正原因，不以放松事实门槛换通过。

P0–P2 的代码和离线结果只能证明已知机制修正；P3/P4 的真实输入、完整套图和失败结果决定图片质量。尚未跑实图、尚未满载、尚未跨类目和尚未正式模板放行的部分要逐项保留状态。

本次审计可以确认的结论是：现有流程有可保留的生产基础；错误集中于少数证据传递、审核消费和资源生命周期边界。完成上述收敛后再做限定实测，比继续扩大规则、素材字段或整套重跑更可控。不能承诺生成模型从此零错误，也不能以本方案代替质量验收。
